# 小程序逐页配置与复用清单

2026-10-13：按 `app.json` 的 28 条路由核对，27 个实际页面接入原生页面配置，`activity` 保留为旧链接跳转。后台入口：[现有页面](http://192.168.5.213:3130/zh/dashboard/miniapp-settings?tab=native-pages)。业务数据与发布配置分别读取；本次没有改写业务记录或历史快照。

## 数据与渲染如何接通

- `contracts/participant-api/miniapp-native.ts` 是原生页面、模块、数据来源、可执行动作和配置边界的共享定义。后台编辑器、原生路由白名单及客户端使用它；`scripts/sync-participant-contract.mjs` 同步小程序合同。
- 保存位置为 `MiniappSettings.experience.screens[]`，每个页面按稳定 `id` 保存标题、说明、前后内容引用及模块实例。模块实例包含 `id / title / visible / density`；三个底部导航页另有 `tabLabel`。未保存的页面和模块沿用默认值，原有配置继续可读。
- `native-screen-schema.ts` 从实际页面定义生成校验：只接受本页存在的模块、支持的密度和合法字段；必需模块保持可见。数据库新增兼容迁移同步 schema，检查页面与模块标识唯一性。草稿保留编辑空间，发布前检查内容引用、用途和公开范围。
- `configuredPage` 保留原控制器的生命周期、权限和业务操作，只注入发布配置。WXML 的 `screen-section` 消费模块呈现，`screen-content` 按引用加载发布正文。可重排的同级模块通过 `moduleOrder` 实际渲染，事务步骤仍由业务控制器排序。
- 原生页面标题、模块标题、说明和前后内容均已接入；发现首页、活动目录、我的、服务目录、服务详情支持所列展示模块的顺序调整。可选模块支持显示开关，列表及资料类模块支持相应密度。网页正文由所引用网站维护，小程序中的补充内容用于复制链接或失败返回界面。
- 导航入口和登录后的返回位置使用同一页面合同。此次补齐原先被白名单拦截的组合页、服务、申请、预约及网页路由，并将预约记录、服务申请、服务预约、消息加入可配置动作。

## 可复用内容与业务控件

组合页面的模块实例可增删和排序，并能放到原生页的前后内容区。本次新增 `accountRecords`：可选择当前账号的活动预约、服务预约、服务申请、报告、任务、服务消息，以及显示条数、条目密度、空状态文案。来源是类型化的 `AccountRecordData`，经 `accountRecordRows` 转为共用 `AccountRecordRow`，使用已有授权接口读取和 `record-card` 显示。报告、任务可进入具体记录，其他集合进入对应业务记录页。

账号记录不会进入公共页面定义或公共缓存。未登录时显示登录入口，隐藏或卸载组件后丢弃旧响应；账号变化时再次比较当前会话。报告版式禁止插入这种实时集合，避免冻结报告混入日后的个人记录。记录集合在后台“数据对象与字段”可查看使用它的页面，并跳转到对应原生页；引用关系同样包含该连接。

参与人选择、日历格、安排列表、时段选择、状态筛选、历史回答和联系方式已经在上表列出的真实页面复用。涉及提交的控件通过事件将选择交回原业务控制器；页面编排不提供任意执行接口。身份授权、容量占用、幂等提交、历史快照等继续遵循各自业务合同。新增一种业务操作或提供方能力仍需要实现相应合同和控制器。
