# 格致未来思维 · 业务配置与本机验收

状态：2026-10-01 根据参考图调整为“发现、课程、家长”三栏，使用原生 TypeScript / WXML / WXSS。页面采用参考图的渐变底色、圆角卡片、底部弹层和两步预约布局，适配 Mathin 主题色。沿用既有本机接口与 iOS 同批的学习接口，开发端已交付，待人工视觉、交互与业务验收。本增量没有数据库执行或生产部署。

## 三栏与二级页面

| 用户入口 | 用户动作 | 数据来源或结果 |
| --- | --- | --- |
| 发现 → 信息与问卷 | 免登录填写动态表单并同意信息使用说明 | 既有 `miniapp_forms` 配置；`miniapp_intakes` 保存回答、表单快照和来源 |
| 发现 → 测评预约 | 选择孩子和真实测评老师，提交意向时间，再确认双方共有的具体时间 | 共用 `assessments` API；既有 `lead_invitation_threads(kind=assessment_1v1)` |
| 发现 → 活动预约 | 按地点和时间筛选；选择孩子与活动项目，再选择地点、周时段并确认 | `activities` + `miniapp_activity_publications`；预约仍写入 `activity_registrations` |
| 家长 → 我的预约 | 按孩子筛选待参与、已参与、已取消或全部记录，取消未开始的预约 | 既有 `bookings` 资源；状态和名额由数据库核验 |
| 课程 → 本周课程 | 切换孩子，查看周一至周日的课次 | 共用 `learning` API 的真实课表 |
| 课程 → 全部课表 | 按孩子与月份浏览日历，查看当天课程和活动预约 | 共用 `learning` API 加上既有预约 |
| 家长 | 登录、查看关联孩子，进入预约、课表、结果回顾、练习记录和信息登记 | 共用 `account`、已发送报告、已发布课堂结果和现有练习提交接口 |

“家长”支持已有手机号或邮箱与密码登录，并通过服务端能力查询显示微信登录和绑定状态。工作人员继续使用现有后台完成账号和孩子档案关联；匿名登记保留登记事实，管理员核对后按现有业务办理。

## 微信登录与绑定

- 服务端配置就绪后，登录弹层显示“微信登录”。每次由 `wx.login` 取得新 code，经共用接口验证后进入原账号。
- 首次使用且尚未绑定的微信会提示登录已有账号，再进入“绑定微信”。家长核对当前账号，输入原密码并点击“确认绑定当前微信”；也可选择“暂不绑定，继续使用”，回到原预约或课程入口。
- 已登录家长点击账号名称可查看微信绑定状态。绑定复用原账号及关联孩子，成功后保留当前会话；密码和微信 code 不保存在页面或长期存储。
- 2026-10-02 用户确认尚未配置 AppSecret，当前真实微信往返待配置与平台验收。配置关闭时显示“微信登录暂未开通”，账号密码入口继续可用。服务端配置、同开放平台 UnionID 和安全验证条件见[共用微信鉴权合同](../../../contracts/parent-api/README.md#微信小程序登录与绑定合同)。
- 网络中断或绑定结果未知时先重新读取绑定状态，再由用户明确重试；已有密码/MFA要求、冲突拒绝和家庭权限继续由服务端核验。

“测评预约”是预约老师进行现有 `assessment_1v1` 的独立入口；普通活动预约保留原含义。测评页和家长页均可进入，测评页右上角查看该孩子的“我的测评预约”。

## 独立 1 对 1 测评预约

- 第一页选择孩子、测评老师；第二页提供未来四周的上海时区意向时间，可多选。意向时间不表示老师的空闲库存，提交后按实际状态显示待老师回复或时间协调中。
- 老师只来自该孩子可证明的当前任课关系，账号及测评权限同时有效。没有唯一可用业务档案、已有进行中的邀约或没有可选老师时，新申请按服务端原因展示提示，已有记录仍可读取和确认。
- 教师回复后，页面只提供服务端允许确认、且双方共有的未来具体时段。家长确认时携带邀约 ID 和最近读取版本；`after_school` 只作为意向，不作为最终确认时间。
- 只有 `confirmed` / `completed` 的 `scheduledAt` 显示为测评时间。`proposedStartsAt` 和申请提交成功都不表示已确认预约。
- 未知结果的申请按账号与孩子在本机保留原 UUID、老师和时间输入；刷新查到同一邀约后解除未知状态。重试使用原输入与 UUID。刷新后确定没有同一记录且允许新申请时，可由用户重新选择老师和时间。旧申请的核对状态不会阻止确认另一条真实邀约。
- 接口合同与 RPC 安装要求见[共用测评合同](../../../contracts/parent-api/README.md#1-对-1-测评稳定合同)。本端不建立测评、教师或预约平行表，不接入生产地址。

## 本次接口复用与界面边界

- 首次访客可直接浏览公开项目和提交表单；预约需要已登录且有关联孩子的账号。登录后会回到发起登录的项目或服务，成功预约后可查看记录或继续预约。
- 发现筛选作用于接口返回的近期项目，当前接口上限为 100 场；达到上限时说明当前范围。现有合同没有年级或分类字段，两个筛选胶囊对应真实地点与时间。历史预约在“我的预约”中显示保存的详情。
- 标题及介绍完全一致的活动组成一组场次，在第二步按地点、星期和时间展示。选择时段后才允许提交，仍以实际场次 ID 预约。同一场次可以切换孩子分别预约；已约、满额和截止场次分别标记，组内其他可约场次仍可选择。网络中断导致结果不明时先查看已有预约，不自动重发提交。
- `GET /api/v1/parent/learning?participant=<ID>&from=<ISO>&to=<ISO>` 与 iOS 复用。成员选择以稳定 ID 为准，快速切换成员或月份时丢弃旧响应；同名成员不共享记录。
- 本周课程以周一为起点，跨月时仍读取完整一周；全部课表按月份读取。课程与活动预约在日历详情中明确区分，课程卡只展示实际课次、时间和已提供的老师信息。
- 共用接口没有提供档案编辑、调课、支付、聊天和问卷历史回看，这些功能不以可操作入口展示。后台仍沿用现有业务页面与 Studio 配置，本增量不创建平行业务表。
- 对外首屏聚焦信息、问卷与预约；实际课程标题、老师信息和报告用途按真实数据展示。字段名遵循数据含义，不用改名替代业务或资质审核。

## 后台设置登记字段

当前管理入口为 Supabase Studio 的 Table Editor。打开开发库的 `public.miniapp_forms`，默认表单 `slug=welcome`。

| 列 | 设置方式 |
| --- | --- |
| `slug` | 表单稳定标识，小写字母、数字或连字符，最多 64 字符 |
| `title` / `description` / `privacy_notice` | JSON：`{"zh":"中文内容","en":"English content"}`，两种语言均填写 |
| `fields` | 字段数组，按数组顺序展示，1～20 个字段 |
| `enabled` | `true` 对外开放；`false` 关闭新登记 |
| `version` | 每次更新自动递增，通常无需手工设置 |

字段示例：

```json
[
  {
    "id": "contact_name",
    "type": "text",
    "label": {"zh": "怎么称呼你", "en": "Your name"},
    "required": true
  },
  {
    "id": "interest",
    "type": "select",
    "label": {"zh": "感兴趣的方向", "en": "Area of interest"},
    "required": false,
    "options": [
      {"id": "reasoning", "label": {"zh": "逻辑推理", "en": "Reasoning"}},
      {"id": "space", "label": {"zh": "空间想象", "en": "Spatial thinking"}}
    ]
  }
]
```

支持 `text`、`phone`、`textarea`、`select`、`multiselect`；选择型字段提供 1～30 个选项。字段与选项的 `id` 使用小写字母开头的字母、数字、下划线，最多 40 字符且同组唯一；保留键 `constructor`、`prototype` 不可用。展示名称可以修改，数据键应保持稳定。文本最多 200 字、长文本 2000 字、电话 30 字符。

表单更新后，已打开旧版表单的用户会收到重新读取提示；已提交记录保留当时的字段名称、选项、回答与同意时间。后台格式不合法时接口停止提供该表单，修正配置后可重新打开。登记记录由管理员在 `miniapp_intakes` 查看。

地推入口可以直达 `pages/register/index?form=welcome&source=campaign-202609`。`source` 用于区分渠道，最多 120 字符；微信场景参数也可作为来源记录。二维码生成、线上发布及渠道自动归因不在本次实现内。

## 发布活动、结果和练习

活动先通过原有后台创建，在 `activities` 中维护时间、地点、时长、容量；再在 `miniapp_activity_publications` 添加对应 `activity_id`，填写双语 `title`、`description`，设置 `enabled=true`。`booking_closes_at` 可提前截止，留空则到活动开始截止。只有未来、当前状态、未删除且公开的活动会进入列表。小程序预约写入原有预约表，工作人员可沿用原有活动后台处理。

测评需要在原有测评流程中确认发送，`assessment_workflow_states.sent_report_id` 指向的版本才进入“回顾”；生成草稿不会公开。老师课后反馈读取 `learning_result_heads` 的已发布 `session_review` 版本，展示最近 366 天的记录。历史结果正文保留发布语言，不在客户端自动翻译。

练习使用现有 `assignments`，标题取 `title`、说明取 `content.text`、截止时间取 `due_at`。参与人须处于相应班级的有效关联范围，可由已关联账号代为提交，参与人本人无需登录。提交以追加记录保存，重新提交保留此前记录，小程序显示最新一次；目前后台核对入口为 `miniapp_practice_submissions` 和 `miniapp_practice_uploads`，本次没有新增网页批阅页面。

## 附件与登录边界

- 每次提交 1～9 个附件；照片 ≤12 MiB，视频 ≤64 MiB；相机录制默认最多 60 秒，既有视频仍受文件大小限制。
- 支持 JPEG、PNG、WebP、HEIC、MP4、MOV。服务端依据文件签名选择 MIME；媒体预览是否支持具体编码由微信和设备决定。
- Storage bucket `miniapp-practice` 为私有，签名预览有效期 5 分钟，视频额外要求家庭关联中的 `video` 范围。正常家长操作仍需 `grades` 范围。
- 会话令牌仅存在小程序本地存储，密码在成功登录后清空；退出清除本地会话。服务端密钥只用于受限的服务端操作。
- 上传失败可重试，成功返回的附件会复用。未返回确认的上传可能留下预留文件，目前没有新增后台清理任务；核对时保留已提交业务附件。

## 本机初始化与复核

本机使用 Windows 隔离 Supabase 和 Next.js，API origin 写在已忽略的 `miniprogram/config.local.ts`。客户端只连接 Next.js API；由服务端连接本机 Supabase。固定账号沿用仓库私有清单，不创建一次性 Auth 身份。

本次两条迁移已在本机应用。全新开发库可以按以下顺序执行；脚本会核对主机、loopback origin、Docker 实际目标、端口监听和迁移摘要：

```sh
node scripts/parent-portal-local.mjs --preflight
node scripts/parent-portal-local.mjs --check
node scripts/parent-portal-local.mjs --apply
node scripts/parent-portal-local.mjs --configure
corepack pnpm parents:check
```

`--check` 在事务中检查并回滚。`--apply` 只接受匹配检查结果的待应用迁移，全部已应用时提示 `ALREADY_APPLIED`。`--configure` 仅向核实的本机库补充明确标为“开发联调”的表单、活动、结果与练习，复用固定身份并保留现有同 ID 数据。迁移命令不用于生产。

真实 HTTP 验证脚本会留下标记清楚的本机登记、附件及提交记录：

```sh
node scripts/parent-portal-http-local.mjs
```

可使用 FFmpeg 生成无个人信息的短视频，增加真实视频、Range 和签名失败验证：

```sh
ffmpeg -hide_banner -loglevel error -f lavfi -i color=c=black:s=32x32:r=10 -t 0.5 -c:v libx264 -pix_fmt yuv420p -movflags +faststart -y .tmp/parent-portal/local-check.mp4
node scripts/parent-portal-http-local.mjs --video .tmp/parent-portal/local-check.mp4
```

工具输出和验收回执在已忽略的 `.tmp/parent-portal/`。共享 `project.config.json` 保持 `urlCheck=true`；按 2026-09-22 的授权，本机 `project.private.config.json` 使用 `urlCheck=false` 连接局域网 HTTP。正式网络接入配置 HTTPS 合法域名。

## 人工验收顺序

1. 在微信开发者工具编译，打开“发现”→“信息与问卷”，免登录完成登记；到 Studio 核对回答和配置快照。
2. 在 Studio 修改表单展示名或选项，重新打开登记页确认变化；确认已有记录保留旧版快照。
3. 通过地点和日期筛选现有活动；从活动预约页登录固定家长开发账号，确认返回原页面，在基础信息选择孩子与项目，在第二步选择实际地点与时段后预约。
4. 在家长页按预约状态进入“我的预约”，筛选孩子、取消尚未开始的预约，再观察名额。若有多个孩子，在成功页选择“继续预约”并切换孩子，核对预约状态。
5. 在“课程”切换孩子、点击本周日期，再进入“全部课表”切换月份，核对真实课程和活动预约。无安排时显示空状态。
6. 在“家长”打开“结果回顾”和“练习记录”；读取已有开发反馈，沿用原流程提交照片或视频并重新打开确认。
7. 使用未关联的固定开发账号确认没有其他账号的结果与练习；在真机检查登录返回、系统弹层返回、相册权限、录制、播放与滚动手感。
8. 在“测评预约”选孩子与老师，选择意向时间并提交；在既有后台回复教师时间，再回小程序确认共有时段。核对“已提交申请”和“已确认预约”的区别，以及重新进入页面后的记录。
9. 配置微信登录后，用未绑定微信进入登录弹层，确认先登录原账号再明确绑定；退出后用同一微信登录，核对关联孩子和原预约仍属于同一账号。配置未就绪时验收明确提示与密码入口。

机器检查覆盖接口、权限、容量、重试与持久化；真机媒体能力、视觉和操作体验仍待人工验收。
