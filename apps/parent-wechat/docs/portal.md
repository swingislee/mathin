## 微信登录与绑定

- 登录弹层仅显示“微信登录”。每次由 `wx.login` 取得新 code，经共用接口验证后进入原账号；首次登录、填写基础信息时通过微信授权手机号。
- 已登录家长点击账号名称可查看微信绑定状态。服务端允许直接绑定时，由本人点击“确认绑定当前微信”；也可选择“暂不绑定，继续使用”，回到原业务入口。
- 绑定复用原账号及关联参与人，成功后保留当前会话。小程序不收集账号密码，微信 code 仅用于本次验证。
- 微信暂不可用时提示重试，需要核对账号时提示联系工作人员。服务端配置、同开放平台 UnionID 和安全验证条件见[共用微信鉴权合同](../../../contracts/parent-api/README.md#微信小程序登录与绑定合同)。
- 网络中断或绑定结果未知时先重新读取绑定状态，再由用户明确重试；账号安全条件、冲突拒绝和家庭权限继续由服务端核验。

“测评预约”是预约老师进行现有 `assessment_1v1` 的独立入口；普通活动预约保留原含义。发现页和家长页均可进入，测评表单下方可查看该孩子的“我的测评预约”。

## 一对一学习诊断预约

面向家长的名称为“一对一学习诊断”。通过交流与数学／英语科目任务了解孩子当前的学习情况、给出建议，本入口不作为招生申请。后台历史对象名与稳定 API 保持兼容。

- 第一步选择学员、测评科目、测评年级和方式。科目暂定数学、英语，可多选；方式为线下到校区测试。更换学员、科目或年级会清除旧时段，避免提交与新选择不匹配的安排。
- 第二步按示例提供校区选项、老师选项和两个七天区间。表格显示完整星期与实际起止时间；只有老师主动发布且覆盖全部所选科目、年级的时段显示“可约”，占用或未发布格为灰色。只选择一个时段，点击“确认预约”创建已确认邀约。
- 老师在后台“测评 → 可约时段”发布自己的排班；持 `followup.write` 或 `schedule.manage` 的工作人员可管理全体。发布时选择科目、年级、校区和起止时间，可关闭发布；已有预约历史的时段保持主体信息不变。家长预约后在既有邀约沟通明细完成或取消，取消释放时段。
- 家长仍需当前孩子的 `grades` 范围及唯一可用业务档案。已发布老师不要求是孩子原任课教师；没有排班时显示真实空状态，已有进行中邀约时先查看记录。旧协调记录保留教师回复和共有时间确认。
- 只有 `confirmed` / `completed` 的 `scheduledAt` 显示为测评时间。`proposedStartsAt` 和申请提交成功都不表示已确认预约。
- 未知结果的预约按账号与孩子保存原 UUID、时段、科目和年级；刷新查到同一邀约后解除未知状态。重试使用原输入与 UUID。刷新后确定没有同一记录且允许新申请时，可重新选择。旧申请的原始输入和重试仍兼容。
- 接口合同与 RPC 安装要求见[共用测评合同](../../../contracts/parent-api/README.md#1-对-1-测评稳定合同)。新增 `assessment_slots` 只存老师发布的安排，预约继续复用现有邀约。本批新能力未部署生产。

## 本次接口复用与界面边界

- 首次访客可直接浏览公开项目和提交表单；预约需要已登录且有关联孩子的账号。登录后会回到发起登录的项目或服务，成功预约后可查看记录或继续预约。

- 公开合同增加可选 `targetGrades`、`subject`：服务端只为公开 RPC 已放行且仍为当前记录的项目补充分类。年级沿用 `activities.target_grades`：空数组表示不限年级，空值表示待核对，选定阶段后不显示待核对项目。现有数学公开课 `kind=public_class` 标记为 `math`，其他项目保留未分类；不从标题或地点猜测分类。历史预约仍显示保存的详情。
- 每个公开活动按独立 ID 展示，选项附日期与地点；同名活动不推断为同一课程或系列。第二步选择该活动实际时段后才允许提交。同一活动可以切换孩子分别预约；已约、满额和截止分别标记。网络中断导致结果不明时先查看已有预约，不自动重发提交。
- `GET /api/v1/parent/learning?participant=<ID>&from=<ISO>&to=<ISO>` 与 iOS 复用。成员选择以稳定 ID 为准，快速切换成员或月份时丢弃旧响应；同名成员不共享记录。
- 本周课程以周一为起点，跨月时仍读取完整一周；全部课表按月份读取。两者显示同一孩子的课程与未取消活动预约并标明活动。年级来自当前孩子的真实学习摘要；课次只显示已提供的时间、班级和老师信息。
- 共用接口没有提供档案编辑、调课、支付、聊天和问卷历史回看，这些功能不以可操作入口展示。后台仍沿用现有业务页面与 Studio 配置，本增量不创建平行业务表。
- 对外首屏聚焦信息、问卷与预约；实际课程标题、老师信息和报告用途按真实数据展示。字段名遵循数据含义，不用改名替代业务或资质审核。

```json
    "required": false,
    "options": [
      {"id": "reasoning", "label": {"zh": "逻辑推理", "en": "Reasoning"}},
      {"id": "space", "label": {"zh": "空间想象", "en": "Spatial thinking"}}
    ]
  }
]
```

支持 `text`、`phone`、`textarea`、`select`、`multiselect`；选择型字段提供 1～30 个选项。字段与选项的 `id` 使用小写字母开头的字母、数字、下划线，最多 40 字符且同组唯一；保留键 `constructor`、`prototype` 不可用。展示名称可以修改，数据键应保持稳定。文本最多 200 字、长文本 2000 字、电话 30 字符。

表单更新后，已打开旧版表单的用户会收到重新读取提示；已提交记录保留当时的字段名称、选项、回答与同意时间。后台格式不合法时接口停止提供该表单，修正配置后可重新打开。登记记录由管理员在 `miniapp_intakes` 查看。

地推入口可以直达 `pages/register/index?form=welcome&source=campaign-202609`。`source` 用于区分渠道，最多 120 字符；微信场景参数也可作为来源记录。二维码生成、线上发布及渠道自动归因不在本次实现内。

## 发布活动、结果和练习

活动先通过原有后台创建，在 `activities` 中维护时间、地点、时长、容量；再在 `miniapp_activity_publications` 添加对应 `activity_id`，填写双语 `title`、`description`，设置 `enabled=true`。`booking_closes_at` 可提前截止，留空则到活动开始截止。只有未来、当前状态、未删除且公开的活动会进入列表。小程序预约写入原有预约表，工作人员可沿用原有活动后台处理。

测评需要在原有测评流程中确认发送，`assessment_workflow_states.sent_report_id` 指向的版本才进入“回顾”；生成草稿不会公开。老师课后反馈读取 `learning_result_heads` 的已发布 `session_review` 版本，展示最近 366 天的记录。历史结果正文保留发布语言，不在客户端自动翻译。

练习使用现有 `assignments`，标题取 `title`、说明取 `content.text`、截止时间取 `due_at`。参与人须处于相应班级的有效关联范围，可由已关联账号代为提交，参与人本人无需登录。提交以追加记录保存，重新提交保留此前记录，小程序显示最新一次；目前后台核对入口为 `miniapp_practice_submissions` 和 `miniapp_practice_uploads`，本次没有新增网页批阅页面。

## 附件与登录边界

- 每次提交 1～9 个附件；照片 ≤12 MiB，视频 ≤64 MiB；相机录制默认最多 60 秒，既有视频仍受文件大小限制。
- 支持 JPEG、PNG、WebP、HEIC、MP4、MOV。服务端依据文件签名选择 MIME；媒体预览是否支持具体编码由微信和设备决定。
- Storage bucket `miniapp-practice` 为私有，签名预览有效期 5 分钟，视频额外要求家庭关联中的 `video` 范围。正常家长操作仍需 `grades` 范围。
- 会话令牌仅存在小程序本地存储，退出清除本地会话；小程序不收集账号密码。服务端密钥只用于受限的服务端操作。
- 上传失败可重试，成功返回的附件会复用。未返回确认的上传可能留下预留文件，目前没有新增后台清理任务；核对时保留已提交业务附件。

## 本机开发与按需核对

本机使用已识别的隔离 Supabase 和 Next.js，API origin 写在已忽略的 `miniprogram/config.local.ts`。客户端只连接 Next.js API；由服务端连接对应 Supabase。开发身份沿用仓库私有清单。

迁移状态按实际目标与迁移账本核对。新环境初始化、迁移和任何造数先按 [数据操作](../../../docs/ops/data-operations.md) 确定目标及范围；历史 `parent-portal-local.mjs` 和 HTTP 联调脚本保存在 [归档](../../../archive/2026-10-04/scripts/)，用于追溯当时的开发批次。

普通客户端增量交付开发者工具或手机使用。需要生成交付程序时执行对应构建；明确需要类型检查时使用 `corepack pnpm parents:wechat:typecheck`。接口、权限或数据风险的检查按 [用例入口](../../../tests/README.md) 选择具体文件，SQL 通过 `pnpm db:test -- supabase/tests/文件.sql` 指定执行，先核对隔离目标。

共享 `project.config.json` 保持 `urlCheck=true`；按 2026-09-22 的本机授权，`project.private.config.json` 可使用 `urlCheck=false` 连接局域网 HTTP。正式网络接入配置 HTTPS 合法域名。临时媒体与核对材料使用无个人信息的样例，输出保存在已忽略的 `.tmp/`。

## 人工验收顺序

1. 在微信开发者工具编译，打开“发现”→“信息与问卷”，免登录完成登记；到 Studio 核对回答和配置快照。
2. 在 Studio 修改表单展示名或选项，重新打开登记页确认变化；确认已有记录保留旧版快照。
3. 通过班级阶段和科目筛选公开项目，核对选择、关闭弹层和重置；从项目进入活动预约页，在基础信息选择孩子与项目，在第二步选择实际地点与时段后预约。没有未来公开项目时显示空状态。
4. 在家长页按预约状态进入“我的预约”，筛选孩子、取消尚未开始的预约，再观察名额。若有多个孩子，在成功页选择“继续预约”并切换孩子，核对预约状态。
5. 在“课程”切换孩子、点击本周日期，再进入“全部课表”切换月份，核对真实课程和活动预约。无安排时显示空状态。
6. 在“家长”打开“结果回顾”和“练习记录”；读取已有开发反馈，沿用原流程提交照片或视频并重新打开确认。
7. 使用未关联的固定开发账号确认没有其他账号的结果与练习；在真机检查登录返回、系统弹层返回、相册权限、录制、播放与滚动手感。
8. 在后台发布测评可约时段；小程序第一步选择学员、数学／英语、年级和到校区测试，第二步选校区、老师、可约格。核对两周切换、灰色格、重置和返回；由负责人确认预约后，在记录及后台核对同一邀约，完成或取消后再看实际状态。旧协调邀约仍从记录中确认共有时间。
9. 配置微信登录后，用未绑定微信进入登录弹层，确认先登录原账号再明确绑定；退出后用同一微信登录，核对关联孩子和原预约仍属于同一账号。配置未就绪时验收明确提示与密码入口。

机器检查覆盖接口、权限、容量、重试与持久化；真机媒体能力、视觉和操作体验仍待人工验收。
