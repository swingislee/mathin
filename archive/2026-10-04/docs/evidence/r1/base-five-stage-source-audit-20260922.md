## 1. 本轮用户已经确认的规则

1. 同时有确认月份和确认人员、具体结果未填的案例，认可已开展有效确认，不重新进入待首联；结果仍如实保留未填。
2. 只有未接通尝试、没有其他有效沟通依据时，保留待首联。每一次确实发生的电话各有沟通记录；首次未通、后续加 V 的两个结果都保留，后续结果参与当前展示。
3. 同一个孩子的重复获客行保留全部来源资料，学生身份和当前主标签只有一份。之前案例 3 的“一人、两份获客资料”按本次回复接受。
4. 学服与测评老师可以由同一员工承担，两项职责都保留。
5. 待测评泛指已经有效沟通、尚无测评结果，包括已预约未到、体验课已到无结果的学生。
6. 待报拟班者保留重要的老师、班型和时段安排；拟班本身不计为正式在读。
7. 已有正式课程自然结束、没有续报的学员，归已停课，小标签“课程结束／未续报”。
8. 遇到“已报名但缺班型”，先按用户补充要求交叉核查其他表单。用户没有授权把全部缺班型者一律当作未分班，也没有选定“确认已报名但班级关系始终无法核实”的统一兜底标签。

## 2. 一人一个主标签，多项小标签

主标签按**学生统一身份、全部可用来源、正式课程当前关系**计算。学服分组只是筛选，同一学生在二组和三组看到的主标签相同；获客来源和经办历史可以有多份。

| 主标签 | 正向判定依据 | 可以同时保留的小标签举例 |
| --- | --- | --- |
| 待首联 | 汇总后没有有效沟通，或始终只有未接通等无效联系尝试 | 未联系、未接通需重试、号码异常、待分配 |
| 待测评 | 有有效沟通，尚未找到可归属本人的有效测评结果，且没有正式课关系进入后两类 | 已加 V、已有老师备注、未预约、邀约协调、已预约未到、已到无结果、体验课、结果待补 |
| 待报名 | 有有效测评结果，尚未报名正式课程；已报名来源另做正式课关系核查 | 结果已出、待反馈、考虑中、待缴费、已有拟班、待落实 |
| 待续保 | 有正式课入班／在读关系，且仍有有效的正式课程服务 | 在读、本轮续报考虑中、有意续报、本轮已续、本轮不续 |
| 已停课 | 有正式课程经历，相关课程已退课、停课或自然结束，且没有更晚恢复或仍有效的其他正式班 | 退课、暂停、课程结束／未续报、复课沟通中 |

“待续保”沿用用户本轮用词；现有代码 key `awaiting_renewal` 和界面“待续班”的对应关系仅在分析中记录，本轮未改 UI 或枚举。已停课沿用现有 `former_student` 的分析去向。

归类先检查当前正式课关系，再检查测评结果，最后检查沟通。已经正式入班的人缺少历史测评成绩，不回退为待测评；测评不合格也是实际测评结果，并非“尚未测评”。

多班、多期关系先分别核对：退掉某一个班、其他正式班仍在读，主标签仍为待续保；旧退费后重新正式入班，也应显示待续保。正在本期上课但说下期不续，只增加“本轮不续”，不提前变成已停课。仅有旧在读表、当前行缺失或续报栏空白，不能证明已经停课或结课。

**五类互斥不等于原表证据完整。** 对已确认同人的资料，只产生一个主标签；来源不明、关系待核、结果缺项使用现有问题标记和小标签，不新增第六个业务阶段。尚不能判定当前主标签的源行先保留原始证据与待核关系，不用默认“待首联”把全量覆盖率凑满，也不把问题来源直接建成另一个学生。已有人工确认的阶段仅在新业务依据成立时改变。

## 3. 有效沟通与沟通次数分开

有效沟通依据包括有效确认记录、加 V／入群、参加活动、实质老师备注、明确到访或后续业务记录。某一学服没有记录，不抵消另一来源已经建立的联系；本次未通不抹掉过去有效联系。

“未通”“无人接听”“号码无效”本身是失败尝试；只有这些内容的记录，即便填写了日期、人员和次数，也不能因备注非空就变成有效沟通。这一例外承接用户对“始终未接通仍待首联”的明确说明。仅分配确认人员、没有确认行为或其他内容，仍不能当作已沟通。

实际结果不必是正向转化：明确拒绝、暂时不考虑等反映已交流的内容，仍属于有效沟通，可使用意向和下次联系小标签。模糊短语、混合否定、备注里的预约或“尚未测评”需要理解上下文，不依靠关键词非空强行升级。

今后系统内每次通话保存独立记录。Base 历史宽表可能追加、覆盖或修改：能区分的每次电话分别还原，不能区分的保留有版本的来源摘要。导出文件变了不等于又打了一次电话；相同摘要重复导入也不增加沟通次数。旧表已覆盖且三个版本都未留下的通话，无法凭空还原。

## 4. 这次实际找到的差异

全部数字是 **Base 来源行数、候选组数或字段数**，没有进行生产身份确认及测试身份排除，不代表正式学生人数和最终五标签人数。

### 跨学服、跨表身份

- 获客表 3,859 行中，同名同一主联系方式的重复候选有 **253 组、523 行**；其中 **114 组**确认人员不同，**51 组**横跨用户指定的当前二、三组。判定使用“家长电话”，不把“团成员手机号”当作本学生电话。
- 这些重复候选包含 **3 组泛称姓名**，同名同号也需要辨别具体孩子。主要学生来源中有 **180 组号码对应多个不同原始称呼**，既可能是兄弟姐妹，也可能是别称、错字或附带班级文字，不能全按电话合并。
- 对一行的联系依据进行筛选时，还找到 **8 行**可通过同名同号在其他表找到后续业务候选、**23 行**在更早 Base 版本中有本次该行不再体现的候选联系依据。筛选排除了短而明确的未通备注，其他原文仍需核对；它们说明当前一行不足以决定当前学生状态，这些集合可以交叉。
- 追加案例 7 实际为三组已有沟通、二组来源尚无有效沟通的方向。它验证跨组重复的同类问题，未声称已锁定用户所指“二组先沟通、三组又新增”的具体学生。

9 张有学员资料的表共有 5,333 行、4,998 行填写姓名，其中 **759 行有姓名但没有主联系方式**。到访表 144 行同时缺姓名和电话，获客表 167 行同时缺姓名和电话；另有 4 条获客行只有电话没有姓名。这里包括空行、残留业务内容或未补齐身份，不能每行直接造一个学生。目标表、内容素材、日报等也不直接生成学生身份。

### 待报拟班与姓名附注

秋季表 174 行中，172 行有姓名、162 行明确在读，9 行报名模式为待报。这 9 行均有班型、老师、周次和时段，在读字段均空。

其中 **8 行姓名带括号附注**。把附注暂时移出匹配串后，**6 行**找到其他表的同名候选，**4 行**候选有测评结果。附注原文继续保留、含义仍需核对；去括号查找只生成候选，不是自动清洗合并。另 3 行没有这种匹配结果，也不能因此判断从未沟通。

建议在沟通列表和班级安排中复用同一份“拟入班”安排：主标签仍按实际测评和正式课关系确定，行内显示“已有拟班／待落实”，同时显示老师、时段和下一步，并提供可筛选的拟入班名单。已有结果者可在待报名下推进，无结果者保留待测评与拟班安排。这样拟班可以集中办理；正式在读人数和开班数继续读取实际班级与正式关系，不从拟班条数推算。本段是展示建议，尚未实现或取得视觉验收。

### 已停课与历史先后

- 秋季表“26秋在读”只有“是”这个选项，没有明确“不在读／停课”选项；空白与删行不是停课记录。
- 历史调价表有 **4 行“已退费”**；另有 **5 行**备注包含停课或退费词，共 **9 条不同来源候选**。备注需核对指的是本机构正式课、其他机构还是家长意向，不按关键词批量打已停课。

## 5. 防止重复获客与重复联系的映射要求

1. **统一学生身份先于阶段。** 同一人所有获客、确认、跟进、活动、测评和班级来源挂同一身份；“同一 Base＋表 ID＋源行 ID”锚定来源，导出日期只新增版本。
2. **两个入口都查重。** 新获客时按规范电话查家庭、学生和已有线索，再用姓名、别称、学校、适用年级区分孩子；开始沟通时再次读取同一学生的当前负责人、已发生结果和联系历史，防止从旧表重复当新人。
3. **匹配与授权分开。** 全机构做身份候选查询；受限人员看到重复提示和可联系的负责岗位，不因查重越过原有个人信息权限。确认同人后追加来源；同号不同孩子继续分开。
4. **当前负责人只落一份确定归属。** 历史获取、确认、跟进人员分别保留；已有明确转交优先，不能依据最后导入的行或文件名抢占归属。归属冲突使用已有问题标记待核，主标签仍汇总全部已确认同人证据。
5. **保存时也防重复。** 界面候选不能代替服务端检查；提交需复核身份关联及归属版本，并用稳定来源键保证重复导入和重试不产生第二学生、第二来源或重复事件。手机号不做学生唯一键，以免合并兄弟姐妹。
6. **人工决定持续生效。** 已确认的别称、姓名纠正、按生产保留班级、测试身份等继续挂稳定身份；本轮没有重新判断或覆盖这些决定。测试属性独立于五个业务标签，正式人数、班级和统计继续按正式对象及关系计算。

## 6. 数据问题继续使用现有字段

原文、规范值和来源版本沿用 `history_source_business_facts.fields` 与原始来源归档。以下是本次问题对应的既有 `review` 值，不新增一套平行问题字段：

| 问题 | 现有标记与说明 |
| --- | --- |
| 身份候选、当前归属或历史先后不明 | `ambiguous`，备注注明来源和待核原因 |
| 缺结果、缺课程关系或资料项 | 对相应字段使用 `missing`；业务事实仍保留 |
| 班级引用未建立或班型需核对 | `reference` / `class_label` |
