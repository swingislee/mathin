## 原因与时间线

产品负责人反馈一节周三 3 年级 A+ 课次课评自动保存失败，截图同时显示“发布逐生课评”和“课评保存失败，请重试”。本次使用生产实际运行版本 `2ded3c75` 的代码和前一版 `f019ce9d` 的编译产物核对；本机开发分支已改用表格，不能用它代替生产卡片实现。

- 16:12:07.997，目标课次最后一次成功保存 10 条课评记录。
- 16:12:10 开始应用切换，16:12:11 完成性能版本发布。
- 16:12:29 至 16:16:05，生产日志记录 33 次 `Failed to find Server Action`。这些请求只有一个接口标识；该标识存在于前一版清单、缺席于新版清单，前一版静态产物将它明确绑定到 `saveSessionReviewsAction`。
- 生产 `SessionStudentPostworkCards` 使用加载页面时绑定的 Server Action 自动保存。发布路径先调用 `flushReviews()`；返回失败后立即返回 `SAVE_FAILED`，因此保存接口失效会同时阻止截图中的“发布逐生课评”。
- 原卡片的课评草稿仅在 React state/ref 中，没有跨刷新恢复机制。卸载时再次调用相同保存函数，也不能解决旧接口标识失效；保留未保存内容应先于刷新建议。

这 33 条日志对应真实的课评编辑失败。前次发布记录只将它们归为旧接口请求，未继续定位到具体业务动作；本次补齐该影响，不能把“新清单中没有其他异常”解释为已打开的编辑页面正常。
