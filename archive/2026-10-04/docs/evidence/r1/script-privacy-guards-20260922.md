# 连接脚本与小程序配置隐私保护

> 状态：2026-09-22 机器检查通过；本机 Git hooks 已启用。该记录不代表扫描能够识别全部个人数据，也不代表历史 AppID 已清除。

> 后续更新：产品负责人追加历史清理要求后，已完成可达历史改写及远端更新，服务器旧对象和缓存待 GitHub 处理。详见[历史清理记录](wechat-appid-history-cleanup-20260922.md)；以下保留首次保护增量的实施范围。

用户指出公开历史提交中的微信 AppID，并要求防止 Agent 连接脚本带入隐私。腾讯文档区分 AppID（应用标识）与 AppSecret（凭证密钥）；本次所指字段是 AppID，未发现 AppSecret 泄露证据。

- 共享小程序配置恢复为 `touristappid`；本机实际 AppID 保存在已忽略的 `project.private.config.json`，保留热重载、局域网域名校验等现有偏好。工程检查和暂存检查阻止实际 AppID 再次入库。
- 连接脚本从环境或私有配置读取凭据；原始 HAR、浏览器状态和临时取证保留在 `.tmp/`。根 Agent 入口与运维文档记录共同边界。
- 新增 `pre-commit`，扫描 Git 暂存对象，防止“工作文件已脱敏但暂存区仍含凭据”；即使使用 `git add -f`，私有配置和取证文件仍被拦截。
- `pre-push` 运行当前及历史密钥扫描；增加微信 AppSecret、认证链接查询参数、HTTP Basic URL、Bearer 和连接脚本字面量检测。结果只报告路径、行号及规则。
- 新克隆需显式启用 `.githooks`，CI 保留当前和历史扫描。客户端 hook 可被绕过，不能替代 GitHub 分支保护、权限控制和人工审查；本次未修改仓库级权限或重写 Git 历史。

验证：家长端工程检查、13 项密钥与暂存区定向合同、受影响 ESLint 通过；当前 3,684 个跟踪文件与 14,131 个可达历史 blob 扫描无高置信命中。测试覆盖实际暂存内容、强行加入私有文件、AppID、运行时引用和日志脱敏；随后提交由新 hook 再次检查。
