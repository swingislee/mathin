# 五项经营指标与 Base 来源差异定位

状态：**只读定位完成；统计修正与业务验收待完成**。本轮响应报名明细及测评、到访、邀约、有效沟通差异，核查使用 2026-09-07 的 Base 导出与 2026-09-08 09:55（Asia/Shanghai）的本机开发业务快照。应用代码、业务数据和生产环境均未在本轮修改。

## 定位结论

差异主要发生在来源业务资料转换为总览事件的规则中：来源月份被具体日期替代，报名合并了入班事实，邀约包含其他业务表，测评和有效沟通使用了不同的完成条件。另发现来源姓名被关联档案的当前姓名覆盖。

当前来源归档的 5,212 条记录、209,075 个原始字段值仍与指定 Base 文件一致，字段原值差异为 0。九月五项实际 reader 没有来源不可用或分页截断，卡片与对应明细数量一致；同一业务快照的事件回放也一致。这证明当前代码按其合同输出了这些数值，月报合同本身仍需修正。

## 报名的具体触发链

当前报名 11 条可以还原为 **7 条来源报名 + 4 条旧花名册入班记录**。Base 8 条中有 1 条填了报名月份却未填报名日期，因此未进入当前日期窗口。7 条已保留来源报名中，3 条通过同一学生同一天合并到秋季课程登记，4 条仍以到访表的来源报名事件输出；不同源表身份不代表这 3 条报名丢失。

四条额外记录的旧快照均显示 `remark` 以“班级学员导入：”开头，`joined_at` 相同且为 9 月 4 日导入时刻。花名册修订将四条状态置为 `withdrawn`，并将备注更新为名单修订说明。当前报名统计依赖备注前缀识别导入记录，备注变化后进入未桥接入班记录的报名分支。

相关位置：[报名来源与入班合并](../../../src/features/school/home/staff-overview-source-contract.ts)，`buildOverviewSourceEvents` 的 `input.memberships.filter`。应以明确报名事实和结构化来源身份识别业务，避免用可编辑备注判断记录性质。简单限制会员为 `active` 仍不能定义正确的历史报名，因为当前退班与过去真实报名是不同事实。

九月报名另有 1 条来源姓名与关联学生当前姓名明显不符；该来源报名仍在 11 条中，页面名称因此难以与 Base 对应。名称读取位置为 [明细 enrichment](../../../src/features/school/home/staff-overview-drilldown-actions.ts)，当前学生名优先于 Lead 名和来源名。需追溯该关联依据，并保留原来源名供核对；本轮未修改身份关联。

## 测评、沟通与日期的定义差异

Base 的“学科老师测评数”使用 `到访月份` 和 `到访与否=已到`，不检查测评结果。当前 [测评完成判断](../../../src/features/school/home/staff-overview-source-contract.ts) 要求已到访且有完成时间或来源结论；[来源结论合同](../../../src/features/school/business-source-contract.ts) 认可等级、分数及指定等级备注，普通文字描述不在其中。九月 19 条未计入完成测评的来源行，不能据此断言真实世界中没有进行过测评。

来源获客表的九月 48 条确认行，确认结果、跟进结果全部为空；确认日期 46 条为空，2 条为未注明年份的 `9.4`。[导入映射](../../../scripts/lib/operational-source-import.mjs) 为其中 11 行生成了结果和发生日期均为空的确认沟通记录，其余 37 行没有生成沟通事件。[总览读取](../../../src/features/school/home/staff-overview-data.ts) 只统计 `outcome === "connected"` 且有发生日期的沟通，九月结果因此为 0。原确认月份仍完整保存在来源归档中。

到访按活动具体日期，邀约按预约中的确认日期归月；报名按登记日期归月。月份标签与具体日期跨月或具体日期缺项时，无法复现按月份标签计行的 Base 月报。历史邀约读取还缺少来源业务表限制，导致袋鼠竞赛报名进入选拔诺访指标。来源事件按导出生成的内部 ID 去重时，也无法自动排除另一批次的同一个原表行。

Base 自身不同图表也有不同条件：例如九月诺访主卡使用确认月份，诺访目标使用到访月份；二、三组图表还增加组别条件。比较具体明细时需要沿用对应图表的完整筛选条件。

## 建议修复合同

1. 为月度指标确定来源表、来源业务月份、记录粒度、状态和署名字段，卡片、明细、学服及老师分项读取同一个事实集合。
2. 月报保留来源月份；日、周读取真实日期。具体日期缺失时显示缺项，按月统计不需要补造某一天。
3. 报名使用明确报名事实；入班、导入、调班和名单修订分别表达。跨批次以原表和原记录 ID 识别来源，同主体同日去重另按指标定义处理。
4. 明确区分来源确认、确认加 V 和有效沟通；区分原 Base 老师到访口径与系统完成测评。每项只使用与其含义一致的证据条件。
5. 明细保留来源行和来源姓名，核对关联档案时能定位到原记录；验收逐行包含、排除和员工分项，不仅比较总数。

这是下一步修复合同，尚未作为已完成的应用改动或业务验收结果。
