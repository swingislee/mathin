# 课程导入链路审查与优化建议

核对日期：2026-09-07。状态：只读审查完成，建议待实施。

代码基线：Mathin `53fc27f0`；来源仓库 `334e24b`。范围为两个仓库的当前代码、现行操作手册、Mathin 本机待导入包和来源可移植产物。本次没有运行采集、重建、导入、数据库或 Storage 写入，没有连接生产核对当前 release，也没有进行人工视觉验收。

## 结论

当前流程中，采集与教学系统的分工有实际价值，但“采集侧审阅的成品”与“Mathin 最终运行的成品”尚未成为同一份可追溯交付物。用户因此承担了跨系统比较和定位差异的工作。

- 魔法校存在两套页面呈现实现：来源 Viewer 先显示 render model，导出器再生成 `page-doc-v1`，Mathin 的 `DocStage` 重新生成 DOM 和行为。
- 爱学习已经复用来源 Viewer 的呈现函数，但 Mathin 仍读取来源源码、重新封装运行时，并在请求时注入宿主桥接。共享函数减少了差异，尚未统一实际执行产物。
- 爱学习的日常新增课程仍受到固定课程包白名单、整包数量断言、整站出口、整包构建及包级 manifest 守卫的共同约束。
- 原有工具已经支持不少增量能力。优化应连接这些能力，并明确内容版本、运行时版本和宿主版本；无需从头重做下载系统。

建议目标：输入提供一次，系统自动推进到 Mathin 待验收入口；人对最终课程内容验收一次。两个系统各自的机器检查继续承担资源完整性和教学集成合同。

## 1. 当前实际链路

本机没有发现一个额外承担爱学习中转的 `2026-07` 仓库。当前 Mathin 两个爱学习脚本默认都指向同级 `2026-07_mofaxiao_courseware`，来源仓库也同时维护魔法校和爱学习。以下按已找到的这两个仓库分析；用户提到的 `2026-07` 是否另指某个外部工作目录，尚未确认。

### 魔法校

```text
课程入口 JSON
  → 来源仓库：目录 / 课程与页面快照 / 资源发现
  → 下载 CAS / H5 捕获、修补与验证 / SQLite 状态登记
  → render model + 文本排版覆盖
      ├─ 来源 Viewer：呈现并审阅
      └─ export mathin-package：转为 page-doc-v1 + 资产/H5/讲次映射
          → Mathin cw:import：找到既有目标讲次、上传缺少的对象、登记版本
          → Mathin DocStage：呈现并进入备课 / 课堂
          → 需要时另走 4:3 适配
```

依据：来源 [现行手册](../../../2026-07_mofaxiao_courseware/docs/current/mofaxiao-localization.md)；[导出器](../../../2026-07_mofaxiao_courseware/src/export/mathin-package.ts) 第 170、455～480 行；Mathin [DocStage](../../src/features/courseware-doc/DocStage.tsx) 第 139、393～479、782～816 行。

### 爱学习

```text
授权 HAR + 已下载视频
  → 来源仓库：预检 / 目录 / player 资产
  → localize：脱敏响应、页面、普通资源、内嵌 H5、queryTopic
  → 按队列继续 ITV、视频匹配、验证
  → Review Site 的 projection / CSS / player runtime / 来源 Viewer
      ├─ 来源 Viewer 的离线验证、版式巡检与必要人工审阅
      ├─ portable-runtime-export：已有派生页与字体优化出口
      └─ Mathin 当前读取 site 和 src/viewer 源码
          → aixuexi-build-package：重新封装 source-runtime 页面及 H5 包
          → aixuexi-import-all / cw:import：匹配目标讲次并登记版本、对象
          → SourceRuntimeStage + H5 服务桥接：Mathin 中呈现
```

`portable-runtime-export` 目前是旁支，尚未接到 Mathin 主构建路径。来源主流程依据 [爱学习现行手册](../../../2026-07_mofaxiao_courseware/docs/current/aixuexi-localization.md) 第 126～198、477～532 行和 [run-har-localization.ts](../../../2026-07_mofaxiao_courseware/src/aixuexi/run-har-localization.ts) 第 521～590 行。

## 2. 为什么两边效果可能不同

### 2.1 魔法校：共享数据模型，呈现代码独立

来源导出器调用同一 `buildPageRenderModel`，并带上 `applyTextLayoutOverrides`，已经传递了本地排版覆盖。来源审阅调用 `viewer-app.ts` 的 `renderedNodeHtml` / `implementationHtml`；Mathin 使用 React `DocStage`，分别处理图片裁剪、富文本、字体默认值、表格、媒体和 H5 容器。

因此，页面 JSON、资源正文甚至坐标相同，也不能推导两边 DOM、CSS、交互时序完全一致。每次让人检查两遍，是在人工补偿这个实现边界。

优先方案是抽取 `page-doc-v1` 共用呈现核心，让来源审阅直接加载最终导出的页面文档，Mathin 编辑器在核心外提供编辑工具。这样可以保留现有文档、编辑及冻结历史合同。把魔法校全面转换成爱学习的 source-runtime 路径，需要扩展当前来源协议和验证编辑/课堂能力，适合作为另一个独立方案评估。

### 2.2 爱学习：来源函数相同，执行包装仍有多层版本

Mathin [loadAixuexiSourceViewerRuntime](../../scripts/lib/aixuexi-source-viewer-runtime.mjs) 第 44～56 行直接读取来源仓库四个 TypeScript 文件，并提取模板字符串；第 133～168 行通过精确字符串替换改写路由和资源接口，再替换启动入口。这些 seam 有缺失/歧义守卫，但本质上仍是消费方读取生产方内部源码。

随后还存在三层影响最终效果的处理：

1. [构建器](../../scripts/aixuexi-build-package.mjs) 第 467～555 行组合 CSS、字体、player 依赖和 HTML，生成新的内容寻址运行时。
2. [SourceRuntimeStage](../../src/features/courseware-doc/SourceRuntimeStage.tsx) 和 [4:3 适配](../../src/features/courseware-doc/source-runtime-four-by-three.ts) 处理外框、缩放、资源绑定、互动及编辑状态。
3. [H5 路由](../../src/app/api/cw-h5/[...path]/route.ts) 第 153～174 行会改写实际返回的 Viewer 脚本并注入课堂/编辑桥；[delivery](../../src/features/courseware-doc/source-runtime-delivery.mjs) 单独维护版本，当前为 `6`。

这些宿主职责有用途，但说明“Storage 包 hash 相同”仍不足以证明两次运行环境相同。可复用的验收身份需要同时包含内容包、呈现运行时、宿主桥版本以及 16:9/4:3 模式。比较时还要区分已发布来源页、教师草稿和课次覆盖。

这类差异已有历史实证：[2026-08-29 来源预览修复](../evidence/r1/teacher-microcourse-source-preview-hotfix-production.md) 记录了 Mathin 将 H5 绑定误作普通资源签名而加载失败，修复时既有 32 页与 283 个绑定保持不变。该记录证明宿主层曾独立产生问题，不代表今天仍有该缺陷。

### 2.3 本地产物已有版本分叉

对当前来源模板按现行打包函数计算，Viewer 指纹为 `770a4759427897d7c7ddeb728560da2244880b5f377eac60a8daea262ee0b744`。本机 `.tmp/aixuexi-import/` 下 G+、X+、A+ 秋季和 A+ 暑期四个标准包的 `sourceFingerprint` 都为 `3e5cc4ca7a01ba71554e1c9b039f2d42e3dffd0939894741b498d5bc6b66cf49`。

这证明当前源码与本机旧打包输入已经不同；不能仅凭指纹不同断言具体页面有视觉缺陷，也不能把临时目录中的包认作生产当前包。来源端改好后，Mathin 的已冻结版本按设计也不会自动更新，需要生成并选择明确的新版本。

## 3. 为什么导入一个简单 HAR 仍然长

| 阻力 | 当前证据 | 影响与优化方向 |
| --- | --- | --- |
| 课程包及数量写在构建代码里 | `aixuexi-build-package.mjs` 第 19～40、312～333、369～382 行，只接受 4 个包，并断言 56/1641、84/2767、30/1034、2/66 | 新包会被拒绝；已知包新增一讲也会触发固定计数不符。改为校验来源声明的本批真实范围，历史基线单独用于基线审计 |
| 源端可以单讲恢复，但默认要求全活动目录输入 | 来源手册第 128～143 行；`localize --lesson-id` 可缩窄 | 编排器应从 HAR 正文识别 lessonId 并显式传范围，主 HAR 与补包分别处理 |
| 单讲推进仍触发整站出口 | `run-har-localization.ts` 第 538 行未向出口传 lessonIds；来源手册第 506 行解释整站保护语义 | 保持完整审阅索引，增加按内容指纹重用未变页面；不能简单用缩小站点范围代替增量构建 |
| Mathin 构建没有讲次筛选，输出目录每次重建 | `aixuexi-build-package.mjs` 第 216～242、393、603～644 行 | 即使只想导一讲，仍生成整包文档与运行时；改为按讲次生成不可变产物，失败后保留上次完整产物 |
| 包级 manifest 变化被普通导入拒绝 | `cw-import.mjs` 第 849～859 行的 `AIXUEXI_SOURCE_PACKAGE_MANIFEST_DRIFT` | 来源 manifest 包含全包页面/资源摘要，一讲改变即可改变包摘要；需要版本化来源快照与讲次增量合同，不能直接取消守卫 |
| 全包摘要进入单讲升级身份 | `cw-import.mjs` 第 710～745 行 | 无关讲次导致包摘要变化，也会改变所选讲次的升级指纹；应分别维护来源观察记录与本讲实际内容/资源闭包指纹 |
| 目标课程目录必须先存在 | `cw-import.mjs` 第 1510～1525、1895～1903 行要求产品码、讲号、可选目录版本唯一匹配 | 原始 HAR 不是完整的 Mathin 建课指令。需要把目录匹配/新建预览并入同一任务，并明确版本歧义和计划占位 |
| 跨仓阶段主要靠 Agent/人衔接 | 来源 CLI 到导出和审计结束；Mathin 从已生成包开始 | 增加一个持久化编排入口，维护输入、目标包、讲次、阶段、产物和下一步动作 |

Mathin 外层 `aixuexi-import-all` 目前用 `--start-at / --limit` 按清单位置选讲；底层 `cw:import --courseware-id` 已有稳定讲次选择能力。因此“导入一定得全量执行”不成立，主要缺口在上游准备、构建及版本接收合同。

## 4. 已有优化应直接利用

### CAS 和恢复能力

来源普通正文已经跨包 CAS 去重，逻辑目录使用 hardlink/引用；`localize` 根据数据库队列推进、分讲隔离失败。Mathin 导入器也已有共享 NDJSON 缓存、文件摘要验证缓存、Storage 存在缓存，以及重复对象跳过上传的逻辑（[cw-import.mjs](../../scripts/cw-import.mjs) 第 129～179、1567～1645、1724～1735 行）。不能把目前的慢全部归因于重复下载或没有缓存。

来源 SQLite 保存采集、发现、处置和验证状态；Mathin PostgreSQL 保存课程、编辑、release、权限与课堂冻结关系。两套数据库服务不同业务阶段；让生产课程直接依赖本机 Viewer 或来源 SQLite，会增加运行依赖，并不能解决版本一致性。

### 可移植运行时已有可用基础

来源 [export-portable-runtime.ts](../../../2026-07_mofaxiao_courseware/src/aixuexi/export-portable-runtime.ts) 已实现按讲次范围导出、输入指纹复用、源 player 图片布局物化和字体裁剪。现有 schema v2 整包 manifest 记录如下：

| 包 | 讲 / 页 | 已物化题目布局页 | 源字体字节 | 可移植字体字节 |
| --- | ---: | ---: | ---: | ---: |
| G+ 秋季 | 56 / 1641 | 787 | 14,851,340 | 778,220 |
| X+ 秋季 | 84 / 2767 | 1098 | 42,090,436 | 4,362,324 |
| A+ 秋季 | 30 / 1034 | 397 | 21,093,892 | 1,014,804 |

这些是现有 manifest 记录的字体体积，不是导入总耗时、页面视觉通过或全包下载量的测量。三个产物均声明 `requiresQuestionImageSizing=false`。

Mathin 当前脚本未读取这些 manifest，而是从 `site` 重新取页面与字体依赖，因此这部分优化尚未进入当前导入链路。可移植产物本身也还没有 `index.html`、完整 Viewer JS 和 Mathin 所需的完整 H5/课堂桥接合同；不能仅替换一个目录参数就完成接入。

### 验收已有可复用合同

来源 [现行手册](../../../2026-07_mofaxiao_courseware/docs/current/aixuexi-localization.md) 第 510 行已有讲次级版式巡检缓存，绑定本讲页面、运行时、巡检规则和浏览器版本；[共同合同](../../../2026-07_mofaxiao_courseware/docs/current/contracts.md) 第 93～116 行把人工审阅限定在工程闭合后的少量歧义页面。

因此，要求用户在来源端逐页验收一遍、在 Mathin 再逐页验收一遍，并不是现行合同必然要求的日常操作。应由工程侧先定位两端产物、比例或宿主差异，再交付最终页面。

## 5. 建议的目标流程

```mermaid
flowchart LR
    I[JSON 或 HAR + 授权视频] --> J[统一导入任务]
    J --> L[来源引擎按讲次采集与物化]
    L --> P[版本化页面 + 共用运行时 + 资源闭包]
    P --> V[同一产物的机器验证]
    V --> M[Mathin 目录映射与导入]
    M --> A[Mathin 最终页面人工验收]
```

统一的是任务入口和实际呈现产物。来源仓库继续维护采集器、状态机和源站兼容；Mathin 继续维护课程运营、编辑、发布和课堂。运行时发布包要能离开来源仓库独立运行。

每个待交付讲次至少携带：

- 稳定的来源系统、课程包、讲次 ID，以及单独的来源快照版本。
- 页面集合及摘要、资源闭包摘要、呈现运行时版本/摘要。
- 宿主协议及桥接版本、画幅/适配模式。
- 机器验证所对应的完整输入指纹与结论；人工验收单独记录对象和范围。
- 新增 / 内容更新 / 原样复用 / 待补输入的计划，以及映射到 Mathin 课程目录的结果。

普通新增一讲应只处理这一讲和新发现的依赖。共享 Viewer 或 CSS 改变时，才按依赖关系扩大机器回归范围；既有冻结课堂持续读取原版本。内容有变化时重新验收变化内容，宿主或适配有变化时验收相应教学行为。

## 6. 分步实施建议

### 第一批：用一个新增 HAR 走通单讲日常导入

优先解决最常发生的场景：向已知课程包新增一个已有 schema 的讲次。

1. 增加统一任务入口，接收 HAR/视频目录及目标环境；自动识别讲次并调用已有恢复步骤。开发环境为默认目标，生产晋级沿用独立授权和目标 preflight。
2. 把固定包定义迁到声明式配置/来源 manifest，将“历史整包基线检查”与“本次真实输入范围检查”分开。
3. 让打包与导入都按稳定讲次 ID 选择范围；将来源包快照版本化，保留旧 manifest，按单讲内容变化决定是否新增 release。
4. 自动核对目标目录并产出可审阅的映射计划，成功后给出 Mathin 最终课程入口。

本批验收：新增一讲不改导入器代码；用户不在两个仓库之间手动交接；中断可从失败阶段恢复；重跑相同输入复用正文与 release；未变讲次和冻结历史保持原值。这个批次缩短操作链路，呈现一致性的结构性工作由下一批解决。

### 第二批：让爱学习交付与验收使用同一份产物

在来源现有 `portable-runtime-export` 上补齐完整可执行运行时、资源/H5 清单和协议入口；来源审阅页加载这个实际交付产物。Mathin 只验证并消费产物，逐步退出模板源码提取。将 Mathin 宿主注入版本纳入一致性证据，并保留针对签名、sandbox、媒体控制、翻页和 4:3 的集成检查。

本批验收：同一讲、同一画幅、同一 runtime 与 host 合同下，来源审阅和 Mathin 使用同一内容与呈现核心；来源优化能在交付清单中明确体现；用户在 Mathin 完成一次内容验收。

### 第三批：统一魔法校页面呈现核心

让来源导出预览和 Mathin 共同使用 `page-doc-v1` 呈现核心，保留 Mathin 编辑界面和版本关系。先覆盖一讲包含富文本、图片裁剪、动画、视频与 H5 的代表样本，再按共享核心的实际影响扩大机器检查。既有数据按版本策略逐批晋级。

## 7. 本次核查结果与限制

- 完成两个仓库当前主链路、CLI 范围、构建/导入合同及呈现入口的源码核查。
- 当前来源 Viewer 能通过现有模板加载和 seam 转换；这只证明字符串接口仍可接合。
- 从四个本机标准包各取一讲执行只读 `loadImportPlan`：39、31、48、34 页的四份导入计划均可解析并通过其清单/文档合同；未执行 `importCourseware` 或 SQL。
- 读取四个标准待导入包的运行时指纹，以及来源 schema v2 可移植产物 manifest；未对全库资源正文重新做审计。
- 生产当前使用的包、运行时、宿主版本，以及用户遇到的具体视觉差异页面，仍需在实际问题定位时核对。本报告不把本地文件或历史生产证据推定为当前生产状态。

本轮最值得优先落地的是第一批的单讲增量合同和统一入口，同时用第二批的一份实际交付产物解决重复内容验收。单纯减少检查命令或继续给两套呈现分别补样式，无法消除版本分叉。
