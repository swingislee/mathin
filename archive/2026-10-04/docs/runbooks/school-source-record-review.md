# 原表资料与可能重复提示

状态：开发端已交付，待人工验收。生产版本另行发布。

## 办理入口

学生表、线索表与首联行显示“可能重复”标签。当前条件是规范化后的姓名一致，且任一联系号码一致；规范化包括姓名宽窄字符、大小写、空白及中国手机号的国家码。电话相同而姓名不同的孩子继续作为不同记录。同名但没有有效号码、别名或录入错误不纳入本轮提示。

点击标签或姓名打开学生 360，再点击“查看原表资料与相关记录”。相关记录只列出当前员工可查看的对象；已经绑定同一学生的线索不重复列为候选。老师可以照常办理，在实际需要时查看相关记录，再决定是否使用既有的关联或合并入口。本功能只读取资料，不创建清理任务或自动改变身份。

原表资料按原来源记录分开展示，包含表名、文件名、原日期、字段名和原字段文本；不同表的同名字段各保留自己的值。非空业务字段直接读取原档案，新增字段也能展示。系统字段与空值不占用资料区域；公式展示已归档的结果文本，附件字段展示原记录中的文字或链接信息。附件文件本体另按已有存储能力访问。

已有的推断关联标为“资料关联待核对”。本轮沿用原关联，不增加姓名或电话推断的来源绑定。每次读取十条原记录，支持翻页；名单只查询当前页的重复提示，原表全文在用户打开入口后读取。

## 导入字段报告

运营导入计划新增 `fieldCoverage`，按来源表和字段 ID 列出非空单元格数、被映射器查询的单元格数、尚未被查询的单元格数。报告保留字段名称和计数，不复制个人字段值。

`source_field_ids` 是来源锚点，整行业务记录已生成也是行级证据。二者都不能证明每个字段已进入结构化业务字段。`fieldCoverage` 中的“已查询”仍只表示映射器访问过字段，需要继续核对目标列、转换规则和界面用途后，才能登记为结构化映射完成。

原表查看入口承接完整阅读需求。后续的 [Base 全字段业务资料整理](base-business-field-organization.md) 已为已知字段登记业务语义和转换方式，并把获客地点、日期、渠道、获取人员、触达内容与组别接回线索表。逐条业务资料与原字段共同保留，当前工作状态继续沿现有业务事实推导。

## 开发验证与发布

本机依次运行 `node scripts/school-record-review.mjs --preflight`、`--check`、`--apply`。脚本核对主机、应用实际 Supabase origin、监听进程、Docker 网络和数据库指纹；`--check` 验证范围与回滚，`--apply` 要求迁移校验和及数据库版本与检查时一致。

固定开发账号的只读 RPC 与 HTTP 启动检查使用 `node --experimental-strip-types scripts/verify-school-record-review.mjs <本机局域网开发地址>`。人工验收从[学生表](http://192.168.5.213:3130/zh/dashboard/students)或[线索表](http://192.168.5.213:3130/zh/dashboard/followups/leads)进入。本流程只适用已经核对的本机开发库，生产发布走独立授权及对应运行手册。
