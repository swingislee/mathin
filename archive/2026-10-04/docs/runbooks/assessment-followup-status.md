# 测评小状态与持续跟进（开发端）

本增量对应产品负责人 2026-09-07 确认的四环节细分与自动标签规则。阶段导航只用于查看；测评、沟通、意向、预约和报名各自在实际保存时形成事实。开发页面等待产品负责人验收，生产与正式 Gate 保持原状态。

## 业务口径

- 四个环节为待测评、测评登记、反馈沟通、去向跟进。行内标签展示具体状态，主筛选与表头细分筛选读取同一组已保存事实。
- 本批不增加“登记中”。逐题进度与已保存草稿继续展示，形成最终结果后进入待反馈。页面浏览、输入未保存内容与预约时间经过都不代替业务事实。
- 家长沟通保存可以没有明确去向；已开展沟通而未决定下一步显示沟通中。考虑中、有意报名、等待开班、暂不报名保留原含义。
- 体验意向是独立事实，可与考虑中同时保存，不要求体验时间、班级或活动，也不自动创建体验场次。意向已确认时显示“体验课”；实际排课仍使用活动/邀约业务入口。
- 已报名依据本次关联的有效报名或独立来源修复明确确认的历史报名事实，并让整条主行及固定姓名列使用已有浅绿表面；家长口头意向不生成报名。提前报名仍保留尚未完成的测评进度。
- 取消与未到分别展示，本次已结束预约不进入活跃四阶段队列。改期标签依据本批之后保存的结构化时间变更，不从文本或过去时间猜测，也不回填旧记录。
- “状态与类型”列使用“继续测评登记／生成测评报告／反馈测评报告”替换行内的“测评中／待反馈”，按已保存结果及报告是否存在区分；标签不带前置圆点。当前工作保留测评老师、逐题入口及已保存的下次联系时间，不重复展示状态标签。
- 1v1 行内类型标签继续隐藏，类型筛选保留；活动集中测评继续展示类型。学生 360 四个业务阶段与首联基线保持原样。

## 保存与历史

`assessment_workflow_states` 新增 `trial_intent`、`contacted_at`；`activities`、`lead_invitation_threads` 新增可空 `rescheduled_at`。不回填、删除或重写既有业务记录。

导航在客户端保持只读；旧客户端的 `visit` 写命令由服务端拒绝。实际测评入口维持原有保存与最终结果生成机制。

反馈沟通与去向跟进共用家长沟通保存，继续追加版本化历史。专业结果已定稿时仍可保存新的家长反馈和体验意向；修改已定稿专业结果继续要求修订原因。提前沟通尚无专业结果时不锁住后续测评登记。

报告查看与导出不记录发送。实际反馈报告后，在这次沟通中确认具体报告版本并一起保存；服务端拒绝旧版本、版本冲突和越权主体。旧快照和发送记录继续保留。

## 本机验证入口

`node scripts/assessment-followup-status.mjs --preflight|--check|--apply` 复用本机目标校验，核对执行主机、实际 Supabase origin、监听进程、Docker 网络和数据库标识。`--check` 在事务内验证并回滚；`--apply` 校验 migration 摘要与已检查 ledger head 后应用。已应用相同版本不会重复执行。

默认检查 `20260907001800` 的沟通与改期合同；增加 `--closed-order` 检查 `20260907002000` 的关闭预约读取顺序。后者让已取消预约进入原权限内的完整名单与细分筛选，保留 `security_invoker` 和基础表 RLS，避免业务行与排序清单缺项。

定向数据库断言覆盖体验意向无需场次、意向并存、提前沟通不锁测评、持续追加沟通、专业结果修订、报告版本、并发冲突、直接写与越权保护、改期标记、取消保持关闭、意向不创建报名。25 张既有业务表按新增字段以外的完整行指纹比较，测试夹具随事务回滚。

单元与组件检查覆盖小状态推导、阶段只读、草稿保留、体验意向保存、定稿后继续沟通、类型和细分筛选。验证技能使用固定开发身份与现有 dev server 做 API/双语页面启动检查；视觉和实际业务效果由产品负责人在开发页验收。

只复查测评列表时，使用 `node --experimental-strip-types scripts/verify-assessment-workflow.mjs --assessments-only`，并通过 `MATHIN_VERIFY_BASE_URL` 指定已核对的本机入口；已有报告页检查结果可独立复用。
