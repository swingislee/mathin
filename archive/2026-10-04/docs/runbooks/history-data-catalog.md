# 全量历史资料编目

本流程读取已封存的来源档案，生成逐表去向、逐字段覆盖、归属计数、处理批次和代表案例。业务拆分、备注归属及历史修订沿用 [业务历史记录规则](business-record-history-state.md)。编目结果用于安排后续增量，当前匹配快照与单案例转换器分别标明适用范围。

2026-09-07 更新源表的权威顺序与交叉匹配结果见 [更新源表交叉整理](source-reconciliation.md)。本文及旧编目结果保留原快照适用范围；新批次使用更新配方生成的来源位置、员工分类和匹配候选。

## 执行与输出

```powershell
node scripts/history-data-catalog.mjs
```

输入为当前历史档案指针、封存 manifest、只读 SQLite 与 `docs/test_material` 原文件。命令核对文件集合、九份原文件的字节摘要及档案数据库摘要；来源新增或变化时，先更新来源档案再编目。SQLite 使用 `readOnly` 和 `query_only`，执行后再次核对摘要。命令不连接 Supabase，不修改原文件、身份、业务记录或既有修订。

私有结果保存到 `.tmp/history-data-catalog/catalog.json`。结果包含源文件标识、表和字段去向、批次、案例来源位置、生成时间及代码的规范化文本摘要。可筛选工作簿放在该目录的 `outputs/` 中。原记录位置和开发页面地址保留在私有交付物，仓库只保存匿名统计与转换规则。

## 计数与归属

- 提取源行包含空业务内容、表头、说明、运营资料和横向名单。去掉已识别表头后的源行仍不能作为学生人数或业务记录数。
- 字段清单覆盖提取档案中的字段与列位置，包含空字段、无标题列和来源元数据。有值单元格与无缓存公式分别计数。
- 班级导出原第 1 行的“班级ID／班级名称”已核对为表头。该修正只影响编目口径，原档案继续完整保留。
- 身份统计沿用结果中标注日期的快照。正式批次按目标库刷新来源映射、识别既有业务与人工修订，再生成增量。
- 员工、班级与内部运营资料使用各自归属规则；横向名单以单元格核对。旧匹配器在这些资料中的学生匹配不作为写入依据。
- “已有单案例涉及”只表示某些字段在样本中使用过。续报结果、不同测评类型、八组报名列、跨年同名期别及备考细节均需扩展规则后再处理。

## 使用顺序

先看工作簿的“整理概览”和“来源清单”，确定去向与批次；“字段去向”定位待补字段，“归属计数”解释候选范围，“抽查案例”打开已定位的真实来源。代表案例覆盖无备注的续报结果、多期报名、多类测评、仅线索沟通、多个归属候选、同电话多姓名、横向名单和退班退款。

第一批结构化验证候选为竞赛报名。正式计划需核对共用活动和届次、备考资料的承载方式、现有修订保留、目标身份与分页。已有样本包含在来源总量中，增量计划分别列出复用、新增和待核对记录。

数量与字段归属检查运行 `tests/history-data-catalog.test.ts`。本增量是来源编目交付；后续业务批量转换、开发端业务验收和生产晋级分别记录。
