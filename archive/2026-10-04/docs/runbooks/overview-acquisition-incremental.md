# 获客总览的 Base 增量来源

“新增线索”及其下钻明细通过 `list_current_staff_overview_acquisition_sources` 读取同一业务 Base 的当前来源。调用者不再传导出文件名或文件日期。

## 每次导入

1. 继续保存不可变原始档案，保留 `source_data.format='feishu-base'`、稳定的 `logicalSourceId`（早期档案可用 `id`）、`record_data.tableId` 和 `source_record_id`。稳定来源标识由 Base 本身生成，文件更名不改变它。
2. 增量只追加新增和变更行即可。读取按 Base、表、原始行编号合并版本，每行只计一次，未变化的旧行保留。无需修改应用常量、统计 SQL 或重新发布。
3. 新档案可显式保存 `source_data.snapshotDate='YYYY-MM-DD'` 表示导出版本日期。已有带日期前缀的文件兼容其前缀；两者均缺少时采用入库日期排序。补导历史版本时必须提供真实版本日期，避免把旧内容当作新修订；业务获客日期始终来自原表字段，不使用入库时间计算。
4. 同日版本按入库时间、档案编号稳定排序。重复文件沿已有导入唯一约束保持幂等。业务关联可以指向旧档案，读取返回旧编号别名用于关联和去重。
5. 导入提交后，在各自目标环境的管理员只读事务中运行 `scripts/sql/current-overview-acquisition-assertions.sql`。再以该环境的原始 Base 及应用日期规则复算月份来源数，分别列出生产原生线索与日期无法归期的来源。核对总览和明细人数；未通过时将导入登记为待核查，不能只凭原档写入条数宣布统计更新完成。

分页读取校验来源版本摘要。分页期间发生导入时返回不可用，由刷新重新取得一致版本，避免混合新旧批次。未安装读取迁移时也返回不可用，不回退到固定旧文件。

## 范围与验证

当前业务 Base 的逻辑标识为 `feishu-base:28a6f6af56504cab716f01eead37d73b5098d0830ed4b02b55c06dc93e135dc6`，获客表标识为 `tblzwPK2XgJa14EC`。表名和文件名可变；其他 Base 的同名表不会混入。真正更换 Base 或重建表时，应确认新的业务来源并迁移稳定标识映射。

本规则保留历史来源，没有推断源文件中消失的行已作废。源行删除、实际日期与月份标签口径、身份或正式班级调整继续独立核对。

开发验证：`node --experimental-strip-types scripts/current-overview-acquisition-reads.mjs --check`，执行前核对本机目标，在事务内验证版本合并、跨页去重、改名、迟到旧版本、关联别名和 RLS，并回滚全部测试行。`--apply` 只向已核对的本机隔离目标安装验证过的迁移。生产使用已冻结候选、写前备份、事务回滚演练和正式应用流程，不执行合成来源测试。
