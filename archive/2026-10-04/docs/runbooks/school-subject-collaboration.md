# 学生参与权限与业务分组

> 2026-09-10：开发端已交付，待人工验收。生产迁移与角色配置另行授权；本增量不改变阶段或 Gate 状态。

参与过学生业务的有效员工保留该学生的查看和编辑范围，具体操作继续校验岗位能力。学服、代课／测评老师、授课老师按业务角色展示；学生表的学服和老师字段可包含多人。“我参与的”读取参与经历，单一分配字段不再决定普通业务编辑范围。

参与经历来自已确认身份关系上的原业务人员、沟通记录人、邀约与测评老师、活动办理人、班级任课与学服安排，以及管理员或主管明确添加的参与人。员工调配后保留原参与经历。普通阅读不会新增参与事实，停用账号由现有身份校验撤回访问。

来源记录按已确认的 Lead／Student ID 关系汇合，只把唯一匹配既有员工的人员字段纳入参与经历，有效账号才能访问。业务角色可由管理员或主管明确配置，覆盖原表中容易混淆的人员字段分类；导入操作员的身份继续作为导入审计，原业务作者和来源凭据保持稳定。

## 业务分组

学生表点击“业务分组”，管理员与主管可新建或改名组别、配置员工业务角色、勾选加入组或取消勾选移出组。学生行的“参与人／组别”用于按实际分工添加人员或组别。

初始保留一、二、三组。原表确认、获客、跟进、到访、选拔交付、配合学服等明确组别与当前参与人的业务组共同用于组内查看；其他来源标签保留原值供核对。员工当前组员名单由管理员或主管维护，来源记录上的组别不推断员工现任组员名单。

“本组”展示当前组员有权查看的分配。组员通过组别获得只读范围；实际参与人可以在岗位能力内编辑。移出组后撤回该组提供的查看权限；同一员工通过其他组或既有参与经历获得的范围继续有效。组员变更、角色变更及参与人添加均保存操作审计。

当前工作和历史资料的边界继续由原工作状态决定，查看范围变化不会恢复已退出当前工作的记录。历史修订沿用字段白名单、版本冲突和前后值审计；共享活动的场次资料继续由活动管理权限维护。

## 本机核对与应用

```powershell
node scripts/school-collaboration.mjs --preflight
node scripts/school-collaboration.mjs --check
node scripts/school-collaboration.mjs --apply
node --experimental-strip-types scripts/verify-school-collaboration.mjs http://127.0.0.1:3130
```

每次执行核对 Windows 主机、应用实际 Supabase origin、监听进程、Docker 网络及数据库指纹。`--check` 在事务中应用迁移，以固定开发身份检查参与人编辑、同组只读、越组拒绝、主管管理、组员撤回、账号停用、历史修订与并发冲突，再回滚并比对原业务表和函数定义。`--apply` 要求同一迁移指纹和数据库版本已通过检查；合成业务事实始终回滚，原业务表内容保持不变。

私有目标核对、数据库检查和页面启动结果保存于 gitignored `.tmp/school-collaboration/`。开发账号按既有固定账号文件读取；页面检查不创建账号，也不替代人工验收。生产人员 ID 与明确业务角色清单单独保留于受控私有文件。
