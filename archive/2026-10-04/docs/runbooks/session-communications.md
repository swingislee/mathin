# 班级表格与课后沟通

## 操作

- 在“我任教的班级”中点击班级行内的“待上课”或“已上课”，原位选择课次进入备课或课后记录；正在上课的课次直接进入课堂。状态依据系统开课、下课记录，日期经过不自动标为已下课。
- 课后表格按学生展开，课评沿用自动保存与独立发布；沟通通过“保存”或“保存并下一位”显式提交，`Ctrl/Cmd + Enter` 保存当前沟通。切换学生保留草稿，成功后回显本课记录。
- 沟通填写日期、方式、结果和内容；选择“待跟进”时填写下次事项和日期。班群统一沟通使用“班级整体沟通”行，逐生沟通状态分别确认。
- 已沟通、待跟进、无需沟通、待处理按每名学生最近一次录入的决定统计。仍有待处理学生或待跟进事项时保留未完成状态，处理后点击“确认本次沟通完成”。后续追加沟通重新打开完成状态。
- 教学记录页提供课后记录入口，显示本课沟通与学生日常背景；学生档案内的逐生沟通可返回所属课次。

## 数据与权限

- 迁移 `20260915008000_session_communications` 为 `student_follow_ups` 增加课次、方式、结果与下次事项；复用实际日期与下次跟进时间。班级整体记录写入 `session_class_communications`。
- 原沟通保留原归属，不按日期或花名册猜测课次。当前名单与冻结名单分别沿用现有权威来源。
- RPC 同时验证员工、沟通权限、课次任课／学服范围及学生访问范围。取消或作废课次保留只读记录。新上下文字段及整体记录经受控 RPC 写入。
- 保存使用客户端提交 ID，重复请求返回原记录，内容冲突保留原值。沟通记录追加，最新录入决定当前状态；通用任务完成入口同样检查已有课次沟通的剩余事项。

## 本地检查

使用固定开发身份及已有隔离目标核对工具，不创建测试账号。SQL 样例与关联事实在同一事务回滚，正式应用只增加本次 schema。

```powershell
node scripts/session-communications-local.mjs --preflight
node scripts/session-communications-local.mjs --check
node scripts/session-communications-local.mjs --apply
node --experimental-strip-types scripts/session-communications-http-local.mjs
```

`--apply` 要求当前迁移摘要与通过检查的版本一致。HTTP 检查仅读取固定教师的中英文班级表格、课后页；视觉和连续填写手感由产品负责人在开发端验收。本批不改变生产部署或阶段 Gate。
