# Base 工作视图与学生阶段差异核对

- 用户目标：先查清老师从飞书多维切到 Mathin 后找人、接续沟通及阶段标签的差异，再让排列与实际工作习惯衔接。
- 本批范围：读取 10 月 5 日 Base 的完整视图配置、对应生产版本代码，并只读核对生产标签与人数。诊断已完成；本批没有修改界面、生产数据或标签规则。
- 私有材料：`.tmp/base-view-alignment-20261005/`；公开记录只保留结构、规则和聚合数字。
- 生产取样：2026-10-05 20:38（北京时间），应用提交 `4ea559922bfff101458c33c2495e24dbe57aeb01`。以下人数为管理员全部可见范围，不能替代逐老师的权限及实际工作视图验收。

## 已确认的差异

1. **工作视图没有随记录迁移。** Base 包含 19 张表、66 个视图。获客、到访、秋季在读三张核心表共 35 个视图，33 个没有显式列排序、依赖原行序再分组，30 个带分组，29 个带筛选。文件包含视图行序、全局及视图 rank、分组、筛选、列顺序、显隐、宽度和冻结列。现有 `extractFeishuBase` 逐行抽取身份、字段与记录元数据，`sourceRow` 为 null，没有把视图及原行序交给业务列表使用。
2. **同一个“学生”入口覆盖了不同对象集合。** 当前统一业务索引有 5,641 个对象，其中 1,468 个已建档学生进入学生名录，4,173 个纯线索留在沟通侧。`students/page.tsx` 默认打开 `StudentDirectoryPage`，其 SQL 明确只选 `student_id` 非空；在这个入口搜索纯线索不能找到人。
3. **排列与密度同时改变。** 学生名录默认按正式班级分组，再按组名、姓名排序，每页 100 人，显示随宽度重新排布的卡片。沟通列表默认按 `createdAt` 倒序、对象键兜底，并按阶段划分。二者都不使用 Base 原行序。老师原来记住的相邻记录、滚动距离和列位置被重新组织。
4. **“我的”范围含义不同。** Mathin 通过正式参与、学服及小组关系计算范围；Base 视图按获取人员、确认人员、学服、授课老师等不同列筛选。这些岗位列不是同一个负责人字段。恢复工作视图须保留真实权限边界，分别映射展示筛选和授权关系。
5. **接续位置只保留在当前工作会话。** 现有沟通保存逻辑会保留本轮行位和“已处理”，但默认入口没有 Base 视图标识、上次处理行及持久化的接续位置。离开当前视图、重新从入口打开时，不能据此恢复老师原来的位置。
6. **源字段被压缩到较少的展示栏。** 到访视图原有 27–47 个可见列，获客视图 11–41 个。Mathin 摘要主要展示姓名、电话、单一情况、学服、最近记录及部分测评背景。加 V、诺访、进群、下期次再联系、意向分类等事实并非都作为独立可扫描／可筛选列出现。

## 三类视图应恢复的定位规则

| 工作表 | Base 中实际保存的组织方式 | Mathin 当前差异 |
| --- | --- | --- |
| 获客与私域 | 获客组别筛选；确认人员、沟通人员或获客组别分组；保留原行序 | 按阶段及创建时间排列，跨阶段拆开老师的一组沟通对象 |
| 到访信息 | 按确认／到访月份筛选，主要按学服分组；个别视图按到访日期、时段或报名日期排序 | 当前阶段及学服列表无法直接恢复原月份、组内位置和并列业务列 |
| 秋季在读 | 授课老师 → 单师班序两层分组，按上课周次或老师筛选，保留组内原行序 | 正式班级目录的组名和姓名序不同；来源单师班序不能擅自替代正式班级关系 |

## 大、小标签核对

- 本次在管理员范围对照业务索引、学生卡片、沟通明细：相同对象的大、小标签一致，未发现入口间计算结果分叉。该结果只证明入口一致，不证明每个来源记录的事实完整或业务判断正确。
- 当前阶段：待首联 1,885，待测评 3,130，待报名 290，待续保 166，已停课 170。
- 细分情况高度集中：2,910 人显示“尚未预约”，290 人全部显示“测后未报”，1,304 人显示“待分配”。单一小标签同时承担分配、沟通、测评、报名及续班含义，无法完整说明下一步。
- 1,104 个已建档学生处于待首联，其中 1,103 个没有关联线索。查询未找到其已链接的历史／在读主档状态或班级来源证据；这是资料不足的候选，不能仅靠阶段兜底就认定老师从未联系过，也不能擅自改成已停课。
- 待续保包含 165 名本期在读学生及 1 名待入班对象，含义是服务关系继续，并不表示每个人当前都要办理续报。来源意向、确认缴费、当前入班及下一期续报继续分别记事实。
- 学生卡片的大、小标签目前放在图标 tooltip 和 `sr-only`，默认没有可见文字；沟通列表虽显示情况文字，但具体下一步仍主要依赖主阶段选择动作。
- Base 获客“确认结果”为多选，可并存加 V、诺访、已进群、下期次再联系、未通等记录；“跟进结果”“当下状态”“意向分类”又是独立字段。不能把这些并行事实全部替换成一个阶段标签。

## 后续施工的具体边界

1. 先提供获客、到访、在读三类连续表格工作视图，导入原视图筛选、分组和行序，保留必要的列顺序、显隐与冻结列。按稳定来源行键恢复位置；同一学生跨事项共享身份，重复来源行不创建重复学生。
2. 找人入口覆盖当前权限内的学生及线索，并明确当前工作视图的范围。班级目录继续服务教学名录，常用工作视图可直接打开、保存并恢复上次位置。
3. 工作视图负责“在哪里接着做”，大阶段负责当前业务事实。保存后本轮名单保持当前位置，不因阶段变化立刻跳走；下一次主动刷新时再反映筛选变化。
4. 大阶段、小状态和下一步均以文字可见。联系结果、微信／进群、邀约、测评、缴费、分班、续班意向及负责人分列或并行标签呈现；小状态服务下一步动作，不把所有状态压成一个枚举。
5. 缺少充分依据的记录显式提示阶段待核对；阶段判定展示所依据的事实。有效联系、实际测评、正式报名、在班／课程结束的边界继续统一，付款备注、诺访和来源班序不冒充正式事实。
6. 首轮用一张老师真实常用视图验收“从熟悉的一段继续沟通”，再扩展其他视图。已询问最典型视图，当前尚未收到具体名称。源码读取与汇总核对不能替代老师实际使用。
