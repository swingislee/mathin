## 已确认的差异

1. **原名单的定位关系没有随记录迁移。** Base 包含 19 张表、66 个视图。获客、到访、秋季在读三张核心表共 35 个视图，33 个没有显式列排序、依赖原行序再分组，30 个带分组，29 个带筛选。文件包含视图行序、全局及视图 rank、分组、筛选、列顺序、显隐、宽度和冻结列。现有 `extractFeishuBase` 逐行抽取身份、字段与记录元数据，`sourceRow` 为 null，没有把分组及原行序交给业务列表使用。应提取老师依赖的定位关系，而非完整复制全部视图配置。
2. **同一个“学生”入口覆盖了不同对象集合。** 当前统一业务索引有 5,641 个对象，其中 1,468 个已建档学生进入学生名录，4,173 个纯线索留在沟通侧。`students/page.tsx` 默认打开 `StudentDirectoryPage`，其 SQL 明确只选 `student_id` 非空；在这个入口搜索纯线索不能找到人。
3. **排列与密度同时改变。** 学生名录默认按正式班级分组，再按组名、姓名排序，每页 100 人，显示随宽度重新排布的卡片。沟通列表默认按 `createdAt` 倒序、对象键兜底，并按阶段划分。二者都不使用 Base 原行序。老师原来记住的相邻记录、滚动距离和列位置被重新组织。
4. **“我的”范围含义不同。** Mathin 通过正式参与、学服及小组关系计算范围；Base 视图按获取人员、确认人员、学服、授课老师等不同列筛选。这些岗位列不是同一个负责人字段。承接其业务分组须保留真实权限边界，分别映射展示筛选和授权关系。
5. **接续位置只保留在当前工作会话。** 现有沟通保存逻辑会保留本轮行位和“已处理”，但默认入口没有持久化当前工作范围、上次处理行及接续位置。离开当前范围、重新从入口打开时，不能据此恢复老师原来的位置；解决此问题不要求复制 Base 视图标识。
6. **减少列还没有完成按当前工作组织信息。** 到访视图原有 27–47 个可见列，获客视图 11–41 个，这个数量不是优点或目标。需要核对的是老师本次工作所需信息能否直接看见、顺手记录；其他信息应在共用学生概况与经历中连通。加 V、诺访、意向等按当下任务选择呈现，不要求全部变成独立列。
7. **大阶段和默认操作绑定过紧。** `communicationEntryMode` 会把待首联导向联系、待测评导向邀约、待报名导向报名。相同阶段内仍可能进行回访、情况补充或约定下次联系，默认操作需要考虑老师当前工作；仅由大阶段选择表单容易错位。

## 三类工作可承接的定位规则

| 工作表 | Base 中实际保存的组织方式 | Mathin 当前差异 |
| --- | --- | --- |
| 获客与私域 | 获客组别筛选；确认人员、沟通人员或获客组别分组；保留原行序 | 按阶段及创建时间排列，跨阶段拆开老师的一组沟通对象 |
| 到访信息 | 按确认／到访月份筛选，主要按学服分组；个别视图按到访日期、时段或报名日期排序 | 当前阶段及学服列表无法直接恢复原批次、月份及组内位置 |
| 秋季在读 | 授课老师 → 单师班序两层分组，按上课周次或老师筛选，保留组内原行序 | 正式班级目录的组名和姓名序不同；来源单师班序不能擅自替代正式班级关系 |

## 大、小标签核对

- 本次在管理员范围对照业务索引、学生卡片、沟通明细：相同对象的大、小标签一致，未发现入口间计算结果分叉。该结果只证明入口一致，不证明每个来源记录的事实完整或业务判断正确。
- 当前阶段：待首联 1,885，待测评 3,130，待报名 290，待续保 166，已停课 170。
- 细分情况高度集中：2,910 人显示“尚未预约”，290 人全部显示“测后未报”，1,304 人显示“待分配”。单一小标签同时承担分配、沟通、测评、报名及续班含义，无法完整说明下一步。
- 1,104 个已建档学生处于待首联，其中 1,103 个没有关联线索。查询未找到其已链接的历史／在读主档状态或班级来源证据；这是资料不足的候选，不能仅靠阶段兜底就认定老师从未联系过，也不能擅自改成已停课。
- 待续保包含 165 名本期在读学生及 1 名待入班对象，含义是服务关系继续，并不表示每个人当前都要办理续报。来源意向、确认缴费、当前入班及下一期续报继续分别记事实。
- 学生卡片的大、小标签目前放在图标 tooltip 和 `sr-only`，默认没有可见文字；沟通列表虽显示情况文字，但具体下一步仍主要依赖主阶段选择动作。
- Base 获客“确认结果”为多选，可并存加 V、诺访、已进群、下期次再联系、未通等记录；“跟进结果”“当下状态”“意向分类”又是独立字段。保留这些并行事实，当前工作只展示相关的少量状态与提示，其余在学生整体情况中可查看。

## 后续施工的具体边界

1. **名单组织、当前操作和整体情况分别承担职责。** 名单让老师找到并连续处理一组人；工作内容由首联、后续沟通、测评、报后服务决定；共用学生概况连接所有事实与历史。大阶段不是唯一工作入口，同一学生可出现在不同任务名单，身份与业务事实共用。
2. **从原表提取有用的分组和顺序。** 参考人员分工、批次／月份、授课老师与班序组织名单。保留可确认的组内相对顺序；明确同一对象多来源顺序冲突及新增对象放置规则。无需复制 35 个视图、原列数、列宽和隐藏列配置，信息排布由当前任务重新设计。
3. **保存和恢复真实工作位置。** 保存后当前人不跳走，本轮名单不因阶段变化自动重排；离开后恢复工作范围、分组展开和当前对象，再以对象定位恢复可见位置。临时按到期日等条件排序由老师明确切换，搜索结果返回时保留原名单上下文。
4. **按当前任务精简查看与录入。** 首联突出联系电话、来源背景、联系结果与下次安排；后续沟通突出上次承诺、关键情况、最新变化及下一步；测评突出相关学情、家长期待和结果；报后服务突出当前课程／班级、学习与服务情况。沿用已有可用的行内编辑器，避免重复填写已知信息。
5. **学生全貌在同一工作位置可达。** 姓名、必要身份信息和当前大阶段可见；相关事实摘要及统一经历就近展开，补看和补记后留在原人、原组。精简当前界面不应切断业务信息，也不要求把全部情况摊成列。
6. **阶段、当前状态和下一步分别表达。** 大阶段由已发生的事实判断；小状态选择与当前工作有关的信息；下一步结合当前任务及老师明确安排。同为待测评，可以分别进行未接通回拨、诺访协调或下期联系，不一律默认创建预约。资料不足显式提示待核对，避免把未知当成从未联系。
7. **按连续工作验收。** 验收“进入熟悉的一组 → 从上次那人继续 → 用当前任务需要的信息完成记录 → 必要时看学生整体情况 → 保存后继续下一人”，同时观察是否频繁搜索、切页面或重复录入。典型 Base 视图只用于理解这一过程，不作为界面复刻清单。
