# 整站开发冷启动

- 用户范围：专门处理本地整站冷启动；生产和数据库不在本次变更范围。
- 起点：`83e9e7fd` 已恢复默认 Turbopack 并拆分微信登录入口；网页首次准备仍约 36–47 秒。
- 定位：已有 trace 的 `compile-path` 约 46 秒，登录页 `ensure-page` 约 35 秒；业务处理小于 1 秒。单独运行现有 PostCSS，全站样式用时 22.661 秒，其中依赖登记约 21.998 秒；扫描包含测试、SQL、脚本和任务记录，共 3,756 个文件依赖。
- 修复：Tailwind 从 `src/` 检测类名，额外包含实际渲染的 `content/` 文章；依赖降到 2,055 个，样式编译 485 毫秒、依赖登记约 36 毫秒。生成 CSS 仅移除了源码与文章之外带入的选择器。开发文件系统缓存恢复开启，保留 JavaScript/Turbopack 的 4 GiB 预算和既有 React 调试内存保护；可用 `MATHIN_DEV_CACHE=0` 作有针对性的缓存诊断。
- 真实请求：配置变更后的推广页首次准备由此前 48 秒降至 7.6 秒（框架部分 6.0 秒）；随后首次读取登录页 1.173 秒、首页 1.085 秒。上述是同机单次观测，页面请求有共享模块复用，不等同独立清空缓存的基准测试。
- 重启复用：通过 Next 正常重启得到新 worker，服务约 646 毫秒就绪；推广页 2.2 秒，登录页 777 毫秒、首页 737 毫秒、文章页 2.089 秒、微信状态入口 785 毫秒，全部 HTTP 200。磁盘缓存已写入 `.next/dev/cache/turbopack`。
- 安装修复：文章首次编译暴露本地 Babel 包缺失；依赖链接检查又定位相关通用包/子依赖缺失。按锁文件版本和 SHA-512 从官方源恢复 `@babel/code-frame`、`@babel/compat-data`、`@asamuzakjp/css-color`、`@csstools/css-color-parser`、`@csstools/css-parser-algorithms` 及原版本链接。包版本与锁文件未变。
- 检查：配置定向 ESLint 通过；新增源码中的任意值样式在约 660 毫秒内生成，临时探针已移除；真实页面、CSS 与文章读取通过。不重复全库测试，不运行生产构建，视觉与长期开发使用待产品负责人验收。
- 状态：开发端已可操作，生产和数据库未改动。后续方法与注意事项见 `docs/ops/development-performance.md`。
