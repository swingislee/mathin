# 管理员微信登录免重复 MFA

## 范围

产品负责人要求修复管理员绑定账号后，通过微信登录仍被要求 MFA 的问题。网站扫码和服务号授权共用微信回调；本次在该回调核对账号、绑定身份和当前原生会话后记录会话证明，后台管理员入口接受这份证明。密码登录继续要求 MFA，首次绑定保留密码与原有 MFA 核验。

## 实现与边界

- 会话证明以服务端密钥签名，限定站点、Auth 源、用户、原生 session ID 和微信身份摘要，保存在 Secure、HttpOnly、SameSite=Lax 的主机 Cookie，最长 30 天。
- 后台首先核对真实会话仍然存活、账号状态和所需协议，再核对证明与当前仍有效的微信绑定。正常刷新保持同一 session ID；密码重登、退出、解绑、过期或篡改不能沿用证明。
- 不修改 Supabase 的 AAL、MFA 因子、账号元数据或数据库 schema。

## 当前交付点

- 已实现网站扫码、服务号授权和绑定回调的当前会话证明，以及管理员入口的对应判断。共享登录身份类型和其他角色权限保持原有合同。
- 机器检查通过：`wechat-trusted-session`、`auth-admin-wechat`、`wechat-callback`、`wechat-session` 四项定向用例，覆盖合法微信、密码登录、跨用户／会话重放、篡改、过期、解绑、锁定、首次绑定、所需协议与原生会话失效；修改源码及测试的 ESLint、定向 TypeScript 检查通过。验证完全使用内存模拟身份，没有数据库写入。
- 开发 3130 已监听，健康接口和登录页可加载。开发入口 `http://192.168.5.213:3130/zh/login`；真实微信需要已登记 HTTPS 源，手机微信往返仍待负责人验收。
