# 微信恢复登录会话时保留管理员验证

- 目标：首次微信登录后，关闭微信再打开网页，仍有效的原登录会话可继续进入工作台。
- 事实：用户确认重新点击工作台仍要求 MFA，排除仅恢复旧提示页；生产 128bb967 包含上次 Cookie 证明实现。尚未取得手机端 Cookie，不能断言具体丢失原因。
- 判断：当前微信证明独立于原生登录凭据保存在浏览器，恢复登录不能保证恢复证明。将已验证的证明保存到服务端并绑定同一原生会话，可覆盖证明 Cookie 丢失后的恢复。
- 范围：证明持久化、当前会话只读 RPC、相关类型与安全检查。保留原生 AAL、30 天证明期限、密码登录 MFA、账号门禁；首次 OAuth 证明失败时不登记。
- 必要检查：定向鉴权用例验证 Cookie 缺失、同一会话续期、跨用户/会话拒绝、篡改、过期、解绑、撤销、存储故障；隔离 SQL 验证读写权限与级联撤销；修改文件静态检查。完成后交付，不追加浏览器验收。
- 已实现：服务端保存签名证明，以原生会话和微信 identity 外键关联；当前用户 RPC 只读取本人当前会话；旧有效 Cookie 校验后迁移，期限不延长。新登录登记失败时撤销该未完成的登录。
- 机器检查：四个定向鉴权文件通过，覆盖 Cookie 缺失恢复、原生会话续期、跨会话/用户拒绝、密码 MFA、签名/期限、解绑与回调失败。无网络临时 PostgreSQL 中完成权限、级联删除及新增迁移事务回退检查；合成夹具已回滚。修改源码和测试 ESLint、定向 TypeScript 通过，新增类型由迁移后的隔离数据库生成。
