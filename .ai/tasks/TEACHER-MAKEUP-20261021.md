# 老师直接记录补课

- 用户范围：补课暂不引入教务参与或审批，老师直接操作，权限以后再收紧。
- 现有事实：旧补课安排关联已排好的课次，不能独立记录部分学生的补课学情。
- 本轮方案：在原课的最右侧提供“补课”，直接选择一人或多人、时间，保存安排或已补课事实；补课考勤、检查点和逐生学情单独保存，原课缺勤与学情保留。
- 范围：原课下的轻量补课记录，不创建新班级、正式排课或家长发布流程。现阶段本课主讲、助教、代课老师及管理员可操作；服务端沿用原课教学范围，权限判断集中一处。
- 必要检查：新增接口的教师权限、外班学生拒绝、并发修订、原课记录保留；定向源码静态检查。数据库先识别实际开发目标，再执行新增迁移与事务回滚检查。视觉和业务交用户验收，不主动运行浏览器。
- 验收入口：http://192.168.5.213:3130/zh/dashboard/classes?view=arrange&scope=mine
- 当前交付：课次右侧“补课”直接打开面板，默认选中原课缺勤／请假学生，支持修改名单、补课时间、待补课／已补课状态、逐生考勤、检查点与六档学情，并可重新打开既有记录继续修改。
- 开发数据：核对本机 WhiteHouse、192.168.5.213、3130 监听 Node、35421 本地网关与 Docker 内数据库标识后，在开发库应用新增表与 RPC 迁移；未改写已有课次数据。
- 实际检查：4 个源码文件 ESLint 与定向 TypeScript 通过；事务回滚检查覆盖本课老师保存、部分学生、独立学情、重复请求幂等、版本冲突、外班学生拒绝、无关账号读写隔离及原课记录保留。检查后补课表无残留测试记录。
- 类型：由本机数据库生成本次表与 RPC 类型，仅合入新增声明；生成服务恢复原先的停止状态。
- 状态：开发端可供人工验收；未运行浏览器，未部署生产。补课记录暂留在原课下，不进入正式课表或家长发布。
