- 目标：把多维表的混合状态拆成五个互斥主阶段＋少量有用的小状态；小状态与备注原文对应；重复导入不再产生副本；保留生产独有记录。现在与过去只看日期，“当前／历史”标签前后端全部舍弃。
- 分工：2026-10-15 起按用户指示接手性能会话（2026-07-mathin-92）的名单读取改写与活动页；该会话确认无未提交改动并停止相关 SQL。
- 当前：两条迁移已应用开发库并跑完 10-14 增量导入；前端去掉“当前工作／历史记录”，活动页、待报名、已停课完成改写；生产未写入（需本次明确授权）。

## 现状结论（生产只读，2026-10-15）

1. **historical 是隐藏机制而非时间口径。** 5,893 个来源行被 `history_review_required/reference_only` 范围归档，视图层隐藏 874/967 条到访登记、355/519 条课程机会、349/516 条报名；`business_source_is_authoritative` 丢弃 xlsx 来源（2024 课表 850 条报名）。结果：已停课只剩 4 人，166 名曾报名学生落在待首联（111）和待测评（51）。
2. **小状态单一且错位。** 待首联 1,458 人显示“待分配”（负责人属性）；待测评 2,408 人“尚未预约”；待报名 307 人全是“测后未报”；续报 172 人全是“在读”。
3. **结构字段不可靠，备注才是信号。** “确认结果=暂无结果”的 545 行里大量备注是“直接拒绝／已经在学了／太远”；“诺访”下也有“未接”。
4. **前系统名单混合多种事情。** 班级学生导出含正式课、公开课／闯关／讲座、短期专项课、测评班、抵用券与真题手册；950 名仅来自前系统列表的学生全部挂在待首联。
5. **重复记录来源。** 同一来源行的事实没有按版本重复；重复主要是同一家庭在不同表、不同行重复出现（同电话多线索 179 组）以及成对的“测评＋体验课”登记（正常）。本次导入继续按逻辑行原位更新。
6. **名单逐行明细读取与阶段不一致。** 旧 `student_record_row_with_context` 逐行重算阶段，已停课名单里 55 行显示“续报已确认”、31 行显示待首联；首联行的小状态仍是“待分配”。

## 拆分规则（`school_refresh_subject_lifecycle`）

主阶段按事实互斥：在读（期次结束日 ≥ 今天）→待续报；曾报名→已停课；完成测评→待报名；有效沟通／到访／邀约→待测评；其余→待首联。短期专题班算到访不算报名；“暑秋连报”秋季部分以 26 秋在读表为准。

| 主阶段 | 小状态 |
| --- | --- |
| 待首联 | 尚未联系、未接通、接通在忙·需回拨、已联系·结果未记、号码无效 |
| 待测评 | 沟通中·待邀约、暂无需求、已诺访、协调中／已约待测、未到待重约、到访过·未测评 |
| 待报名 | 测后未报（有等级）、已测评·等级未录；原生报名机会的考虑中／有意报名等沿用 |
| 待续报 | 在读、已连报下期、已报名·待入班；原生续报机会沿用 |
| 已停课 | 课程结束／未续报、已退课／停课 |

单次联系按备注语义判定（`.tmp/base-restructure-20261015/classify-lib.mjs`）。后来的未接通不抹掉早先的有效沟通；暂无需求取最近一次有效沟通。负责人不再作为小状态。
