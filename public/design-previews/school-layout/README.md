# 学校运营排布试用

2026-09-19 产品讨论原型。使用共同的虚构名单，比较可实际操作的排布。现有业务页面、权限和数据保持原状。

最新试排为 D：用户认为 A/B/C 都在拆分与重新分类，并提出直接归并学生和学服中的十个标签。D 按这一尚在讨论的方向，将相同工作的名单和操作放到共同入口；名称和合并范围仍供体验讨论。

## 入口

- [比较入口](http://192.168.5.213:3130/design-previews/school-layout/index.html)
- [D：十标签归并（当前默认）](http://192.168.5.213:3130/design-previews/school-layout/d-merged-work.html)：线索、首联、测评、报名与分班、在读与续班、停读回访六个工作入口；活动继续按场次组织。教师与学服进入同一组工作面，在读名单中同行处理课堂与续班。
- [A：对象集中](http://192.168.5.213:3130/design-previews/school-layout/a-objects.html)：学生、班级、活动是常用入口；分班提升为共同班级工作面，班级内切换组织安排、教学记录和续班。
- [B：业务分区](http://192.168.5.213:3130/design-previews/school-layout/b-business.html)：招生处理新客、测评和等班；教学处理班级与课次；续班是独立业务。学生档案用于跨业务查找。
- [C：工作清单](http://192.168.5.213:3130/design-previews/school-layout/c-worklists.html)：今天、在读班级、新客联系、测评、等班、寒假续班、周末公开课直接作为可进入的工作清单。

顶部“用同一件事比较”会将各方案定位到相同业务场景。四个文件与 `layout.css`、`layout.js` 放在同一目录，也可直接打开 HTML 使用。

## D 的归并范围

| 原标签内容 | 试排入口 |
| --- | --- |
| 学服线索 | 线索 |
| 学服首联＋学生待首联 | 首联 |
| 学服测评＋学生待测评 | 测评 |
| 学生待报名＋分班中的报名、等班 | 报名与分班 |
| 学生待续班＋学服续班＋分班中的常驻班级名单 | 在读与续班 |
| 学生已停读／课程结束 | 停读回访 |

分班原有内容按报名入班与日常在读分入相邻工作面。在读页同时纳入教师班级与教学工作台的日常记录，提供按班级／按学生排列和本课／续班待处理筛选。教师视角调整默认范围，工作入口保持一致。全局查人和姓名详情承担学生资料查询。

这是一种将十个标签归并为六个工作面的试排。它不预先决定正式菜单，也不改变实际报名确认、缴费或权限规则。

## 可体验的操作

- 展开班级，点学生查看记录、课程关系和本课登记。
- 将沈念、陆明哲、白可欣从等班安排至同年级、有余量的班级。
- 逐人登记寒假续班意向，筛选结果，保存后继续下一位。
- 登记本课出勤、课堂观察、公开课到场和家长反馈。
- 登记新客联系、完成测评，查看更新后的名单与完整历史。
- 切换学服、教师和负责人体验视角；教师班级视图默认显示李老师任教的班级。
- D 中确认方柚的示例报名、安排入班，再从在读名单展开同一行，分别或一起保存课堂与续班记录。
- D 中查询梁悦、江予川的过去课程，登记停读回访；可以在线索页安排负责人。

结果只保存在同源浏览器的 `mathin-school-layout-demo-v1` 存储项中。四个方案共用该示例存储；D 另附两位虚构的课程已结束学员。“重置示例”恢复虚构初始名单。存储不可用时，编辑仍在当前页面内有效。原型没有网络写入或业务 API 调用。

## 验证范围

首轮核对脚本语法、六个页面／资源的开发服务响应，并用 DOM 环境检查 A/B/C 导航、场景切换、入班、续班、课堂、活动、学生历史与关闭弹层的主要交互。D 增加合并入口、教师视角保持入口、同行分别保存教学与续班、报名入班接续、全局查人、负责人分配与停读回访检查。布局与使用直觉待产品负责人实际体验；这些检查不构成现有业务系统的运行验收。
