# 唯一生产管理员恢复手册

本手册用于 Mathin 1.0 只有一个生产管理员时的 MFA 丢失、凭据失效或账号误锁恢复。任何步骤都不得把密码、恢复码、访问令牌或 MFA secret 写入 Git、工单、聊天或 `production-admin-manifest.json`。

## 适用边界

- 只对清单中 `environment=production`、`admin.role=admin` 的唯一账号执行。
- 操作人和复核人必须是两名不同的实际人员；两人分别核对项目 ID、数据库 ID、Auth user ID、profile ID 和受控离线凭据封套编号。
- 先保存无 PII 的故障时间、请求来源和关联号。无法完成双人核验时停止，不创建第二个长期管理员。

## 恢复步骤

1. 从受控存储读取最新生产管理员清单，并运行 `pnpm r1:admin-manifest:check -- <path>`；校验失败立即停止。
2. 操作人与复核人分别通过既定线下渠道确认管理员本人身份，不接受仅凭邮件或即时消息的确认。
3. 检查账户是否被锁、Auth provider 是否 ban、现存会话数和 MFA 因子数；导出仅含 ID、状态、时间与关联号的诊断摘要。
4. 先撤销该用户全部现存会话，再解除误锁。若旧 MFA 已不可用，删除失效因子并生成一次性恢复链接；不得由支持人员替用户设置或保管新密码、TOTP secret。
5. 管理员本人完成密码更新、重新登记验证器并以 AAL2 登录。支持人员确认已验证因子数至少为 1，随后再次撤销恢复期间产生的其他会话。
6. 运行账户支持审计，确认 `session_revoke`、`restore`/`recovery_requested` 均有理由、结果和关联哈希；更新清单中的 `verifiedAt`、`lastTestedAt` 与审批人，但不得写入秘密。
7. 在受控证据库登记复核结果和 SHA-256；若发生越权迹象，立即进入事件响应并轮换 Supabase service-role、数据库和部署凭据。

## 失败与回退

- Auth provider 不可用：保持账号锁定，不直接修改 `auth.users`，转入平台恢复流程。
- 数据库与 Auth 状态不一致：停止对外开放管理员入口，保留审计，先恢复一致性再重新验证。
- 无法证明唯一管理员身份：不得发恢复链接或临时提权；由发布负责人启动独立的身份升级流程。
- 恢复后仍无 AAL2：管理员只能进入账户安全页，生产发布与支持操作继续保持关闭。

## 演练要求

每次 RC 发布前至少演练一次“撤销会话 → 恢复链接 → MFA 重登记 → AAL2 → 审计核对”，使用隔离环境和测试管理员。正式环境演练只在 R1-18 获得明确人工授权后执行。
