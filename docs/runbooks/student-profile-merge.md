# 学生档案合并

> 2026-09-09：合并功能已应用本机隔离开发库，待产品负责人交互与视觉验收。生产与阶段 Gate 保持原状态。

## 产品操作

打开学生档案侧栏或完整档案页，点击“合并档案”。按姓名、电话、家长、学校、负责人或完整档案编号寻找同一孩子的另一份档案；没有自动匹配结果时也能继续搜索。

核对两份资料的负责人、创建日期和档案编号，选择保留档案。姓名、年级、电话、家长、学校、微信、地区、来源、备注和学生状态可以逐项选择采用哪份值；保留档案缺失的字段默认采用另一份值。关联记录按业务类型显示数量。

填写确认两份资料属于同一孩子的依据，勾选身份核对后确认。成功后列表刷新；切换了保留档案时转到保留档案。合并记录展示操作者、时间、说明和原档案基本资料。

预览后资料或关联记录发生变化时，重新读取并核对预览。页面保留选择与说明，重新核对后继续。取消预览不会写入业务资料。

## 数据与权限

迁移为 `20260909000200_student_profile_merge_review.sql`，入口为 `preview_student_merge`、`confirm_student_merge`、`search_student_merge_candidates` 和 `get_student_merge_history`。

- 搜索、预览和确认均要求员工身份、`student.edit` 及两份学生档案的可访问范围。数据库独立检查，客户端隐藏入口不构成授权。
- 确认事务锁定两份档案和关联记录，校验预览版本。相同已完成请求返回原合并结果；冲突、过期版本和权限失败均回滚整笔事务。
- 两份档案绑定不同登录账号，或有重叠的正式报名、课次考勤、评估等唯一记录时，显示冲突并保留两边资料。完全相同的家庭、联系人和年级资料沿用保留档案的记录，原记录继续留存追溯。
- 待合入档案包含非零账户或财务记录时，操作者还需 `finance.account.adjust`。无该权限时预览隐藏金额并提示负责人处理。允许合并时累计账户余额与课时、保留账目行及原账户行。
- 沟通、活动、评估、报名、教学和待办等可变业务归入保留档案，操作人和业务内容保持原值。旧档案成为已合并的归档记录；整个合并事务不删除正式事实行。
- 原始导入凭据、冻结花名册和既有审计保持原样。导入记录的当前归属通过带版本的关联及关联事件更新；已定稿活动和评估仅在合并事务内允许身份归属调整，内容冻结约束继续生效。考勤保留原标记者与标记时间。
- 内部审计保存合并前后完整快照、字段选择、操作者、说明和事务编号。客户端直接读写审计表及调用内部合并证明函数的权限均关闭；公开历史接口只返回基本资料摘要。
- 关联表清单包含当前学生外键；新增模块有待合入记录但尚未定义合并规则时，提示专门核对。旧的两参数 `merge_students` 返回 `MERGE_PREVIEW_REQUIRED`，由新版预览确认入口办理。

共享目标检查器先核对主机、实际 Supabase origin、开发端口监听进程、Docker 上下文、网关和数据库指纹。

```powershell
node scripts/student-profile-merge.mjs --preflight
node --experimental-strip-types scripts/student-profile-merge.mjs --check
node --experimental-strip-types scripts/student-profile-merge.mjs --apply
$env:SUPABASE_META_DOCKER = 'supabase-meta'
node scripts/generate-database-types.mjs
node --experimental-strip-types scripts/verify-school-support-intake-merge.mjs <local-dev-url>
```

## 暂停与恢复

需要暂停功能时先关闭应用合并入口，保留新增审计与旧入口的预览保护。已完成合并的恢复须按具体合并编号核对前后快照、后续业务变化和原记录清单，再取得对应数据恢复授权；当前界面提供追溯，不提供自动撤销。恢复演练在隔离副本执行，正式资料按批准清单处理。
