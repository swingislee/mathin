## 旧表字段与本次业务范围

用户提供的 `.base` 文件为压缩表格快照。使用表格技能按只读方式提取 14 个字段和视图定义，未导出、导入或展示个人明细。

| 旧表字段 | 当前工作面 |
| --- | --- |
| 姓名、电话、年级 | 固定身份列，姓名进入既有学生 360 |
| 班级、授课教师 | 原班级与主授教师，分别筛选；负责人仍为独立业务归属 |
| 报名季节（寒、春、寒春连报） | 冬／春／夏／秋多选，寒春连报可同时选择冬和春 |
| 沟通方式（私下、家长会） | 单独沟通、家长会，并补充电话与微信 |
| 缴费时间、缴费金额、缴费方式 | 实际缴费日期、金额及支付方式；沿用现有报名期数 |
| 备注 | 常驻右栏家长关注点，和教师专业观察分别显式保存 |
| 校区、班型、父记录 | 沿用周期校区与实际班级／课程关系；父记录是旧表层级，不新增重复身份或关系 |

季节标签用于本次安排，保存仍只确认当前续报周期的目标课程与学期；多选不会生成其他学期的正式报名。已报名与已缴费分别呈现，旧缴费缺少日期／支付方式时显示未登记，补齐时填写真实事实。这里只登记线下实缴，不发起收款。

## 数据与保存

- Migration：`20260907000300_renewal_workbench_details`，规范化 SHA-256 为 `263c78e7df50f910da00ed26cea2c548e758e2fd3281bacc8643b401664c023f`。
- `renewal_workbench_details` 保存沟通方式、季节、缴费补充字段、版本和实际操作者；RLS 沿用对应商机的可见范围，客户端只读。
- `save_renewal_workbench_v1` 在同一事务校验周期、学生范围、跟进写权限和版本，复用既有报名／缴费记录流程。已报名／已缴费额外要求报名管理权限；保留现有报名及缴费事实的边界，不提供取消或退款能力。
- 尚无报名的意向保存不创建报名；“已报名”可确认报名而不虚构缴费，“已缴费”要求金额、期数、日期和方式。已缴费与不续报保存时清除当前下次联系；草稿切换结果期间保留先前输入。
- 页面摘要只反映已保存事实。未编辑草稿可接收服务器刷新；已编辑草稿保留原版本，冲突时保留内容并提示刷新核对。普通保存停留当前行，成功后“保存并下一位”才前进；首次保存将候选转为商机时保持同一行身份和当前名单。
- 历史记录通过原历史修订入口维护，本面板的当前续报与教师观察控件保持只读。教师观察独立提交，教师输入区的 `Ctrl/Cmd + Enter` 只保存观察；家长侧快捷键保存当前续报登记。

## 人工验收建议

1. 打开续报工作表，按班级／教师、季节、结果、支付方式或下次联系筛选，核对主行能否支持连续处理。
2. 展开一位学生，在三个阶段间切换，核对顶部标签和右栏位置；填关注点及下次联系，收起再展开检查草稿。
3. 在已登记的开发验收名单上分别确认意向、已报名与已缴费的业务含义，检查季节多选及实际缴费字段。普通保存核对停留原行，“保存并下一位”核对成功后前进。
4. 以教师账号核对学情与专业观察，以历史记录核对只读浏览和既有修订入口。布局、颜色、设备适配和真实操作体验以产品负责人本次验收为准。
