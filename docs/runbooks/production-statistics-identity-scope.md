# 正式统计中的人员用途与员工别称

人员分类与班级共用 `purpose = production | test`。`profiles`、`students`、`leads` 上的分类是持久业务元数据；姓名含“测试”的记录自动标为 `test`。学生同时显示既有“测试”标签，员工列表显示“测试”标记。改名保留用途；用途不改变账号角色、登录权限、花名册、课次和受保护对象清理规则。

正式统计使用 `statistics_*` 视图，保留原表 RLS 与来源权威规则。学生、关联线索、入班、考勤、报名和财务事实按同一身份分类排除；班级数使用班级用途，混合班只排除测试学生。负责正式业务的测试管理员仅作为录入人时，不把其录入的所有真实业务一并排除。

员工默认姓名保存在 `profiles.display_name`，已确认别称保存在同一账号的 `staff_aliases`。来源原文保留原署名；业务归属、统计和选择器匹配唯一在职账号。别称有多个候选时保留待核对状态。已确认别称再次导入时保持默认姓名，已有展示选择随别称映射到该账号。

## 导入与运维

1. 按写入目标保险丝核对环境。特殊身份按该环境内的 ID 确认；“最早登记”按 `created_at` 核对，同时间存在多个候选时先解决歧义。
2. 导入更新现有记录时保留 `purpose`、`staff_aliases`；员工匹配读取 `staff_aliases`，不要从文件名或快照日期重新推导人员身份。
3. 独立核对测试班：明确测试名称，或已确认测试负责人且全部已登记学员为测试。混合班继续作为正式班统计真实学员。
4. 生产变更先备份、事务回滚演练，再提交分类与别称。私人审计留在对应环境，公开证据只记录计数、状态和校验摘要。
5. 复核总览及下钻、班级列表人数、教学班级统计、领域概览与管理分析。统计排除不构成删除授权。

本地验证入口：`scripts/sql/production-statistics-identity-assertions.sql` 在回滚事务中运行；`MATHIN_STATISTICS_HTTP_TEST=1` 启用 `tests/production-statistics-http.test.ts`，只复用固定开发身份。
