# 更新源表交叉整理

当前批次以 `2026-09-07【思维】用户与产品运营表.base` 为业务主来源。魔法校的学生、班级、花名册和场地导出用于身份与目录比对；`员工管理.xlsx` 决定现有员工成员范围。子2工作簿与既有小地推导出提供历年报名、授课、获客和沟通的交叉依据。

本流程交付来源匹配预览。它读取原文件并在私有目录封存副本、生成结果，不连接 Supabase。后续业务批次沿用 [业务历史记录规则](business-record-history-state.md)，按目标库重新核对已有身份、来源映射和人工修订。

## 执行

入口为 `scripts/source-reconciliation.mjs`，匹配合同在 `scripts/lib/source-reconciliation.mjs`。

```powershell
node scripts/source-reconciliation.mjs --run .tmp/source-refresh/run-<新批次> --python <依赖运行时Python绝对路径>
```

`--source` 默认为 `docs/test_material`。`--previous-base` 可指定上一版封存的 `.base`；`--decisions` 可指定私有、带确认依据的员工别名 JSON。原始文件按相对路径封存，manifest 保存字节数和摘要。结果位于新建的 `analysis-<时间>/reconciliation.json`，批次内的 `latest-analysis.json` 指向最近结果。`--reuse` 复用同批次提取文件，仍核对原文件集合与原文件、封存副本的全部摘要。输入有变化时创建新批次。

本次 `.base` 与配套导出的文件名属于已验证输入合同。后续更换权威批次时，先核对文件与字段合同，再升级配方。原版本继续保留。

## 匹配规则

- 当前业务状态取飞书业务字段及其所属时期。秋季在读、待报名和未填写分别保留；魔法校的历史状态、无年级或旧班级状态只形成对照差异。
- 员工按当前名单分类。学科、学段、序号和待定占位名称排除真实员工导入。名单外的完整老师姓名作为历史署名；简称、渠道、活动与状态标签分别保留待核对。历史署名不生成当前员工账号。
- 同一名单姓名明确包含的中英文别名可唯一关联。其他别名要求私有决定中包含 `name`、`employeeId`、`confirmedBy` 与 `evidence`；占位目标和冲突别名拒绝关联。真实姓名与占位式联系方式分开处理。
- 魔法校学生 ID 是参考身份键。姓名与全部完整电话共同命中唯一 ID 时关联；同名、仅家庭电话、矛盾电话和重复候选保持待核对。姓名中的备注或疑似错别字保留原样。
- 秋季主表没有电话时，可使用完整姓名与当期班级花名册共同定位。班级须同时符合 2026 秋季、年级、校区、班型、老师、周次与时段。旧年度仍标为开课中的班级不用于此规则。
- 完整姓名与相同完整电话集合形成全来源联系组。多个来源位置仍保留各自业务事实；同一电话下的不同姓名保持独立。秋季表中的同名联系组仅提供候选电话，不自动认领身份。
- 横向名单逐姓名单元格拆分，保留所属班级块与原位置。记录数、姓名位置数和独立人数分别统计。
- 班级文件名中的来源 ID 用于关联花名册。空班文件即使字节完全相同，也按各自相对路径保留。班级汇总与明细逐行按多重集合对照，业务关联使用明细，避免把两份导出相加。
- 场地使用校区与教室名称组合定位。来源中的占位目录、占位教室和未填写教室单列核对；校区目录不生成组织、权限或班级作用域。
- 飞书修订按表 ID、记录 ID、字段 ID 对照。显示值更新与原始导出表示变化分别记录；本次未出现的旧记录继续保留在旧快照中。
