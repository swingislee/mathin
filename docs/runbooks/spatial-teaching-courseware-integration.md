## 开发端人工验收

1. 从现有正式课件或微课编辑页打开“插入工具组件”，分别选择展开图、骰子。
2. 在同一工作台配置起点，等待动作完成后插入。检查组件区域及编辑器句柄；不应出现额外名称框。
3. 保存并重新打开，检查折叠/剪棱、左右手系、点数、标色、透明度、移面和足迹。选中组件后使用“编辑教学起点”，分别检查应用和取消。
4. 发布后修改草稿，确认已发布预览保持原起点。从教学工作台进入试讲，或进入现有课次课堂；只有控制端可操作组件，展示端跟随。
5. 在同页放两个组件，分别试用折叠、三条剪棱后展开单面、11 种换图、移面、标色、透明度、骰子点数显隐、受控滚动及投骰；检查中间过程与最终结果。教师松手后不应重播拖动。
6. 动画中取消，检查两端都回到该动作前的稳定场景。动画中打开展示端、完成后刷新展示端，检查最终场景、面样式、题设及足迹一致。
7. 展开图右侧、骰子“复原”面板里的“恢复起点”恢复本组件课件起点。课堂动作不修改固定课件或个人草稿。

## 共用课堂接入层

- `tool-classroom.ts` 是按工具内容版本登记的严格状态合同入口。共用舞台、试讲、LiveShell/PublicClassRunShell、eventlog、liveState 只处理统一封套，不分支识别展开图或骰子。原立方体 v2 的事件格式与 origin hash 保持兼容。
- `useTeachingWorkbench` 统一处理持久动作接收、自己回执不重播、远端恢复、终态对齐、取消、恢复起点与写入失败。写入失败停止自动重试，下一次教师操作或恢复起点再尝试，避免动画重播循环。
- `workbench-classroom-contract.ts` 登记稳定 snapshot 与可重放语义 command。命令先写 outbox，再调用原工作台动作；动作完成后保存完整终态。相机自由拖动、纸片/骰子拖动预览和逐帧动画均不写入权威事件。
- 动画事件包含稳定起点、动作、开始时间；晚加入沿原算法定位到播放位置。终态事件带关联动作 ID，若早于展示端动画结束则等待原动作完成后对齐，避免瞬间截断。取消发无关联终态，立即停止远端动画。
- 投骰包含教师产生的随机种子和权威落定场景；各端用同一模拟入口重建表现，最终始终采用教师结果。物理表现加载失败时仍落到教师结果，不另抽点数。
- page/doc/instance/origin 隔离、教师单写者、512,000 字节封套预算、乱序幂等、持久 outbox 与晚加入重发沿用原通道。试讲保留内存隔离；事件通道就绪后才开放写入。本批无数据库、RLS、服务端 API 或生产配置变更。
- registry 的两个新版本已登记同步 provider；旧无状态工具和 H5 仍各自只读，不因为同页存在可写组件而开放。

## 后续新增工具的复用边界

新工具在自身模块提供版本化起点/状态 schema、语义动作执行和稳定状态导出，并在合同 registry 与 renderer 入口登记。交互仍由原组件实现，课堂共用宿主负责生命周期与同步；不再为每个工具改写课堂页面、事件存储或恢复链路。工具内容类型的服务端保存白名单仍需按既有课件合同登记，这与重写课堂适配不是同一件事。

独立工具页与 `ToolOverlay` 不自动成为权威课堂组件；本批入口是课件中的固定工具实例。`ToolOverlay` 的开关同步不能替代工具内部状态协议。
