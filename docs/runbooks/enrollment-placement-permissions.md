# 分班与调班权限

2026-09-10 产品决定：当前小团队中，任课老师可以处理涉及本人班级的分班及调班，后续人员扩大时再调整此规则。本变更已完成开发检查及独立授权的生产发布，实际教师操作待人工验收。

- 原班或目标班有一端是本人任课班级，即可完全调班、临时调班或取消这两班之间的临时安排。
- 待分班学生可以加入本人任课班级；本人班级的学生可以退回待分班。同班座位调整使用本人任课范围。
- 任课关系使用 `classroom_members.role = teacher`，包含系统同步的主讲和助教关系；账号应处于有效员工状态。
- 原有管理岗继续使用 `enrollment.manage` 和两端班级管理范围。老师的授权集中在调班函数，没有给教师岗位追加完整报名管理或班级管理权限。
- 商业报名确认、退课和来源历史修订继续使用对应权限。教师分班表提供选择转入、转出所需的当前班级、座位与学生姓名；档案、联系方式和历史资料继续服从既有学生读取范围。

数据库权威判断为 `mathin_internal.can_transfer_enrollment(from, to)`；函数内部从实际花名册、当前报名分配及临时课次解析真实两端。客户端下发的班级关系只用于拖拽反馈。改动任课判断时，同时更新前端 `canMovePlacement` 和下述权限矩阵测试。

开发验证入口：`node --experimental-strip-types scripts/teacher-enrollment-placement.mjs --preflight` → `--check` → `--apply`。工具核对本机主机、Supabase origin、监听进程、Docker 网络和数据库指纹；`--check` 回滚候选迁移与固定账号的测试业务记录，`--apply` 要求对应版本及断言已经通过。执行前保存在本机的函数定义及 ACL 用于检查回滚和还原；生产发布按生产 runbook 独立授权与核对。

定向覆盖：原班老师、目标班老师、无关老师、普通员工、学生、停用账号；未关联和已关联报名、待分班、临时调班与取消、幂等重试、伪造班级／报名参数；原有班额、冻结记录与历史保留合同。开发页面由产品负责人继续人工验收。

2026-09-10 开发验证：迁移已在隔离开发数据库应用；权限事务断言、业务数据不变、既有函数 ACL 保留和候选迁移回滚检查通过。相关前端／Action 测试、类型检查、生成类型摘要与 ESLint 通过。HTTP 检查确认管理员中英文分班页面可启动，学生及没有符合分班条件的任课关系的固定教师被正确拒绝；该固定教师仅关联测试班，老师授权页面的实际操作仍由产品负责人使用对应任课账号验收。生产发布单独进行。
