# 学生历史资料按业务拆分试导

> 状态：开发端已交付，待人工业务与视觉验收。范围为产品负责人指定的一个既有学生案例。
> 阶段入口仍为 doc 04 的 R1-Live-2；本增量不代表生产部署或阶段关闭。

## 业务结果

历史资料沿用现有 Student 身份。续费、活动参与、测评、报名、沟通分别增加结构化历史事实子表，由现有学生、续费和活动入口查询。来源文件和原始行用于展开追溯，业务页面读取领域列。

| 来源内容 | 历史业务记录 | 本案例数量 |
| --- | --- | --- |
| 暑秋续报行中的两个期别意向 | `student_renewal_history`，按暑季、秋季拆分；最终结果保持未记载 | 2 |
| 袋鼠报名与备考行 | `student_activity_history`，报名日期与实际举行日期分别保存 | 1 |
| 到访行中的测评等级、能力表现、家长情况 | `student_assessment_history`，保存原等级；缺失分数保持空值 | 1 |
| 报名行中的寒假和春季两组列 | `student_enrollment_history`，分别保存日期、原金额及当时班型、教师、课表信息 | 2 |
| 续报与到访中的沟通段落 | `student_communication_history`，保留完整文字，未知作者和沟通日期为空 | 2 |

续报沟通提到的竞赛成绩保存为活动结果线索，明确显示“沟通记载／届次待核对”。当前配方只提取明确陈述的奖项，不将意愿、否定语句、多个可能届次视为已确认成绩。

原报名金额作为历史资料保存。历史报名、续费意向和活动记录补充过去经历；当前在读、班级成员关系、工作清单、提醒、通知和财务仍由各自现行业务动作维护。

原始行中的身份属性差异、同名候选及多名学生共用的班级行保留待核对。此配方只接收已确切关联到指定 Student 的来源；源记录与历史事实的 `(source_record_id, student_id)` 复合外键防止跨学生误接。当前接收四种已识别来源，其他表按后续配方逐项补齐。

## 本机执行

复用 `.tmp/history-import-trial/family-*/plan.json` 中产品负责人指定的案例。以下工具只接受本机 WHITEHOUSE、loopback Supabase、已核对的监听进程、Docker 网络和数据库指纹；preflight 有效期一小时。原档案配方和来源摘要发生变化时停止执行。

```powershell
node scripts/student-business-history-trial.mjs --preflight
node scripts/student-business-history-trial.mjs --prepare --family=<已确认家庭目录的绝对路径>/plan.json
node scripts/student-business-history-trial.mjs --migrate
node scripts/student-business-history-trial.mjs --apply
```

`--migrate` 首先保存 schema 备份，再在事务中演练 schema、实际转换样本、角色访问和外键，确认 rollback 后无新增表残留才提交 schema。该命令只应用本次独立迁移，不重复执行已存在的 migration。

`--apply` 在一个事务内检查来源和导入摘要、写入领域事实、核对受保护表内容指纹，并保存批次验证结果。同一输入重试新增为零；同一记录标识的内容发生变化时停止，供显式制定更正规则。

私有计划、原文、数据库结果和页面 HTML 位于 `.tmp/student-business-history-trial/`，不进入 Git。本机开发数据库中的新增历史事实已由本次迁移接入真实 Supabase 查询；页面不读取 SQLite 作为业务数据源。

## 人工验收顺序

以本轮交付的指定学生链接为准；所有入口使用 `http://192.168.5.213:3130`，复用开发管理员。

1. 学生 → 历史记录：确认按业务分类能读懂经历。
2. 续费 → 历史续费：按学生搜索，核对两个期别的意向及未知的最终结果，展开相关沟通。
3. 活动 → 历史活动参与：核对报名事实、日期、沟通中的结果及届次待确认状态。
4. 学生 → 历史报名：核对两期各自的金额、日期和课表字段，避免跨列组借值。
5. 学生 → 历史测评、历史沟通：核对原等级、能力和家长情况、完整文字。
6. 展开来源依据及档案待核对区：检查是否有遗漏、错误合并或尚未确认的归属。

当前页面为管理员单案例验收切片，单类读取上限为 250 条，超过上限显式报错，不静默截断。扩大全量前增加按业务类型的服务端分页和更完整的配方覆盖，并明确历史资料岗位访问策略；当前导入能力不自动晋级为生产批量迁移。
