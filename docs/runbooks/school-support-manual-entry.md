# 学服工作表补入与资料修订

> 2026-09-08：开发端已交付，待人工交互与视觉验收。生产与阶段 Gate 保持原状态。

产品负责人确认五张学服工作表、现场测评／体验和老生报名／续班都有手工补入需求，并授权开始施工和热修补。本轮按本地开发目标实施。

## 可验收范围

- 首联、沟通、测评、报名、续报和学生页提供“补入学生”。检索权限内学生档案及未关联线索，展示年级、联系电话、家长、学校和负责人。相同电话的不同孩子分别呈现。
- 选中已有档案直接办理。新资料至少填写姓名或电话；缺项保持为空。确认是新学生时可以建档，也可以保存为待确认登记。
- 沟通补入接到持久工作单；现场测评可选择现有场次，或直接安排一对一测评。只有明确勾选实际到场才登记到场。
- 报名和续报接到课程机会；课程或身份未齐的事项保留在原工作表的待办行。补齐后使用既有登记表办理，确认报名后由正式记录继续流转，手工待办自动移出。
- 点击学生姓名打开共用档案侧栏，通过“资料与修订”编辑姓名、年级、电话、家长、学校、微信和备注。保存使用资料版本校验，记录修改前后值、操作者和时间。并发冲突后保留草稿，重新读取后显示最新资料与草稿差异。
- 待确认登记可关联到已有学生，或明确确认为新学生。原参与记录、课程机会和办理事项沿用既有身份重挂逻辑；两边已有同轮待办时返回关联冲突，保留原记录供核对。
- 当前业务记录和导入历史的更正继续使用工作表原有的业务修订入口。已关联正式身份的调整继续沿用既有身份变更流程。

补入只保存资料与当前安排。首联、邀约结果、付款和正式报名由各自实际登记产生。原始导入凭据保持不变。

## 数据与权限

迁移：`20260908160000_school_support_manual_entry.sql`。

`leads` 新增手工登记与身份待确认标记；只为手工登记扩展缺项合同。新增 `school_support_work_items` 保存尚待办理的事项，`school_support_entry_receipts` 防止同一请求重复写入，`school_support_change_log` 保存修订轨迹。

写入函数逐一检查功能权限、主体范围、资料版本和业务状态。客户端不能直接写新表。普通首联的成功沟通后建档行为保持原合同；未确认的手工身份先保留待核对状态。

数据库类型由本地 pg-meta 重新生成。生成结果同时补齐了此前已存在但类型文件尚未收录的业务视图和函数；其实现没有在本轮修改。

## 本地验证与应用

执行前由共享目标检查器核对执行主机、Supabase origin、开发端口监听进程、Docker 上下文、网关绑定和数据库指纹。

```powershell
node scripts/school-support-manual-entry.mjs --preflight
node --experimental-strip-types scripts/school-support-manual-entry.mjs --check
node --experimental-strip-types scripts/school-support-manual-entry.mjs --apply
$env:SUPABASE_META_DOCKER = 'supabase-meta'
node scripts/generate-database-types.mjs
node --experimental-strip-types scripts/verify-school-support-manual-entry.mjs <local-dev-url>
```

`--check` 在事务内执行迁移与合同断言，随后整体回滚；验证现有业务表内容及原函数权限未变。`--apply` 要求匹配的迁移、断言校验和与账本位置，再在事务内应用。测试数据始终回滚。

本地受控日志保留于 `.tmp/school-support-manual-entry/`，账号与会话信息不进入日志或提交。

## 人工验收重点

1. 在每张工作表搜索已存在的孩子，核对同电话的多个候选并补入。
2. 用缺电话的姓名登记临时到场，或先保存缺课期的老生续报；刷新后从待办继续，核对保存后的定位与展开体验。
3. 从档案侧栏更正资料，检查列表、侧栏和修订记录；并发编辑时核对冲突提示与草稿保留。
4. 确认身份后继续报名，检查原参与和办理记录，以及正式登记后的名单归属。

若需暂停该入口，先回退应用入口变更并保留新增资料与审计表，再按具体问题修复。已发生业务写入后，保留身份、报名和历史凭据，按对应领域流程处理更正。
