# Base 业务事实与当前工作范围

本轮迁移以 `2026-09-07【思维】用户与产品运营表.base` 为当前业务核对主表。学生列表、班级明细和其他 Excel 仅用于身份、班级等交叉核对。参考表中的“潜在”“历史”或报名行不单独构成待首联、报名或续报事实。2026-09-08 用户补充确认：资料先保存，关联采用现有证据下最可能的结果；疑点通过徽章提示，老师实际办理到该学生时再核对或修改。

## 整理规则

- `business_*` 业务视图读取 Base 导入事实和系统内实际新登记的业务。参考表保留在原始来源档案，不参加业务阶段推导。
- 仅由参考导入建立、没有 Base 或系统内新业务依据的身份，使用 `reference_only` 范围记录退出当前工作队列。身份本身与关联历史保留。
- 当前主表的秋季在读／待报记录、本月及后续业务、系统内实际新增业务、明确开放提醒和邀请继续保留。秋季名单中的正式在班身份同时保留；仅姓名相同的其他历史 Lead 独立核对。
- 先前按期次线索生成的 `history_review_required` 和 `processed_prior_period` 属于推定范围，界面显示为“暂按历史 · 待核对”，保留查询入口、数量及来源期次。老师实际办理时可恢复办理或修正为历史；这些资料已保存，不形成导入前置审批队列。
- 同一步骤有明确年份时，月份标签沿用该年份。月份只用于资料归期，原始日期、日期精度、结果、金额和报名状态保持真实。
- 同一来源行可以包含本月沟通与旧月到访。`history_business_workflow_scopes` 对旧业务事实单独限定范围；本月沟通不会把以前的报名或测评恢复成当前待办。
- 工作表默认显示“当前工作”，可主动切换“历史记录”或“全部记录”。阶段判断使用当前联系、测评和报名，正式在班关系按有效学期判断；学生 360 与历史统计继续保留完整经历。
- 新登记的当前联系、跟进、活动、报名或明确提醒可恢复该人的当前工作范围。历史修订、带来源的导入、补录旧日期的沟通和自动初始联系提醒保留原范围；历史记录通过修订接口更正，当前办理接口检查业务范围。
- 报名归类接受原资料缺少学期 ID 的记录。未关联学生的报名仅沿同一来源行的唯一明确业务主体识别；有冲突时保留待核实。

## 本机执行

第一次整理的规则位于 `scripts/lib/base-workflow-scope.mjs`；本次复审使用 `scripts/lib/current-workflow-review.mjs`。输入包含只读学生阶段快照、导入批次／行、实际账户绑定与待办，输出私有范围清单；清单保存原始 Base SHA-256、写前业务表指纹与既有范围指纹。明细保留在 gitignored `.tmp`。

`scripts/reconcile-base-workflow.mjs --mode apply --plan <私有清单>` 每次核对本机主机、实际 Supabase origin、监听进程、Docker 网络和数据库标识后，核对清单及来源指纹，再应用范围元数据和版本化读取规则。已应用批次拒绝重复写入。当前用户授权直接应用，不运行事务演练或回滚验证。

复审清单使用 `scripts/reconcile-current-workflow.mjs --plan <私有清单>`，复用同一本机目标核对，应用 `20260908006000_current_business_workflow_boundary`。事务内核对 26 张原始业务表不变，只更新范围元数据与读取／办理规则。

2026-09-08 本机复审已应用：760 个主体进入历史核对范围，当前主体从 1,111 收敛为 351；当前阶段为待首联 165、待测评 14、待报名 9、待续报 163。本期秋季在读报名 155 条继续保留。上述数量是本次机器核对结果，业务和视觉仍待人工验收。

本次定向检查覆盖范围规则、首联占位、测评和分班显示、筛选交互、历史反馈及首页待办；固定身份读取核对了五个阶段、业务工作表、历史查询／管理员修订、教师及学生权限。中英文学生和测评页面、本机分班及首页启动通过。全库类型检查仍有 `autumn-identity-review.test.ts`、`source-reconciliation.test.ts` 的既有错误；页脚测试仍有两处既有尺寸断言与当前组件不一致。本轮未关闭正式 Gate。

`--mode verify` 用于应用后、继续登记业务及账号登录前的只读原表指纹与范围检查。开始人工操作后，旧指纹不再代表当前预期输入。`scripts/verify-base-workflow.mjs` 复用固定开发身份检查 API、关联读取、权限及页面启动；登录只产生正常认证活动，不登记业务事实。

开发端交付入口为 `http://192.168.5.213:3130/zh/dashboard/students?scope=all`。机器检查与页面可启动分别记录，视觉和业务意图由产品负责人验收。

## 学习资料与推定关联

- 学员列表统一显示“学服”；待测评沿原确认人员映射，待报名沿来源学服映射。从待报名起增加“老师”，优先采用来源学科老师，正式在班学生采用实际任课老师。来源署名可以保留为文本，不自动授予账号或权限。
- 明确的原测评等级“未达A”映射为 X+；原始测评备注和来源原文继续保留。学习力的同名等级也以 X+ 展示，推荐班型或备考成绩不补造正式测评。
- 学习背景读取已关联的完整历史测评，办理阶段仍沿原始业务来源保持连续。缺少真实完成测评时，待续班显示实际“班型参考”，同时保留其参考属性。
- `scripts/lib/student-learning-inference.mjs` 按电话、姓名、唯一姓名、已在班身份及既有候选排序。保存最可能的归属，电话缺少佐证、同名或分数并列等情况保留疑点；已有关联和明确身份继续优先。
- 推定结果使用 `history_import_associations.match_state='inferred'`、`match_reason` 与追加审计事件保存，系统推定的确认人为空。真实业务资料沿现有来源关联机制接入学生；正式学生身份、班级、花名册和来源档案保留。
- “资料待核对”链接到学生来源资料；已保存的推定资料可以直接用于办理。“核对／修改”按需打开原文和学生选择，版本核对后保存人工修订。已被正式报告或分班使用的跨学生变更继续执行既有保护规则。
- 本机执行入口为 `scripts/reconcile-student-learning.mjs --plan <私有清单>`，复用本机目标核对、版本化迁移和重复执行保护。本次保存 285 条推定关联（137 条测评来源、148 条秋季在读来源），45 条明确的原测评等级归一为 X+。机器检查覆盖推定规则、直接办理与按需修改、权限边界和页面启动；产品人工验收仍待完成。

## 2026-09-08 学员页超时修复

后续用户验收发现学员页超时：页面为全阶段字段筛选请求每批 100 条，旧读取逐人重复汇总报名关联，实测约 16 秒；此前 HTTP 200 检查漏掉了流式页面中的服务端错误，不能作为该页已恢复的依据。

本机已应用 `20260908006100_student_stage_batch_enrollments`：每批汇总一次当前报名，单人及批量接口复用同一字段计算。内部批量函数只向数据库维护角色开放，人员访问范围、历史隔离与原 100 条返回内容核对一致。固定校长、教师的 100 条读取约 0.75–0.80 秒，学生仍被拒绝。中英文及待续报页面实际表格渲染通过；检查脚本现覆盖 100 条调用、页面内超时信息及学员表标记。

## 2026-09-08 学习资料读取性能修复

补充学习资料后，用户反馈待续班初次加载慢。固定开发账号两次读取的首字节约 0.3–0.4 秒，表格到达约 10.8–11.1 秒，说明等待主要发生在服务端数据阶段。开发日志另有 16–28 秒的重新编译记录，会进一步放大冷启动与热更新时的首次等待。

页面为保持全阶段列筛选与筛选项统计，先取得全部 163 条资料，再返回一页；两批请求先后执行。执行计划显示每位学员分别重新读取预约、当前测评、历史测评与候选，业务范围判断在较大的输入集上反复运行；阶段统计还重复读取报名关系。新增的历史资料计数此前也串在主表读取之前。

`20260908007100_student_stage_relation_lookup` 先沿学员及来源编号确定相关记录，再使用原业务视图进行范围判断；阶段计算复用本次报名集合，来源线索的两条关联路径改为可直接连接的集合。页面同时发起历史计数和主表读取。字段、历史依据、阶段、排序、分页与权限合同保持原样，没有增加跨请求缓存。

本机应用时，管理员和教师共 13 页、476 条完整返回记录前后相同；100 条待续班 RPC 复测约 2.15 秒。真实页面表格到达复测为 4.45 秒和 3.64 秒，未发现流式页面错误。ESLint 与迁移文本检查通过。本次测量包含开发环境开销，不代表生产环境或浏览器端交互验收；开发模式重新编译仍可能增加首次等待。
