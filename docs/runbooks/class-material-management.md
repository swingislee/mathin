# 班级教材与班型规则

## 管理入口

- 课程管理 → **班型对应规则**：按课程系列、业务班型、开班学年/季节、起始年级维护默认教材难度。
- 班级详情 → 设置 → **教材与难度**：保存业务班型、开班批次和实际教材；预览课次影响后填写原因并保存。
- 新建班级选择课程后填写班型与开班批次，可明确采用匹配规则。
- 原班教材设置中的 **沿用此设置新建班级** 保留原始批次与规则版本。新班仍选择实际年级、季节和教材版本。

开班学年使用学年起始年；季节顺序为暑期、秋季、寒假、春季。例如 2025 学年的春季可以发生在 2026 日历年。当前年级、教材版次和导入时间均不作为开班批次。

## 已确认的初始对应

- E 系列 A 班采用 A 教材。
- 2026 学年暑期以前的 E 系列 A+ 班采用 B 教材。
- 2026 学年暑期、秋季从一年级新开的 E 系列 A+ 班采用 A 教材，后续升年级仍按原开班批次匹配。

初始规则作为数据保存；迁移不推断或修改既有班级配置。其他批次可以新增规则或逐班手动选择。

## 保存与保护

规则每次保存生成新版本，旧版本保留。已采用旧版本的班级保持实际教材；采用新版本需要管理员明确选择。相同系列、班型、年级和开班范围的启用规则重叠时会提示调整。

班级实际教材切换限定为相同年级、季节与用途。课次按课程讲次编号匹配，预览明确列出结果：

| 情况 | 默认处理 |
| --- | --- |
| 未开课、没有备课资料 | 切换到目标教材对应课次 |
| 已开始、结束、冻结、取消/作废或已有学习/考勤/反馈记录 | 保留课次原教材 |
| 单课独立选材、微课或自定义课件 | 保留独立内容 |
| 已备妥、固定来源或进入待审/通过审核 | 保留原教材 |
| 未提交的备课草稿 | 默认保留；可明确勾选后切换 |
| 目标教材缺少对应讲次 | 提示补齐；本次保存整体不执行 |

切换保留教案、批注、解题、学习检查、审核、招生报名与冻结记录。旧页面批注仍属于旧教材页面，切换草稿课次后需要老师按新教材核对。班级默认教材与被保留课次的实际教材可以不同。

预览令牌包含班级、教材、设置版本和课次依赖快照；保存时加锁并重新检查，数据发生变化后要求重新预览。教材、设置、变更记录和审计事件在同一事务提交。

花名册导入保留业务班型与既有班级匹配。E 系列 A+ 新建班的教材难度由管理员从目录实际选项中明确选择，避免从当前年级推断新老批次。

## 权限与验证

- 全局规则写入需要 course.manage。
- 班级配置和影响预览需要 class.manage 且满足班级 scope。
- 新建班级需要 class.create，沿用原班设置还需原班管理 scope。
- 新表开放受 RLS 约束的读取，应用身份通过 RPC 写入。

本机命令由 scripts/class-material-local.mjs 执行：

1. preflight：核对 Windows 主机、loopback origin、监听进程、Docker 网络及数据库指纹。
2. check：在事务中运行新增迁移及固定开发身份断言，结束后回滚并核对。
3. apply：要求与成功检查完全相同的迁移和断言校验和，仅安装本机新增结构与初始规则。
4. types：从已安装的本机数据库生成本功能类型，复用共享工具合并指定成员。

验证结果只证明覆盖的合同。开发页面的视觉、交互和业务验收由产品负责人完成；生产迁移与发布另按生产授权和 runbook 执行。
