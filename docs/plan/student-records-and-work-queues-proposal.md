# 统一客户资料与日常工作安排：现状分析及方案

> **规划状态**：`reference`
>
> **用途**：回应 2026-09-08 产品负责人关于 8,809 项资料混合、逐条核对不可执行、资料隔离和当前业务节奏的反馈。
>
> **交付状态**：统一档案、本轮工作与再联系工作单已实现并交付开发端，待人工视觉与业务验收。原始分析快照保留在下文；实施与验证见[统一档案与联系工作安排](../runbooks/unified-student-records.md)。尚未创建真实试行批次；不改变生产、R1-Live 阶段与 Gate。

建议取消“历史数据池”作为客户的业务归属。客户及其所有经历保持统一，日常工作量由实际跟进安排控制，旧线索通过有明确目的的工作单再次联系。日期说明记录何时发生，不直接证明客户是否值得经营。

当前 8,809 项没有人工决定记录。复核列表直接拼接人员范围条目和来源行，按内部键排序，没有形成一次可执行的联系工作。普通学员阶段检索仍先应用当前范围条件，因此隔离影响了查找和阶段读取，不能只靠更改“历史”文案解决。

数量依据：本轮私有开发库快照及聚合结果。手机号仅用于联系去重统计，不作为合并学生身份的唯一依据。源记录内容复用了上一批已保存快照，本轮核对的 4,988 个来源 ID 均存在其中。没有将备注关键词解释为真实的未来约定。

## 2. 需要分开的四件事

| 对象 | 系统负责保存和表达 | 对日常工作的影响 |
| --- | --- | --- |
| 客户档案 | 学生、家庭、联系方式、当前服务关系、原始来源与全部经历 | 权限内始终能找到，不需要先“恢复历史”才能查看 |
| 业务事实 | 沟通、测评、报名、在读、退课；保留发生日期和原文 | 解释此人的情况；旧测评仍可作为学习背景 |
| 本轮工作 | 为什么联系、谁负责、计划时间、下一步动作、完成情况 | 决定是否进入本轮工作单或今日工作 |
| 数据疑点 | 关联把握不足、联系方式冲突、结果矛盾、影响当前办理的缺项 | 对应字段显示徽章，办理时修正；记录较旧本身不代表存疑 |

前一版把资料年代、客户状态、待办范围和资料质量合并成“当前／历史”，再让老师逐条决定，扩大了人工工作量。应把日期范围用于查看与分析，把执行范围交给工作安排。

## 3. 产品上的具体行为

1. **统一检索和档案。** 同一入口按姓名、电话查找权限内全部客户；打开后读取完整关联经历。学生与线索的推定关联保留依据和可更正关系，同电话多子女保留各自身份。
2. **日常工作台保留本轮范围。** 已安排的首联、预约、反馈、报名跟进、在读服务和本轮续班继续工作。没有安排的资料不会因为刚导入就产生逾期，也不批量进入今天的电话名单。
3. **阶段与本轮安排独立。** 去年完成测评的客户仍有测评事实；尚未纳入本轮联系，不代表需要重新首联或重新测评。客户再次沟通时创建本次记录，已有经历保持连续。曾就读后结束课程，应表达真实的停读／课程结束情况，而不是将整个人移入“历史数据”。
4. **再联系是有目的的工作。** 系统从全部客户中生成按人组织的建议，展示上次联系、真实结果、已有测评、当前课程、建议理由和疑点。选定一批及负责人、计划日期后，形成可跨天继续的工作单；每个客户无需先逐条确认导入。
5. **按需核对。** 老师办理时可直接记录沟通。疑点落在关联、号码、学情等具体位置，修正保留来源和审计。未影响本次工作的缺项不要求提前补齐。
6. **非客户资料由后台分类。** 目标拆解、内容素材、日报和空结构行保留在导入来源中供追溯，不形成客户待办。取消面向老师的 8,809 项核对总数与逐条恢复流程。

## 4. 再联系建议的生成

建议分组具有可解释的业务依据，而不是把所有旧客户按日期排序：

| 分组 | 建议依据 | 使用方式 |
| --- | --- | --- |
| 明确需要接续 | 已记录约定、家长新回复、明确待处理的本轮安排 | 进入对应负责人的安排；无法确认是否仍未完成的旧约定先作建议，避免制造历史逾期 |
| 曾未接通 | 有可用格式号码，最近一次实际结果为未接通 | 按最近联系、尝试次数、当前业务关系和联系间隔排序，分批重拨 |
| 已测评、尚无报名依据 | 有完成测评及家长诉求，与当前产品可能匹配 | 根据已知情况接续沟通，缺少报名证据时保留不确定性 |
| 曾就读、目前没有在读课程 | 原课程和学习经历可用 | 围绕合适课程、年级衔接或活动组织再次联系 |
| 长期未联系、资料不足 | 有联系人但缺少可信的近期进展 | 保留可检索性，按运营活动按需选入小批次，不自动制造未完成任务 |

当前在读或已有开放跟进安排的客户，优先接续现有工作，避免重复分配。明确要求不再联系、号码失效、近期刚处理的对象从通用重拨建议中避让；证据不足时提示而不推断“已经同意联系”。同一联系电话在同一轮默认避免重复拨打，沟通内容关联到对应孩子。

“暂缓”“这次不报”“某次未到”都保留所属业务轮次，不能永久覆盖这个人的后续机会。导入时间和实际发生时间分开保存；未知日期保留未知精度。

## 5. 实施顺序与既有能力

**第一步：统一资料可见性，稳定当前工作。** 保留当前 351 条办理范围作为接续基线，移除老师侧的超大复核入口。全档案搜索及学生详情覆盖过去事实，当前工作范围显式展示。原始业务日期、记录内容及正式身份关系保持可追溯。

**第二步：将工作范围接入现有安排。** 复用 `communication_worklists`、沟通日期视图和 `lead_next_actions`。明确工作单成员、负责人、本轮目的、计划日期及下一步。阶段标签提供背景，进入日常工作由本轮安排决定。这里调整读取和任务组织，不把旧业务记录批量改为当前、复制成新报名或重算欠费。

**第三步：试行一批再联系。** 可先从最近一次未接通且有号码的线索里，结合当前服务、重复联系、明确拒绝和资料疑点筛选，建议先选 20 个联系人形成工作单，验证接通率、有效需求、重复资料和老师实际耗时后，再调整排序与批量规模。20 是试行建议，不是已经创建或固定的业务规则。

- [沟通工作台读取](../../src/features/school/communication-workbench-data.ts)：已有工作单成员顺序与日期范围加载。

- [当前阶段读取](../../supabase/migrations/20260908006600_student_stage_source_key_context.sql)：目前人员检索先应用当前范围。

## 6. 业务验收场景

- 搜索一个上月未接通的客户，能直接看到原记录，并开始本次沟通，无需先恢复历史或补齐所有资料。
- 打开在读学生，看到去年和本年的测评；新导入旧月份资料后，在读状态和当前续班工作保持连续。
- 导入一批资料后，今日待办和逾期数量不因来源行数自动增加。
- 同一客户来自获客、到访、测评和续报四张表，工作单按本次工作去重，完整保留四份来源。
- 选定一批客户及计划日期后，只有该批形成新的工作安排；其余客户仍能在统一档案中查到。
- 老师修正一个存疑关联后，后续读取采用修正结果，原文和修订依据仍可追溯。

以上场景留待产品负责人在开发页面验收。实现提供统一读取与明确安排入口，试行对象、负责人及日期由实际办理人员选择。
