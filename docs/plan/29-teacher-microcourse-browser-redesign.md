## 一、文档目的

当前教师微课课程族页面经历了“课程卡片目录”和“年级 × 学期覆盖矩阵”两种方案。两者都难以承载教师自建课程长期增长后的实际使用方式：

- 一门课程可以跨多个年级、学期、班型和使用场景；
- 同名课程由不同教师形成不同维护方向，但仍属于同一门课程；
- 老师日常浏览只需要看到当前默认版本，维护分支和历史提交属于按需进入的二级信息；
- 课程数量持续增长后，图谱、卡片墙和固定二维矩阵都会迅速失去可读性；
- 学科运营负责解释“为什么、什么时候需要某类课程”，课程板块负责承载“具体课程内容、当前版本和历史维护”。

本次重构将教师微课页改为一个可扩展的**课程浏览工作台**：

```text
左侧：可切换的虚拟目录／使用场景树
中间：高密度课程表格，每门课程一行
右侧：当前默认版本的快速预览
下钻：完整课程内容、维护分支、提交历史与默认版本管理
```

页面优先服务老师的高频路径：

```text
我接下来需要做一类课程
        ↓
进入对应使用场景
        ↓
快速浏览已有课程
        ↓
查看当前默认版本
        ↓
直接使用 / 创建自己的维护方向 / 新建课程
```

# 二、已经确认的产品决策

## 2.1 学科运营与课程板块分工

### 学科运营

负责：

- 全年固定事项和临时项目；
- 时间节点、准备期和里程碑；
- 项目要求、负责人和整体交付；
- 从事项中发起、引用或复用课程。

### 教师微课课程板块

负责：

- 课程实体；
- 当前默认版本；
- 课节、教学目标与课件内容；
- 课程适用范围；
- 同名课程下的教师维护方向；
- 提交历史与版本检索；
- 被多个运营事项、班级和场景复用。

学科运营事项可以打开教师微课工作台并携带上下文，但课程实体保持独立，可以被多个事项重复调用。

---

## 2.2 同一课程可以出现在多个虚拟目录

课程只保留一个权威实体。目录节点只承担索引关系。

例如《图形计数公开课》可以同时出现在：

- 公开课；
- 趣味活动；
- 三至四年级；
- 暑期、秋季；
- 贯通体系；
- 某次学科运营事项的历史使用记录。

无论从哪个入口进入，打开的都是同一课程和同一当前默认版本。

课程与使用场景之间为多对多关系，不设置主场景。

---

## 2.3 主页面采用“目录 + 表格 + 右侧预览”

主页面采用高密度连续浏览工作台：

- 不使用课程卡片墙；
- 不使用课程关系星图；
- 不使用年级 × 学期覆盖矩阵；
- 不在首页展示 Git 图、分支图或完整提交历史；
- 每门课程在表格中占一行；
- 右侧只展示当前默认版本；
- 历史版本和维护方向在课程内部按需打开。

课程表格的核心列固定为：

| 课程名称 | 年级／学段 | 学期 | 适用班型／体系 |
| --- | --- | --- | --- |

进入具体使用场景后，表格不再重复显示场景列。

---

## 2.4 默认浏览方式为“使用场景”

教师第一次进入时默认按使用场景浏览。

后续允许切换虚拟目录，例如：

- 使用场景；
- 年级／学段；
- 学期；
- 班型体系；
- 全部课程。

系统记住每位员工最近使用的浏览方式和最近打开的目录节点。共享 URL 中明确指定的目录和课程优先于个人记忆。

---

## 2.5 同名课程归为同一个课程实体

课程名称是一级身份，老师姓名是二级维护关系。

```text
《图形计数公开课》
├── 王老师维护方向
├── 李老师维护方向
└── 教研共建维护方向
```

创建课程时发现同名课程，默认进入已有课程并提供：

- 查看当前默认版本；
- 基于默认版本创建自己的维护方向；
- 加入已有维护方向；
- 查看历史版本。

课程维护人从已经提交并满足发布要求的版本中指定当前默认展示版本。

老师日常浏览只看到当前默认版本；维护方向和历史提交在“维护与历史”中展开。

---

## 2.6 课程创建不预设课次数量

运营事项可以提供说明和历史经验，但课程创建过程不自动生成固定讲次。

创建课程时只要求完成课程身份和适用范围；老师进入课程后按实际需要新增课节。

# 三、使用场景体系：766 锚点 + 可配置场景树

一级目录名称从机构 766 教学体系的 19 个子项中选择。

### 七步教学

1. 进门考
2. 授新课
3. 随堂练
4. 理结构
5. 出门测
6. 讲明白
7. 作业练

### 六项护航

8. 计算天天练
9. 习惯周周练
10. 月清课
11. 思维天天练
12. 思维拓展练
13. 升班活动

### 六项保障

14. 课堂表现集
15. 答题集
16. 成长档案
17. 课后沟通
18. 体系规划
19. 阶段会谈

每个学科可以启用其中若干项作为一级锚点，并独立设置顺序。

一级锚点使用稳定代码，中文名称来自机构 766 配置或系统内置翻译。启用、停用和排序由该学科主管及以上权限完成。

---

## 3.2 二级及下级使用场景

一级锚点下展开可编辑的具体使用场景，例如：

```text
授新课
├── 公开课
├── 暑期收心课
├── 知识点专项课
└── 竞赛备赛课

月清课
├── E 系列阶段复习
├── 外部期中专题复习
└── 外部期末专题复习

思维拓展练
├── 趣味游戏课
├── 数独系列
└── 竞赛思维专题
```

以上仅作为首轮示例种子，不写死为业务规则。管理员可以在网页端轻松调整。

数据层使用 `parent_id` 支持树形关系；第一版界面以“766 一级锚点 + 一至两级场景节点”为主要使用深度，避免长期形成过深目录。

---

## 3.3 场景配置交互

新增学科使用场景配置页，支持：

1. 从 19 个 766 子项中多选启用一级锚点；
2. 对已启用锚点拖拽排序；
3. 展开锚点，新增、重命名、归档具体场景；
4. 对多个场景进行多选；
5. 拖拽单个或多个场景调整顺序；
6. 将场景拖动到另一个 766 锚点下；
7. 展示每个场景关联的课程数量；
8. 已有关联课程的场景使用“归档”而非物理删除；
9. 所有修改写入审计记录。

管理员首次进入时可以：

- 使用示例场景；
- 从空白开始；
- 批量选择 766 锚点后再配置子场景。

# 四、机构学术维度配置

教师微课的适用范围由机构配置驱动，不在课程组件中写死。

## 4.1 年级与学段

机构设置维护：

- 年级列表；
- 年级显示名称；
- 年级排序；
- 学段分组及成员年级。

课程适用范围以具体年级为权威数据。创建和编辑时可以提供“低段／中段／高段”等快捷多选，最终展开为年级集合保存。

表格展示时：

- 精确匹配某一学段的年级集合，可以概括显示学段；
- 其他组合显示具体年级；
- 该维度零选择显示“通用”。

---

## 4.2 学期

机构设置维护学期列表和顺序，首轮默认：

- 暑期；
- 秋季；
- 寒假；
- 春季。

课程可以多选学期。

零选择表示该维度通用。

---

## 4.3 班型体系与具体班型

机构设置维护班型体系和具体班型。

首轮默认配置：

```text
贯通体系
├── X+
└── G+

培优体系
├── A+
└── S

创新体系
└── C
```

课程适用范围允许直接选择：

- 整个班型体系；
- 一个或多个具体班型；
- 多个体系和班型的组合。

选择整个体系时保存体系引用，而不是把当前子班型展开为静态列表。机构以后在该体系下新增班型，课程自动适用于新班型。

选择具体班型时保存叶子引用，机构新增同体系班型不会自动扩展该课程范围。

同一条范围中如果已经选择整个体系，界面隐藏或禁用该体系下的重复叶子选择。

零选择表示所有班型通用。

---

## 4.4 通用语义

年级、学期、班型三个维度分别独立判断：

```text
某一维零选择 = 该维度通用
```

示例：

```text
年级：一年级
学期：暑期、秋季
班型：未选择
```

表格显示：

```text
一年级 | 暑、秋 | 通用
```

通用是显式业务语义，页面、RPC 和筛选均不得把它处理成缺失数据。

# 五、课程浏览工作台

## 5.1 页面整体结构

宽屏布局：

```text
┌──────────────┬──────────────────────────────┬────────────────────────┐
│ 虚拟目录树   │ 课程表格                     │ 当前默认版本快速预览   │
│              │                              │                        │
│ 使用场景     │ 名称  年级  学期  班型       │ 课程名称               │
│ ├ 766锚点    │ ─────────────────────────── │ 当前版本               │
│ │ ├ 场景     │ 课程A                         │ 课节目录               │
│ │ └ 场景     │ 课程B                         │ 教学目标               │
│ └ 766锚点    │ 课程C                         │ 少量缩略预览           │
│              │                              │                        │
│ 全部课程     │                              │ 打开课程               │
│ 未归类       │                              │ 维护与历史             │
└──────────────┴──────────────────────────────┴────────────────────────┘
```

建议宽度：

- 左侧目录：`14rem–18rem`；
- 中间表格：自适应主区域；
- 右侧预览：`26rem–34rem`；
- 右侧预览在桌面端保持 sticky；
- 页面主体保持无横向滚动。

响应式：

- 超宽与普通桌面：三栏；
- 中等宽度：目录可收起，保留表格与预览；
- 窄屏：表格占满，点击课程后用抽屉显示预览；
- 移动端不压缩成横向宽表。

---

## 5.2 虚拟目录

浏览方式至少包含：

1. 使用场景；
2. 年级／学段；
3. 学期；
4. 班型体系；
5. 全部课程。

第一次进入默认“使用场景”。

每个目录节点展示去重后的课程数量。

### 使用场景模式

```text
全部课程
未归类

授新课
├── 公开课
├── 暑期收心课
└── 知识点专项

月清课
├── E 系列阶段复习
└── 外部期末专题
```

选择 766 一级锚点时，表格展示其所有后代场景关联课程并去重。

选择具体场景时，表格展示与该场景直接关联的课程。

---

## 5.3 顶部命令区

保持紧凑命令层：

- 浏览方式切换；
- 当前目录面包屑；
- 搜索；
- 年级筛选；
- 学期筛选；
- 班型／体系筛选；
- 新建课程；
- 具备管理权限时进入场景配置。

搜索默认在当前目录范围内执行，同时提供明确的“搜索全部课程”入口。

主搜索默认只搜索课程当前信息：

- 课程名称；
- 当前默认版本的课节名称；
- 当前默认版本的教学目标。

历史版本通过“包含历史版本”显式开启，避免旧提交在主列表中形成重复课程。

---

## 5.4 课程表格

课程表格一门课程一行，不使用卡片。

固定列：

| 列 | 内容 |
| --- | --- |
| 课程名称 | 课程权威名称；同名课程只出现一次 |
| 年级／学段 | 多选范围；零选择显示“通用” |
| 学期 | 多选范围；零选择显示“通用” |
| 适用班型／体系 | 显示体系名或具体班型；零选择显示“通用” |

表格行不常驻展示：

- 维护教师；
- 分支数；
- 提交数；
- 完整度卡片；
- 使用次数；
- 大量标签；
- 历史版本状态。

这些信息进入右侧预览或课程详情。

表格支持：

- 单击选择；
- 键盘上下移动；
- 当前行高亮；
- 服务端分页或游标加载；
- 大数据量虚拟滚动；
- 管理模式下批量调整使用场景和适用范围。

默认排序采用最近有效更新；顶部提供简洁排序选项：

- 最近更新；
- 课程名称；
- 最近使用。

---

## 5.5 选中规则

页面进入时按以下顺序选择课程：

1. URL 中有效的 `course`；
2. 当前用户在该目录中的最近选择；
3. 表格第一门课程；
4. 当前目录为空时显示空预览。

行选择只更新右侧预览和 URL，不触发整个课程族页面重新渲染。

# 六、右侧当前默认版本预览

## 6.1 预览目标

右侧预览用于快速判断：

- 这门课大致讲什么；
- 有哪些课节；
- 每讲目标是什么；
- 课件整体形式是否符合需求；
- 是否值得打开完整课程或创建维护方向。

右侧始终围绕当前默认版本，不主动展示分支历史。

---

## 6.2 立即加载内容

选中课程后第一阶段立即展示：

- 课程名称；
- 当前默认版本标识；
- 年级／学段；
- 学期；
- 班型／体系；
- 课节目录；
- 每讲名称；
- 每讲教学目标；
- 当前版本是否可直接打开。

这些字段使用轻量预览清单，不读取完整 PageDoc、H5 包、游戏运行时或原始图片。

---

## 6.3 延迟加载内容

第二阶段异步加载：

- 当前课节封面或第一页缩略图；
- 少量关键页缩略图；
- 总页数；
- 最近一次有效提交说明；
- 历史使用摘要。

只加载预生成的 WebP／缩略图派生文件，不在目录页初始化完整交互运行时。

---

## 6.4 操作入口

右侧预览保留少量明确动作：

- 打开完整课程；
- 在当前事项中使用／关联；
- 创建自己的维护方向；
- 维护与历史。

“维护与历史”进入课程详情的二级页面或二级标签。

---

## 6.5 性能目标

隔离环境与生产走查采用以下目标：

- 课程行切换到文本预览：缓存命中接近即时，未命中 p95 不高于 300ms；
- 第一张缩略图可见：p95 不高于 800ms；
- 快速连续切换时，旧请求被取消，最终只展示最后一次选择；
- 初始目录不批量加载所有课程预览；
- 客户端保留最近 20 门课程的轻量预览缓存；
- 鼠标悬停或键盘聚焦稳定超过约 120ms 后允许预取；
- 缩略图以默认版本 revision/release ID 作为不可变缓存键。

# 七、课程创建、同名归并与维护方向

## 7.1 从使用场景中创建

默认入口：

```text
进入使用场景
→ 新建课程
```

创建表单预填当前场景，并允许继续多选其他场景。

创建字段：

- 课程名称；
- 使用场景，多选；
- 适用年级，多选；
- 适用学期，多选；
- 适用班型体系／班型，多选；
- 简短说明，可选。

创建时不预设课次数量。

---

## 7.2 自由创建

老师也可以从“全部课程”自由创建课程，之后再关联使用场景。

没有关联场景的课程进入“未归类”，便于后续整理。

---

## 7.3 同名检测

课程名称在机构 + 学科范围内进行标准化：

- Unicode NFKC；
- 去除首尾空白；
- 连续空白折叠；
- 英文字母大小写归一；
- 保留有业务意义的标点和数字。

发现标准化同名课程后，不继续创建第二个课程实体，而是显示现有课程：

```text
已存在《图形计数公开课》

[查看当前版本]
[创建我的维护方向]
[申请加入已有维护方向]
```

主管及以上可以处理历史误建的同名课程归并。

---

## 7.4 维护方向

维护方向采用简化 Git 逻辑：

```text
课程实体 = repository
维护方向 = branch
明确提交 = commit
默认展示 = default HEAD
```

但界面使用课程语言：

- 课程；
- 维护方向；
- 提交版本；
- 当前默认版本；
- 历史版本。

老师姓名显示在维护方向层级，不进入课程名称。

一位老师默认拥有一条个人维护方向，也允许建立教研共建方向或多人协作方向。

自动保存只更新草稿，不生成历史提交。

老师明确执行“提交版本”时生成不可变提交快照，并进入现有审核／发布流程。

满足发布要求的提交才可以被课程维护人设为默认版本。

---

## 7.5 当前默认版本

课程维护人可以从已经满足发布条件的提交中指定当前默认版本。

默认版本变更：

- 写入审计记录；
- 保留之前的默认历史；
- 不删除旧提交；
- 不改写已经冻结的课堂快照；
- 新打开课程和新关联事项读取新默认版本；
- 既有班级和历史课堂继续读取各自冻结版本。

第一条正式发布提交可以自动成为默认版本；之后由课程维护人主动切换。

---

# 八、课程详情与历史版本

## 8.1 默认进入当前课程内容

点击“打开完整课程”后，默认进入当前默认版本的：

- 教学计划；
- 课节目录；
- 课件预览；
- 使用或派生入口。

日常教师无需先看到分支图或提交列表。

---

## 8.2 维护与历史

“维护与历史”作为二级标签或二级页面，展示：

- 当前默认版本；
- 所有维护方向；
- 每个维护方向的负责人和协作者；
- 提交版本列表；
- 提交说明；
- 审核／发布状态；
- 历史使用记录；
- 版本来源；
- 基于某个历史版本创建维护方向。

第一版优先使用高密度线性列表和维护方向切换，不要求绘制复杂 Git 图。

历史检索支持：

- 提交说明；
- 维护人；
- 提交时间；
- 使用事项；
- 版本状态。

# 十三、旧数据迁移

## 13.1 课程实体归并

迁移前生成同名课程报告：

- 按组织、学科和标准化名称分组；
- 列出来源班级、课节、维护人和当前 release；
- 主管人工确认归并结果；
- 归并后保持所有历史 revision/release 可追溯。

现有“同一自由班多个课节被拆成多门单讲课程”的旧模型，应先按班级级合同归并，再进入本次同名课程归并。

---

## 13.2 适用范围迁移

现有 `grade`、`courseSeason`、`classType` 更接近来源信息，不能自动扩大为未经确认的适用范围。

保守迁移策略：

- 原 grade 生成一个精确年级目标；
- 原 courseSeason 非空时生成一个精确学期目标；
- 原 classType 非空且能映射机构班型时生成一个精确班型目标；
- 空值维度保持通用；
- 写入 `scope_origin='legacy_source'` 或等价审计字段；
- 管理员可以在网页端批量确认和修改。

旧来源字段继续用于追溯，新的适用范围关系负责浏览和筛选。

---

## 13.3 场景迁移

旧课程主题、关键词和班级类型不自动推断使用场景。

第一轮：

- 管理员配置 766 根节点和示例场景；
- 现有课程进入“未归类”；
- 提供批量多选课程并关联场景的管理模式；
- 后续根据实际使用逐步整理。

这样可以避免标题推断造成错误归类。

# 十四、实施阶段
