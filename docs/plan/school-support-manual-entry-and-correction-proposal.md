# 学服工作表补入学生与资料更正方案

> **规划状态**：`reference`
>
> **需求确认（2026-09-08）**：产品负责人提出历史资料不齐时需要临时插入学生，并在办理中修改资料、学生记录；补充确认各工作表、现场测评／体验、老生报名／续班场景都有。
>
> **交付范围**：代码现状核对与业务方案草案。下文交互、字段和施工顺序属于建议，待产品讨论；本次没有实现新接口或变更业务数据，不改变 doc 04 的阶段、生产状态或 Gate。

学服可以从当前实际业务节点开始办理。系统在当前表内完成找人、必要的最小登记和本次工作安排，之后由真实保存的业务记录继续流转。历史资料在影响本次工作时补齐。

本方案接续[统一客户资料与日常工作安排](student-records-and-work-queues-proposal.md)中的档案、业务事实、本轮工作与数据疑点分层；重复沟通与修订继续遵循 [doc 30 的 Communication / Task 合同](30-mathin_school_ops_architecture_plan.md#43-沟通与工作流层)。

## 2. 各表共用的补入流程

各表顶部提供“添加学生”，面板显示具体去向，例如“加入本轮联系”“加入本场测评”“加入本轮续班”。所选日期、活动、周期和班级可继承为默认值，保存前就地展示。

1. **输入并查找。** 姓名、家长电话、微信或已知外部编号可作为线索；优先呈现本次输入直接命中的候选，再展示其他可能匹配。搜索覆盖权限内全部档案及未关联线索，跨历史日期和当前阶段。
2. **选择这个孩子。** 候选展示姓名、年级及其时间依据、家长、可见联系方式、当前课程／最近经历，并说明匹配依据。选择已有对象后直接继续本次工作。
3. **未找到时最小登记。** 只填写本次能确认的身份线索和办理所需字段。仅有联系方式时复用 Lead / Contact 语义；已确认孩子身份时建立最小 Student。现场暂缺联系方式可先用姓名或可辨认称呼、场次及必要备注登记，缺项明确留空，不填写虚假号码或补造姓名。
4. **填本次安排并保存。** 当前表只要求对应工作的必要信息；来源默认记录为人工添加，操作者与录入时间自动保存。临时到场、转介绍、旧表遗漏等来源说明可快捷选择，普通补入无需逐条撰写长说明。
5. **留在当前表办理。** 成功后定位并展开新增行；保存失败保留输入。同一业务事项已在名单中时定位原行，用户可以继续办理或明确创建另一次尝试。

“已有多个相似对象、暂时拿不准”提供“暂存，稍后关联”：保留一个有稳定编号、能承载本次工作的待关联登记，优先复用已有未关联 Lead。它需要能再次检索，后续确认身份时接续同一项工作和全部记录；资料疑点落在该对象上，避免生成全员逐条清理任务。其具体存储方式需在实现时核对现有领域约束。

手机号只能帮助找到联系人或家庭。同号多子女各有身份，同名以及同名同号均由操作者结合背景选择；搜索不自动合并档案。有明确关联依据时复用该身份，纯来源行需确认其对应对象后才成为可办理主体。

查找权限与办理权限分别沿用现有范围。可检索不意味着可以改负责人、合并身份或登记正式报名；需要其他岗位处理时接续现有分配或办理入口。

## 3. 加入不同表时实际保存什么

| 当前工作表／场景 | 补入后形成的工作 | 后续自然流转依据 |
| --- | --- | --- |
| 线索 | 复用已有对象或登记最小线索，保留来源；负责人可留空 | 有明确联系安排时再进入本轮工作，采集信息本身不要求填写下一动作。 |
| 首联／沟通 | 复用客户或最小线索，加入本轮联系安排；负责人和日期按工作场景继承或选择，立即登记沿用当前办理权限 | 实际保存本次沟通及后续安排；老生新一轮联系保留已有经历。 |
| 测评／体验 | 建立或复用本次预约／参与记录；临时到场按事实直接登记到场 | 本次测评、家长反馈和去向分别保存。临时到场无需补造电话或邀约完成记录。 |
| 报名跟进 | 建立本轮课程机会或报名办理事项；课程未明确时允许先记需求 | 有意报名、待核实和正式报名分别表达；确认真实报名时使用既有报名流程。 |
| 分班 | 已有报名时直接加入待分班；旧表遗漏时可先保存待核实的分班办理事项及已知课程信息 | 核实有效报名并选择班级后，使用正式分班操作建立关系。资料补全前，办理事项继续可见。 |
| 续班／重新报名 | 为已有客户建立本轮沟通与课程机会，显示已知原班／课程及缺项 | 本轮意向、缴费核实和正式报名各自流转；仅加入名单不会生成在读或欠费事实。 |
| 学生阶段列表 | 找到或登记统一档案，并按当前目的创建相应工作 | 主阶段继续按实际沟通、测评及课程关系推导；本轮工作用途单独表达。 |

各表读取统一档案及对应工作关系。一个孩子可以在本轮报名跟进中，同时保留原课程的在读事实。学生页的阶段筛选与工作表用途分别处理，界面说明实际归类；保存回执或当前会话保留刚加入的工作，刷新后仍能从其工作单找到。实现时应补齐工作关系的持久读取，不能只在浏览器临时追加一行。

人工补入与自动流转使用相同领域操作，并保留入口来源。对同一孩子、同一场次／周期、同一事项进行重复提交或后续自动流转时复用既有记录；再次测评、另一课程或下一轮续班保留各自独立的事项。

## 4. 办理过程中修改什么

行内或学生侧栏提供“编辑资料”；每条已保存业务记录提供“修改本条”；新发生的沟通仍使用“新增记录”。关联错误在身份区提供专门的“更正关联”。

| 动作 | 例子 | 保存与同步范围 |
| --- | --- | --- |
| 编辑当前资料 | 改错字、更新学校／年级、补家长电话 | 更新统一档案与相关列表摘要，保存前后值、操作者和时间。历史原文及冻结快照保留。 |
| 修改本条记录 | 更正上次沟通日期、测评分数、导入报名说明 | 复用所属记录的修订机制；保留原作者、原始发生时间与修订链。更正一次沟通保持沟通次数。 |
| 新增一次记录／补录历史 | 今天再联系、去年漏记的测评 | 新建独立事实；历史补录记录实际发生日期及已知精度，录入时间自动保存，未知日期明确留空。 |
| 变更本次工作 | 改约、换本轮负责人、取消本次参与 | 使用对应工作操作；展示已经发生的测评、报名或分班影响并保留原尝试。 |
| 更正身份关联 | 将哥哥的测评误挂到妹妹、旧来源关联错人 | 展示将移动的具体来源／业务记录，确认后仅更正选定关系并留痕。真实重复档案的合并作为单独操作评估。 |

更新家长电话时保留其联系人关系；共享联系人影响其他孩子时明确显示涉及范围。输入号码命中其他档案时提示核对，不因改号码自动改变孩子身份。仅知道旧表年级时同时保留原学年或日期，避免把历史年级直接当作当前年级。

已生效的缴费、报名、分班、退课和已定稿测评通过各自业务入口更正。修订历史文本不自动撤销后续业务；确需调整时显示受影响事项并引导对应操作。普通字段更正直接保存，涉及下游关系或身份迁移时再展示具体影响供操作者确认。

“移出本轮名单”只结束或撤销相应工作关系并保留办理记录；学生档案和历史经历继续可查。档案删除继续遵循既有正式数据保护规则。

## 5. 建议施工批次

1. **共用找人和补入能力，先接沟通与临时测评。** 覆盖已有学生、未建档线索、新人、同号多子女、疑似关联暂存和重复加入；保存后直接继续当前行。第一批同时打通最常用资料字段的编辑。
2. **接报名、分班与续班。** 复用第一批找人组件，分别实现对应业务事项；兼容老生资料不齐与跳过前序节点，核对工作表、学生摘要和完整档案的读取一致性。
3. **补齐记录修订与关联更正。** 复用现有沟通／业务修订能力，优先覆盖当前办理会遇到的错误；身份重挂和真实重复合并按明确范围单独实现。历史数据的全量合并不作为以上批次的前置条件。

各批都先完成受影响合同与权限检查，再交开发页面人工验收。批次一与二涉及新增写入口时，服务端重新检查身份、可见范围、业务引用和重复事项；同一保存中的建档／关联与本次事项应保持原子性，重试复用同一结果，已有版本变化时保留草稿并提示重新核对。

现有布局、快捷键和显式保存继续按[首联保护基线](school-support-followup-panel-contract.md#10-首联已验收保护基线)及同文档的测评验收记录复用。具体必填字段和面板手感由产品负责人逐批验收，本草案不替代该验收。

## 6. 业务验收主例

- 学服在任一工作表查到已有学生，选中后直接加入当前工作，完整旧经历仍可读取。
- 现场来了一个未预约孩子，先登记到场并开始本次测评，后续补联系方式；系统保留真实进入路径。
- 同一号码查出兄妹，选择妹妹后只给妹妹新增本次工作；拿不准时可暂存并在确认后接续同一记录。
- 老生没有完整旧报名资料，先进入本轮续班／分班办理；缺项就地补齐，核实后通过正式报名／分班继续。
- 人工补入后再触发正常自动流转，同一事项保持一条；再次测评或下一期续班生成新的业务尝试。
- 更正电话后各工作表读取新号码，原始来源、联系人关系和历史快照可追溯；更正沟通不增加次数。
- 新增人、关联档案与加入工作之间发生失败时没有半成品提交；重试和并发修改给出明确结果。
- 误加入名单可移出本轮，误挂记录可按具体影响更正；本人无权限的档案或正式业务保持原授权边界。

这些是待实现和人工验收的场景清单，本轮没有执行这些业务操作。
