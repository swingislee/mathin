> **规划状态**：`active`
>
> **交付状态**：设计已形成，待实现；本文件属于 E0，不表示数据库、页面或生产性能已升级。
>
> **依据**：2026-09-21 产品负责人要求沿 PostgreSQL 结构化数据、数据库聚合与按页读取的方向进行升级设计。

## 1. 设计决定与现有证据

采用 **写入时整理单行统计字段 → 数据库按授权范围关联、去重、聚合 → 应用接收展示结果 → 展开时读取一页明细** 的链路。

首版继续使用现有 PostgreSQL/Supabase、业务表和业务 RPC。单行确定性转换使用显式 `STORED` 生成列；跨行版本选择、人员归属和去重先使用集合 SQL。计数、趋势、人员汇总由数据库计算。物化视图或增量汇总表作为执行计划证明仍有必要时的下一层优化。

现有证据的边界如下，后续基线需固定版本、账号范围、数据集和时间重新采集：

| 已知事实 | 含义与来源 |
| --- | --- |
| 本机完整装载仍有 39 次内部 REST 调用，解码 JSON 合计 8,849,704 字节 | 是 Supabase → 应用服务器的数据量，包含工作项和月目标读取；不是浏览器下载量。见 [SQL 投影优化证据](../evidence/r1/overview-acquisition-projection-20260921.md) 与 [装载诊断测试](../../tests/staff-overview-loading-database.test.ts)。 |
| 沟通约 3.13 MB、获客来源约 2.27 MB、线索约 1.08 MB、活动报名约 1.06 MB | 前四类约占 85%；优先减少这些明细和来源元数据在总览请求中的传输。各请求并发，耗时不能相加作为页面耗时。 |
| 最新本机总览数据装载约 423–437 ms，39 次调用和 8.85 MB 未变 | 前轮优化减少重复权限判断、档案回读和 JSON 展开，尚未改变整个总览的输出与计算位置。不能外推为生产页面时间。 |
| 用户生产硬刷新仍感到 4–5 秒 | 需要同时测量认证、服务端装载、响应传输与页面渲染；本设计解决其中统计与列表读取部分。 |
| 测评已采用数据库分页，首联已有无额外筛选的分页分支 | 复用现有成果，继续处理搜索、列筛选和其他阶段的残余全量计算。见 [表格分页证据](../evidence/r1/table-database-pages-20260921.md)。 |

`04000`、`05000`、`06000` 获客迁移的本机与生产状态以对应发布证据及实施时的 preflight 为准。最后核对记录中，这三条仍未发布生产；本设计不把仓库存在当作生产生效。

## 2. 读取结构

```mermaid
flowchart LR
  A[业务写入与来源导入] --> B[现有业务表与原始来源]
  B --> C[同事务生成窄统计字段]
  C --> D[按当前身份可见的候选事实]
  D --> E[SQL 版本选择与业务去重]
  E --> F[周期统计 / 学期容量 / 当前待办]
  F --> G[总览汇总 RPC]
  E --> H[搜索排序与数据库分页]
  H --> I[一页明细 RPC]
  I --> J[按需查看原文与业务详情]
```

三类统计分别限定范围，共用授权和事实规则：

| 类型 | 输入范围 | 返回内容 |
| --- | --- | --- |
| 周期统计 | 选定本期、比较期及既有来源确认月份；最新版本选择先于日期筛选 | 六项业务计数、逐日趋势、学服漏斗、教师参与与报名结果、活动报名计数 |
| 当前学期 | 唯一当前学期内的有效 production 班级、有效入班与任职关系 | 学生去重人数、班级数、席位、年级和教师容量、页面实际展示的班级摘要 |
| 当前待办 | 当前有效线索、邀约、未测评到访和待处理学服任务 | 七项待办计数；逾期依照本次服务器时间计算 |

缺少发生日期的数量按当前既有规则单独汇总，不能因所选月份筛选而消失。展示人员目录使用授权范围内的窄 ID/姓名查询，保留当前期间无业务但可选的人员；不再为建立目录返回全部历史事实。

## 3. 数据层：先建立窄字段，保留唯一事实来源

### 3.1 单行派生字段

优先在原记录上保存确定性、可重建的统计字段，避免另建需要持续双写的业务事实表。字段名为设计名，最终 migration 须附旧字段到新字段的完整映射。

| 原表 / 输入 | 需要的派生内容 | 维护方式 |
| --- | --- | --- |
| `history_import_records.record_data` | 获客日期、来源登记日期、姓名/电话存在标记、来源署名、逻辑来源键与版本；姓名仅用于明细搜索和显示 | 复用 `06000` 已建立的原文投影规则，补齐真正参与筛选的类型化字段。生成表达式直接使用原字段，不引用另一生成列。 |
| `lead_communications.source_metric_facts` | 标签是否合法、来源键/版本/范围、沟通确认、确认月份状态、来源署名 | 写入时完成与现有解析器等价的校验与提取；业务发生时间、结果和历史负责人沿用现有列。 |
| `activity_registrations.source_metric_facts`、`source_enrollment_facts` | 六类确认及月份、对应署名、来源报名日期 | 仅派生总览使用的标量；原始证据和原表名称保留在原文中，展开后再查。 |
| `course_enrollments.source_metric_facts` | 来源合法性、键/版本/范围及报名所需的确认字段 | 原生报名时间与 Opportunity 关系继续沿用领域事实。 |
| `activities.remark` 的历史来源标签 | 现有规则识别的学服/学科署名 | 单行解析结果可存储；名称到正式账号的解析在读取时按现有规则完成。 |

规则要求：

- `source_metric_facts` 只有通过完整校验后才提取为有效来源事实；不能仅删除 `evidence/sourceName` 等字段后交给旧解析器，导致其失效并切换统计分支。
- 月份区分 **字段缺失、显式 null、有效月份**。旧代码会据此选择实际发生时间或确认月份，单一可空日期列不足以表达全部语义；使用 `month_state` 与 `reporting_month` 配对。
- 实际时间 `timestamptz`、业务日期 `date`、仅有月份分别保存；机构时区在查询时统一换算。生成列不依赖当前时间、当前用户、其他表或机构设置。
- 来源版本比较和同版本的稳定顺序沿用现有规则；若发现旧顺序不确定，先登记差异，不能借性能迁移改变获客人数。
- 字段不保存跨请求的“当前用户可见”或“已逾期”结论；这些条件在每次读取时求值。

### 3.2 跨表计算留在集合 SQL

建立可复用的窄候选关系，逻辑上包含：`candidate_key`、指标、来源类型、原记录 ID、来源键/版本、真实日期/时刻、月份状态、人员依据、Lead/Student/Activity 引用。这是一组按指标拆分的内部视图/SQL 函数，首版不要求新增一张万能事件表。

候选关系只负责提供事实；版本选择、归属和去重按指标口径执行。总览与明细共用这些关系，避免维护两份独立统计规则。

现有 `business_*` 视图的来源权威、人工裁决与 current/historical 边界继续复用；新候选不能直接读取底表后省略这些条件。若这些视图本身仍有重复计算，在保持同一可见集合的前提下单独改写并对照。

集合处理顺序固定为：

1. 确定调用者能读取的来源与关联对象。
2. 按该范围选择来源版本、连接别名和关联记录。
3. 按指标生成原生/来源候选；获取所需关联闭包。
4. 按本期、比较期及指标规则去重、归属和汇总。
5. 最后构造返回 JSON；明细则在构造完整行前分页。

日期限制不能过早裁掉归属和去重依赖。例如本月来源的新版本移到了其他月份，不能因先筛本月而让旧版本重新入账；教师报名归属也需要相关参与记录，而非把所有关联表都限制成同一日期。

### 3.3 写入、修正与重建

单行派生列跟随原业务 INSERT/UPDATE 同事务更新，原事务失败则一起回滚。删除、归档、恢复、Lead 关联变更、人员转交、学期切换由实时关联反映，无需新增定时全量刷新。

实施前列出实际写入口：领域 RPC、原生编辑、`scripts/lib/operational-source-import.mjs`、来源修复、重新导入、身份合并/拆分、人工历史范围裁决。逐一检查生成函数执行权限及更新后的 business view 列权限。历史表的导入权限模式不能照搬到普通员工可写的沟通/报名表。

首次字段回填属于迁移成本，记录锁等待、执行时间、WAL/磁盘增量与写入延迟；数据较大时采用可分批回填的派生列方案及切换检查。任何批次都不覆盖原始档案和业务记录。重放同一输入必须生成同一统计字段。

| 沟通 | `connected/declined` 与来源确认分支保持；月报对来源版本去重并排除既有 followup 分支；补充确认按主体、人员及月/日规则判断 | `supplementOverviewContacts`、`getStaffOverviewData` |

## 5. 总览、分页、详情分别定义接口

### 5.1 总览汇总

拟新增 `get_staff_overview_summary_v2(p_grain, p_date)`，使用调用者身份。机构时区、本次时刻、当前学期和月份目标在数据库查询上下文中一次确定。采用一个 `LANGUAGE SQL STABLE SECURITY INVOKER` 入口，以一个查询快照产出总览主体；确认项目实际 PostgreSQL 版本和已授予列权限后再落 migration。

返回 `schemaVersion`、`generatedAt`、周期边界、可用性，以及与 `StaffOverviewData` 对应的展示数据：

- 六项业务的本期/上期计数与趋势、活动报名计数、缺日期数量。
- 学服各人漏斗、教师参与结果、授权人员目录。
- 当前学期快照、年级/教师容量与现有页面需要的班级摘要。
- 七项待办计数与允许读取的当月目标。

应用保留类型适配、翻译、数字格式和展示选择，不再接收通信记录、原始来源 cells、电话、证据数组和历史别名数组来计算统计。小型人员与班级摘要随页面现有规模增长，历史业务明细增长不应线性增加响应大小。

页面“我的工作”角标独立使用只返回数量的查询，复用既有工作项候选与授权规则，不再调用完整列表后取 `.length`；遵守 [doc 25 工作项合同](25-production-1.0-product-completeness.md#41-work-items现状缺口与决定)。其计数可以与总览并行，标明独立采集时刻。月份目标进入总览查询，消除其当前串行读取。

汇总不再受应用端 10,000 行下载上限限制。超时或错误返回明确不可用状态；不能以截取前 N 条的结果冒充完整计数。支持的权限范围不足以计算某指标时，该指标保持 null。整个 RPC 失败时显式显示加载失败并可重试。

### 5.2 明细分页

拟新增 `list_staff_overview_details_v2`，输入保持现有 `kind/metric/period/person/search/sort/page/pageSize` 语义，增加版本化上下文校验。服务器使用 Zod 白名单验证；数据库再次限制指标、排序和每页 25/50/100 条。

执行顺序：**授权候选 → 对应统计事实 → 搜索/列条件 → 稳定排序 → 准确总数和当前页键 → 当前页展示字段**。姓名搜索、来源名优先级、中文排序、Unicode 空白处理必须在分页前与当前合同对照；禁止先取一页再搜索。排序最后使用稳定业务键，页码保持现有越界收敛规则。

返回现有 `total`（基础范围数）、`filteredTotal`（筛选后数）、全范围人员选项、有效页码和一页记录；人员选项本身不读取全部宽明细。记录保留回溯业务对象/原始来源的键，原文在用户展开后单独读取。

当前 [明细 Action](../../src/features/school/home/staff-overview-drilldown-actions.ts) 的“全量补姓名 → 排序/过滤 → slice”在切换后移出线上路径。明细与摘要使用同一口径，但 `generatedAt` 只固定统计截止时间，不能代表跨请求冻结数据库快照。用户展开期间数据发生修改时读取最新授权数据、显示明细生成时间并允许刷新总览；不为性能改造新增跨请求历史快照存储。

### 5.3 沟通、测评、线索列表

保留现有列表产品形态、筛选语义与首联操作基线。将权限、阶段、搜索、列条件和排序所需字段组成窄候选关系，选页后补齐展示字段。完整历史、逐题备注、原始档案和沟通流水由展开动作读取；列表只返回最近记录或聚合摘要。

复用 `list_assessment_workbench_page` 与 `list_student_records_page`；重点补齐沟通有搜索/列条件的分支、其他阶段和工作单路径，检查线索关联历史与入库列表。列表总数、阶段计数和筛选选项均来自完整授权集合，不以当前页替代。已验收首联的草稿、保存、快捷键及姓名入口继续遵守 [保护基线](school-support-followup-panel-contract.md#10-首联已验收保护基线)。

## 6. 权限、查询计划与一致性

- 受保护入口继续走 `requireUser`；数据库使用 `SECURITY INVOKER` 及底层 RLS。新增列、视图和函数逐项登记 ACL；只开放需要的只读接口。
- **先按调用者可见范围选择事实，再做跨版本去重和统计。** 不能先按管理员权限全局聚合，再通过人员筛选伪装成员工可见数据。来源可见性、业务对象可见性与字段权限分别核对。
- 事实上的业绩归属与访问权限独立。负责人字段、来源署名、页面选中人员均不能单独证明读取授权；角色撤销、协作关系变化后，下次请求立即重新检查。
- 权限中与当前行无关的身份判断每语句计算一次；依赖当前行的范围条件保留。按执行计划选择关联键/筛选键索引，避免把集合连接写成逐行调用权限或解析函数。
- 候选索引围绕来源键与版本、业务日期/月、关联 ID、当前状态以及现有授权关联。测试期间记录扫描行数、loops、buffer、排序和临时文件；小表顺序扫描本身不是缺陷，不为得到 Index Scan 强行加索引。
- 使用 `count(distinct ...)` 或分组前去重时，分别验证机构和个人口径，控制 JOIN 放大。优先压缩中间关系后生成 JSON，避免一层层构造宽 JSON 再排序。
- 首版实时查询不跨请求缓存授权结果。若后续引入预汇总，必须定义修正/撤销/重新导入的重算范围、幂等键、失败恢复、重建校验及权限维度；涉及 distinct 学生的指标不能简单累加每日人数。

## 7. 性能目标与测量口径

以下是本次升级的**设计预算和验收目标，尚未实测达成**。不改写 doc 25 的正式性能门槛，也不把它们增加为 R1-Live Gate 2 条件。

现有本机数据读取已经约 0.43 秒，生产整页仍有 4–5 秒体感，两者的环境和测量范围不同。压缩内部数据量能减少冗余处理，但不能据此承诺消除全部等待。批次 A 同时固定整页关键路径：导航开始 → 连接/请求 → 认证与模块初始化 → 数据 RPC → RSC/HTML 传输 → 脚本/字体与渲染 → 主要数据可操作；用关联请求标识和分段时间识别剩余开销，不能把并发段时间相加。受控 HAR/日志仅保存必要计时，凭据与业务行不进入共享证据。

| 层次 | 设计预算 / 目标 | 测量方式 |
| --- | --- | --- |
| 总览主体读取 | 1 个汇总 RPC；工作角标至多额外 1 个计数 RPC | 统计从装载开始到数据完成的全部实际请求；认证等共享请求另列，不藏进统计数字 |
| 总览内部业务响应 | 当前基准数据集解码 JSON 合计目标 ≤150 KB；不随历史明细数线性增长 | 计入汇总、目标、工作角标及剩余兼容请求；同时记录压缩后网络字节 |
| 汇总 SQL | 首轮目标 p95≤200 ms | 固定数据、时区和身份；包含 RLS、聚合、返回 JSON 构造；单列首次执行、规划与执行时间 |
| 完整业务数据读取 | 首轮目标 p95≤500 ms | 真实 Supabase HTTP，计入等待、全部响应接收、JSON 解析和应用适配 |
| 内部关键页服务端 | 既有 PERF-03：同地域网络 p95≤1.5 s | 按 doc 25，不用 SQL 时间代替 |
| 用户看到数据并可操作 | 按前轮确定的方向，以首次打开、硬刷新和侧栏进入均 ≤2 s 为体验目标 | 目标浏览器+生产构建，主要数据完成且控件可操作；骨架、首字节和仅 LCP 不代表完成 |
| 列表与明细 | 每次至多 pageSize 条完整行，额外关系只服务当前页 | 测首页/第二页/末页/空搜索/列筛选；总数与选项允许单独集合计算，计划中检查其成本 |

测量分三类，分别保留结果：

1. 新页面/禁用浏览器 HTTP 缓存的硬刷新；不会清空数据库缓存或自动代表服务进程冷启动。
2. 隔离开发环境的应用新进程首次访问；若需要验证数据库冷缓存，仅在隔离副本测试并单列，不重启生产数据库制造样本。
3. 后续刷新、侧栏切换、换月和展开明细。

开发内循环先各取 3–5 次观察首次值、中位数与最大值；候选稳定后在代表环境收集至少 30 次独立请求，p95只作小样本比较，记录样本量；正式容量结论仍按 doc 25。固定 build、机器、连接方式、账号授权范围、数据规模和缓存状态，不能拿本地热读与生产硬刷新直接相减。

## 8. 实施批次与退出条件

每批独立提交；先在本机隔离数据库验证。设计文件本身不执行 migration 或生产发布。

| 批次 | 具体改动 | 可以确认的结果 |
| --- | --- | --- |
| A：冻结口径与读取基线 | 固定 `now`、数据集与角色；列出全部字段/写入口；扩展已有真实 HTTP 对照工具，增加业务键集合和每段字节/耗时 | 一份可重复的旧行为基线；发现的业务歧义逐项登记 |
| B：沟通与获客 | 建立必要窄字段和 invoker 候选 SQL，首先完成这两项计数、趋势、人员汇总与明细候选 | 这两类原始明细不再是新汇总算法的输入响应；约 61% 的当前内部流量有明确替代路径 |
| C：其余总览指标 | 迁移邀约/到访/测评/报名、教师结果、学期容量、当前待办、目录/月目标与工作角标计数 | 完整 v2 DTO 与旧口径对照；汇总 RPC 只返回展示结果 |
| D：总览接入与展开分页 | 接入 summary v2 与 detail v2，迁移明细搜索/排序/补姓名，移除线上旧全量读取调用 | 请求数/字节/SQL/页面体验共同验证；开发端可验收 |
| E：列表剩余分支 | 复用现有数据库分页，处理沟通搜索及其他阶段、工作单、线索长历史；复测测评历史查询 | 首页、翻页、空搜索、跨角色都遵守分页合同；逐路由登记结果 |

首个开发增量固定为 A+B，交付沟通/获客真实数据库对照及独立迁移候选。新旧完整总览双读只用于隔离验证，不放进生产首屏；总览生产切换以 C+D 完成的完整路径为单位，避免留下“新 RPC 后仍调用旧全量读取器”的双重开销。批次 E 可按路由独立验收。

真实 HTTP 等价对照使用 v2 返回的 `generatedAt` 作为旧算法的 `now`，在固定且无并发修改的隔离数据集上比较。数据库内部对照在同一只读快照执行，避免把时间流逝或并发业务变化记成算法差异。

采用新增 v2 函数/适配器的兼容升级：字段和只读函数先部署，再切应用。旧算法保留在测试基线及可回退版本中，线上请求不自动回退到全量下载。出现指标差异或性能回退时，通过已知应用版本/配置回切整条路径并登记原因。

生产候选列出精确 commit、迁移依赖、锁影响、备份及恢复命令，按[写目标策略](../runbooks/r1-write-target-policy.md)执行授权与 preflight。回退优先切回旧应用；新增派生字段可暂留，清理按依赖逆序另行执行，不恢复或覆盖新产生的业务数据。

## 9. 防回归检查

优先复用既有 `staff-overview-*` 测试及真实库诊断，新增检查覆盖以下实质风险：

- **等价性**：当前/历史周月、月底、来源仅月份/缺日期、重复导入/同版本、同名不同人、Lead 转 Student、来源与原生重叠、多教师归属；计数、趋势、人员和全部分页键集合对照。旧读取达到 10,000 上限时不作为完整 oracle，使用可控夹具和独立 SQL 核算。
- **权限**：现有固定管理员、校长/销售/教师/教研、学生、家长、匿名；复用连接切换身份；撤销角色/协作后重读；明细、总数和筛选选项均不泄露范围外信息。
- **新鲜度**：真实写入口修改日期/负责人/结果，重复导入、修正版本、归档恢复、合并拆分后，下次查询立即符合事实；纯查询无业务写副作用。
- **分页**：同日期/同姓名稳定排序、第二页/末页/越界页、无结果搜索和中文排序；名称筛选命中其他页时能正确出现；异步旧响应不会覆盖用户新选择或草稿。
- **规模**：隔离事务生成受控夹具，分别增加历史事实数和单个主体历史长度；摘要响应不随历史明细线性增长，列表补齐行数受页大小约束，记录真实计划变化。测试夹具回滚且不触碰正式数据。
- **首屏与错误**：v2 页面不得调用旧全量装载器；计数角标不得下载工作项全文；统计/详情失败显式提示；新结果不能以缺日期、丢页、权限绕过或隐藏错误换取速度。
- **回退与写入开销**：迁移前后业务原文摘要、权限和业务计数一致；测量写入增量成本、数据库恢复与应用回切；每次验证按新增风险选择，不对纯文档和已覆盖小改动重复完整 Gate。

完成汇报分别列出机器检查、开发端可验收、生产已部署待验收、用户实际验收；这一设计不提前宣称其中任何运行结果。

## 10. 技术依据

PostgreSQL 支持在筛选后的集合内执行 `GROUP BY`、`COUNT` 和条件聚合，结果可以直接形成页面需要的分组表；这里据此设计汇总查询。[官方聚合说明](https://www.postgresql.org/docs/current/tutorial-agg.html)

显式 `STORED` 生成列在原行写入时计算并存储，适合本设计的单行字段整理；生成表达式限于当前行和 immutable 运算，跨表关系继续交给查询。[官方生成列说明](https://www.postgresql.org/docs/current/ddl-generated-columns.html)

Supabase 数据库函数可通过 API 调用，适合数据密集计算；调用者权限、函数授权和 search path 需明确配置。[官方数据库函数说明](https://supabase.com/docs/guides/database/functions)

物化视图会存储查询结果，需要刷新来反映后续变化。本设计先测量实时集合查询，仅在有剩余瓶颈时追加预汇总，并明确新鲜度和修正策略。[官方物化视图说明](https://www.postgresql.org/docs/current/rules-materializedviews.html)
