## 1. 本次复查结论

首批目标是：员工在有权查看的一节课中，能发现并阅读该课的教案、解析和试讲视频，并继续查看同课学生表现与反馈；切换材料或返回列表时保留老师、班级与课次定位。

现有入口能够定位课次，但材料的发现、读取权限和阅读动作尚未形成完整路径。该缺口可以在现有班级课次详情中解决。上一轮提出的常驻老师与课次侧栏尚无必要性证据，退出首批方案。

### 1.2 与旧规划的关系

[doc 26](26-teacher-workflow-upgrade.md)中的独立教案管理入口属于“创建教案并绑定课次”的剩余工作，另有服务端打印 PDF 派生文件。它们与本次“集中阅读已有材料”目标不同，继续保留原状态，本次不把它们作为依赖或完工项。

[doc 25](25-production-1.0-product-completeness.md#431-备课行课课后统一对象合同)已要求开课、下课后保留备课材料。本次补齐班级入口到材料的读取路径，复用课次这个权威对象，不建立第二份教案、解析或审核状态。

## 2. 修订后的查看流程

1. 从现有班级入口按老师分组或筛选，展开对应班级和课次。明确显示老师、班级、课次标题和日期。
2. 课次详情直接呈现“教案、解析、试讲视频”的材料入口；本课课件提供对照入口。目录显示真实材料标题、类型与可用状态，审核状态作为附属信息。
3. 选中一种材料后，在当前课次的阅读区展示正文或文件列表；保持课次身份可见。一次加载所选内容，切换材料保留相应阅读位置。
4. 学情、作业、课评与课次沟通继续复用现有记录区。阅读材料后能返回同课学生记录；与本课无明确关联的沟通保持原来源说明。
5. 返回或切换课次后保留老师范围、班级展开、筛选与滚动位置。移动端沿用同一对象与材料顺序，阅读区域按可用宽度展开。

首批阅读入口采用只读模式。需要修改、审核或登记时进入对应的显式操作；打开阅读区本身不触发开始备课、创建空白教案、自动保存或状态流转。

## 3. 每种材料的阅读合同

| 材料 | 阅读结果 | 必须保留的区别 |
| --- | --- | --- |
| 在线教案 | 显示已保存正文、当前状态、revision 和更新时间 | [读取适配器](../../src/features/school/teacher-preparation.ts)可在没有记录时生成默认模板，阅读入口应显示“暂无已保存教案”，不能把模板当作老师已经填写的内容 |
| 上传教案 | 图片/PDF 提供可用预览及原件下载；其他格式提供明确的打开或下载动作 | 正文教案与附件都存在时分别列出；上传文件不冒充在线教案版本 |
| 板书解析 | 复用关联课件页与板书的合成预览、现有导出能力 | 使用生成后的 `solution_records`；老师个人未生成成品的板书草稿与解析成品分别处理；关联页不可用时说明缺失 |
| 上传解析与文字说明 | 展示说明、文件列表及可用预览/下载 | [解析上传投影](../../supabase/migrations/20260730010500_doc26_teacher_workflow.sql)与原文件列表可能指向同一内容，按来源去重，不重复计数 |
| 试讲视频 | 展示已保存外链，提供“打开原链接”与复制；Mathin 中保留原课次位置 | 当前为试讲/磨课外链，不能标成真实课堂录像；外部网盘可能要求登录，不承诺所有链接都能在页内播放 |
| 本课课件 | 从本课所选内容或已冻结快照读取，支持材料对照 | 历史课堂对照使用课次事实，不能静默替换成课程目录的最新 release |

材料归属于实际课次。按老师筛选表示任课关系，不等于证明每份材料均由该老师创作。存在作者、提交人、修订人数据时按其真实含义呈现，不能从当前主讲姓名推断材料作者。

课件冻结也不代表教案、附件和视频永久停留在开课时版本。档案补改后显示已读取材料的真实状态、版本与更新时间；没有相应历史快照时不使用“上课时版本”标签。完整版本对比不属于首批范围。

## 4. 只读权限与状态

建议管理阅读范围与已有全体班级查看范围对齐：持有 `class.view.all` 的员工可只读其可见课次的教学材料；任课教师和指定审校人继续按原关系读取。具体角色对照与 RLS、Storage 实现须在开发前核实，本次复查没有授予或变更任何账号权限。

新增的管理只读能力与审校、材料修改、点名和课堂控制分别判断。审校人能看教学材料，也不因此新增学生名单或联系方式的读取能力。原沟通数据继续沿用其独立权限与可见范围。

查看结果至少区分：已读取但无材料、已有草稿/已提交材料、没有查看权限、读取失败。签名过期或附件读取失败提供重新获取和重试，不解释为老师未提交；没有材料时也不推断为教学不合格。

## 5. 首批范围与实施顺序

首批交付包括材料只读合同、教案/解析/视频的完整打开动作、班级课次内的统一入口及阅读位置保留。这四项共同形成一次可验收增量。仅补跳转按钮只能记作局部修复。

实施顺序：

1. 对照固定教师、具备团队查看权限的主管、指定审校人与无权限主体，确定课次、正文和附件的真实读取范围；核查空模板、签名失败和作者/版本字段。
2. 复用教案只读渲染、解析合成预览与受权文件读取，补齐每种材料的打开、失败和空态。
3. 接入现有课次详情，在三个教学阶段保持材料入口一致，保留原学生登记和未保存保护。
4. 完成覆盖本次改动的定向检查，交付开发端供人工体验。涉及只读权限或 API 变更时增加相应集成检查；视觉结论由产品负责人确认。

首批范围之外：独立主管仪表盘、独立资料库/教案创建管理、教学质量评分、自动异常排名、跨课进步推断、全量历史版本对比及视频转码。后续增加项目应由真实查看过程中的具体问题驱动。

## 6. 人工验收场景

- **找得到**：从现有班级入口按老师找到一节已结束课程，课次内能直接发现教案、解析和试讲视频。
- **读得到**：在线教案正文、上传教案、板书解析、上传解析和视频外链都能完成对应阅读动作，不能停在文件名或提交状态。
- **连得上**：看解析时能对照原题；随后查看同课学生表现和反馈，不必重新寻找老师、班级或课次。
- **继续看**：返回或切换另一节课时，保留老师范围与原列表位置；移动端同样可完成。
- **看得准**：无材料、模板、草稿、已提交、无权限和读取失败有明确区别；材料作者、版本与课次来源没有混淆。
- **只读可靠**：主管阅读不创建或修改业务记录；其他主体不能通过直达地址或附件请求越权。既有学生登记的草稿和保存保护继续有效。
