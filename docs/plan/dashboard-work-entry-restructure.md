# 仪表盘工作入口重组

> **状态**：开发端已交付，待人工视觉与业务验收。
> **依据**：2026-09-19 产品负责人要求直接重构正式页面，并明确旧网址无需保留接入新入口；后续确认学生改为密集名录卡片，沟通继续连续登记。
> **范围**：侧栏、工作页编排、站内链接、学生名录读取与既有功能迁移；当前生产阶段继续以 doc 04 顶部为准。

## 1. 一级入口

员工先按要做的事选入口，再按阶段、班级和时间缩小名单。角色决定可见范围与办理权限。

| 顺序 | 入口 | 工作内容 |
| --- | --- | --- |
| 1 | 总览 | 查看概况与已有待办，进入对应办理页面 |
| 2 | 课表 | 按时间找课、进入课次 |
| 3 | 线索 | 导入、核对、分配联系人 |
| 4 | 沟通 | 按学生阶段展开登记，连续处理联系结果 |
| 5 | 测评 | 查看预约、登记测评与反馈、查看报告 |
| 6 | 学生 | 按组织形式找学生、看档案、选人后进入沟通 |
| 7 | 班级 | 分班、进入班级、连续教学登记、查看完成情况 |
| 8 | 续班 | 沿用目标周期、沟通结果、报名与缴费工作 |
| 9 | 活动 | 按场次安排与登记 |
| 10 | 财务 | 沿用原账务入口 |

教学资源继续分组展示。组织管理包括机构、校区、员工、权限、学年和报名配置；系统管理沿用现有入口。协同记录、管理分析退出侧栏并返回 404，底层历史记录继续保留。

## 2. 沟通

正式地址为 `/dashboard/communication`。标签沿用学生阶段的权威推导：**待首联、待测评、待报名、待续班、已停读／课程结束**。

- 待首联复用已验收的首联摘要行与行下详情，包括联系结果、微信、意向、承接、备注、下次联系和显式保存。历史仅有学生档案的记录继续使用已有首联承接方式。
- 待测评默认展开邀约登记；待报名默认展开报名登记；待续班和已停读／课程结束默认展开沟通备注，保留续班或重新报名等既有快捷动作。表内展开、保存与下一位继续使用现有连续录入逻辑。
- 五阶段继续共用原数据层，在沟通中作为工作标签；在学生名录中作为筛选条件与卡片标记。
- “联系工作单”进入 `/dashboard/communication/worklists`，保留原工作安排、待安排、沟通记录和固定名单。明确的线索或工作单定位也进入该办理面。
- 只有原沟通权限但没有学生列表读取权限的员工继续使用工作单界面；数据读取和写入仍由原权限及服务端合同控制。
- 跨阶段搜索使用学生阶段表原有行内登记。首联表自身列筛选仍作用于当前加载名单；本轮没有重写五标签的人群推导或跨页草稿规则。

首联授权与保护基线见 [首联面板合同 §10.6](school-support-followup-panel-contract.md#106-2026-09-19-沟通入口与五阶段编排开发端待验收)。

### 2.1 学生名录与选人沟通

`/dashboard/students` 展示已建立学生档案的身份。是否报名不影响进入名录；纯线索留在线索与沟通中，线索关联学生后按学生身份展示一次。

- 主体使用密集卡片：姓名、年级、电话后四位；边框、底色和 SVG 图标表示阶段，悬停显示具体状态。真实测评附上最近结果和日期，班级等级推断仍只作为原档案中的参考。
- 支持班级、年级、负责老师、业务组及不分组；缺少分组的名单置后。一个学生可在多个所属分组中出现，选择与总人数按学生去重。筛选和分组人数在数据库分页前计算。
- 教师默认“与我相关”，其余拥有全局学生查看权限的员工默认“全部可见”。范围始终受原学生可见权限约束；页面入口不增加办理权限。
- 点击卡片打开已有学生档案侧栏。搜索与阶段筛选辅助找人，原五阶段不再作为学生页主标签。学生的新建、导入、业务分组和回收站入口继续保留。
- 跨页最多选择 100 人，点击“联系这些学生”进入沟通的选定名单。按选择顺序显示当前阶段及对应表单，复用原显式保存和下一位逻辑；阶段改变后保留本轮行序，返回名录可恢复筛选。选定名单只在当前导航中传递；服务端重新核对可见身份，不创建新工作单。
- 教师日常教学从班级进入，集中沟通从沟通进入；学生页承担人员检索与组织浏览。

本机新增 `20260919001000_student_directory` 与 `20260919002000_student_directory_group_order` 两个只读接口迁移。开发核对与复验命令见 [学生名录本机验证](../runbooks/student-directory-local.md)。

## 3. 班级

正式地址为 `/dashboard/classes`。2026-09-20 产品负责人确认名册与教学记录合并，继续以原分班名册作为主体：每班一行，直接看到时间、任课老师、难度和全班学生。

| 位置 | 内容 |
| --- | --- |
| 顶部 | 按年级／老师分组、学期选择、右侧更多操作；移除班级名册／教学记录两个主标签 |
| 班级主行 | 班级、时间、老师、难度固定在左侧，全班学生在右侧直接铺开；选座、调班和原容量校验继续保留 |
| 每班课次条 | 默认正在上课、今天或最近课次；可选具体课次、上一课／下一课，显示已登记考勤与课评数 |
| 班级行下详情 | 点击“查看 / 登记”展开本课学生的考勤、逐题学情、课评和沟通；课评自动保存，沟通支持保存并下一位 |
| 右侧“…” | 名册筛选、建班、完成情况、我的待办、班级目录 |

- 学期负责选择班级范围；课次由各班自己的课次条选择。明确的课次链接直接定位所属班级和学期，并展开该课。
- 班级名与学生名继续打开已有详情和档案；课次详情保留专业课次工作区、作业批阅、已有沟通与辅助记录。
- 顶部完整名单反映班级当前组织关系；展开后使用所选课次的实际名单，冻结课次沿用当时学生，未冻结课次沿用原实际名册来源与临时调班规则。
- 课评只提交本次修改过的学生。保存校验与本课实际名单一致；当前新加入但不在旧课名单中的学生不会被写入旧课。沟通继续复用原课次登记接口。
- 未保存的沟通、课评保存中或保存失败时，保留当前展开课次并提示先处理登记；可重试或放弃未保存内容。原课评发布与沟通完成操作继续保留。
- 所有员工共用此结构；可见班级、课次和办理权限仍由已有权限、RLS 与课次 RPC 控制。详情按需读取，编辑器按展开加载。
- 完成情况作为辅助入口保留跨班周／月／学期统计；班级主体不再另设教学记录列表。
- 名册继续移除“当前工作／历史记录／全部记录”状态筛选；旧 `state` 参数不影响范围，已有来源记录随所属学期呈现。
- 时间与教师姓名完整换行。待分班、空位、年级、课程与搜索位于更多筛选，启用条件时提供标记；单列筛选继续位于表头。
- 班级目录保留建班、导入和测试班级管理，使用 `view=directory`。辅助入口保留班级、教师和期次定位，清除独有字段与分页。

本机课评名单修正：`20260920001000_session_review_roster_alignment`。复核使用 `node --experimental-strip-types scripts/class-session-registration-local.mjs --preflight`，再运行 `--check`；校验过程在事务中创建样例并回滚，复用固定身份。`--apply` 仅向已核对的本机隔离库应用已通过检查的同一迁移。
