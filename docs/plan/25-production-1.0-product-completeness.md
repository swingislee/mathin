## 1. 背景与结论

Mathin 当前已经具备较深的学校业务能力：

```text
学生生命周期
课程产品与讲次
班级与排课
课堂与白板
考勤、课消、请假、补课、代课
作业、课评、讲题视频
订单、收款、退款与账户流水
岗位权限与对象作用域
领域事件、审计、学期轴、状态机
私有文件、RLS 断言、备份恢复与离线课堂
```

这些能力使 Mathin 已经不再是原型，也不只是若干页面的集合。

当前距离生产 1.0 的主要差距，已经从“核心业务对象是否存在”转向：

```text
用户能否安全进入系统
机构能否完成初始化并持续配置
学生和家长能否独立完成完整旅程
业务发生后是否有人接、有人知、有人完成
异常情况是否有明确处理和恢复路径
数据、文件、指标和财务数字是否长期可信
管理员是否有支持与修复工具
系统是否经过真实公网、真实设备、真实班级验收
```

因此，本阶段的目标不是继续增加独立业务模块，而是把现有能力连接成一套可以长期运营的完整产品。

生产 1.0 的核心判断是：

> 所有正式开放的能力，都具备正常路径、异常路径、权限边界、责任归属、通知反馈、审计记录、修复手段和真实环境验收。

## 4. 统一成熟度标准

以后每个能力都使用同一尺度验收。

| 等级 | 定义 |
| --- | --- |
| L0 不存在 | 没有数据模型、接口或产品入口 |
| L1 数据预留 | 有字段、表或底层平台能力，用户尚不能完成操作 |
| L2 局部可用 | 有单个页面或接口，可以完成简单动作 |
| L3 基础闭环 | 正常路径完整，具备权限、校验、反馈和审计 |
| L4 运营闭环 | 异常路径、通知、批量操作、修复、管理和历史追踪完整 |
| L5 生产验证 | 经过真实角色、真实设备、真实数据、真实公网和故障场景验收 |

生产 1.0 的规则：

- 核心能力达到 L4；
- 生产运行达到 L5；
- 需要真实课堂或真实用户证明的核心能力，在 RC 试点后达到 L5；
- 未达到发布要求的非核心能力通过 Feature Flag 关闭。

### 6.3 安全规则

- 提升密码最低要求；
- 注册、登录、找回密码和邀请码验证使用统一限流；
- 注册接入 CAPTCHA 或 Turnstile；
- 邀请码支持失效时间、使用次数、适用身份和使用记录；
- 管理员、财务和高权限员工强制 MFA；
- 安全类动作全部写入审计事件；
- MFA 重置、邮箱更换和手机号更换需要二次验证；
- 管理员支持操作保留操作前后状态和原因。

### 6.4 验收

- 新用户可独立完成注册、验证、登录、修改资料、修改密码和找回密码；
- 管理员可安全恢复无法登录的账号；
- 高权限用户未启用 MFA 时进入强制设置流程；
- 同一账户可查看并撤销其他会话；
- 注册脚本和暴力登录测试受到限流与 CAPTCHA 阻断；
- 手机与桌面浏览器均完成真实邮件或验证码链路验收。

- 按监护人 scope 控制费用、视频和成绩可见范围。

### 7.3 门户设计规则

- 门户按学习服务组织，不复刻员工后台的数据表；
- 首页优先展示需要用户采取行动的内容；
- 所有通知深链到具体孩子和具体对象；
- 多孩子切换保留当前业务上下文；
- 内部员工备注不会进入家庭或学习环境；
- 家长和学生看到的是正式发布内容；
- 空状态说明下一步，而不是只显示“暂无数据”。

### 7.4 验收

- 学生能完成“登录→查看下一节课→进入课堂→完成作业→上传视频→查看教师反馈”；
- 家长能完成“登录→切换孩子→请假→查看补课→查看课后反馈→确认已读”；
- 家长 scope 差异通过真实双监护人账号验收；
- 390px 手机、iPad 和桌面浏览器均可完整操作；
- 弱网和页面刷新后保留关键状态。

## 24. 执行纪律

1. 每个 `R1-*` 独立拆分施工任务和提交；
2. 开工前核对远端 `main`、数据库 migration 账本与工作树；
3. 新页面先进入 `dashboard-routes.ts` 或对应门户路由合同；
4. 新业务动作统一使用 zod、`ActionResult`、服务端权限复核和领域事件；
5. 新敏感表必须先设计 RLS 与真实越权断言；
6. 新长任务默认进入后台任务队列；
7. 新文件类型默认进入统一文件治理；
8. 新正式数字必须登记指标口径；
9. 新状态必须定义合法跃迁、责任人和恢复动作；
10. 新用户可见结果必须定义发布、通知和已读；
11. 新高风险动作必须定义幂等、事务、审计和修复；
12. 所有文案同步更新中文与英文消息；
13. 控件优先复用现有 shadcn 和共享原语；
14. 每项完成后运行目标测试、`lint`、`typecheck`、`messages:check` 和必要的生产构建；
15. 涉及路由、权限、Storage、数据库或生产环境时增加对应自动化断言；
16. 施工记录必须写实际实现、偏差、验收数字和遗留项。

## 25. doc 25 自动审计方向

新增 `scripts/verify-doc25-production-completeness.mjs` 与 `pnpm doc25:audit`，逐阶段增加规则。

建议检查：

- 正式开放功能必须登记 Feature Flag 和成熟度；
- 账户设置、学生门户、家庭门户存在稳定路由；
- 注册和安全动作使用统一限流；
- 高权限角色 MFA 策略存在；
- 新业务状态有状态机或集中 RPC；
- 新敏感写操作落领域事件；
- 新后台长任务进入统一任务队列；
- 新上传类型登记文件策略；
- 新报表引用指标字典；
- 新对象链接命中 canonical 路由；
- 新用户结果具备发布或通知路径；
- 核心 E2E 用例在 CI 中登记；
- 生产配置不保留开发回调、自动确认或测试凭据。

自动审计负责防止结构性回退，真实产品完整性仍由浏览器 E2E、角色验收和 RC 试点共同证明。
