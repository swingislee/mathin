## 1. 已确认范围与协作分工

产品负责人本轮明确：

1. **先拆筛选弹层，主表保持紧凑。** 一个视觉列中的时间、地点、老师等字段，在弹层内横向分栏；有排序含义的字段各有独立升／降序 SVG 按钮。
2. 日期筛选支持年／月／周／日聚合，最细为日；当前年份隐藏年份，其他年份保留；近期日期补充星期。
3. 测评分数表达统一，分清分数、等级与答题进度。
4. 姓名、手机号等几乎每条不同的值使用检索／排序，不逐个列成枚举分组；同样检查长备注、拼接摘要、数量等字段。
5. 当前业务模型基本确定。历史值有确定对应关系的适配到现有标签；不能确定适配的保留原文到备注，保持业务字段为空，**不扩充现有业务标签体系**。
6. 协作对象为已有任务“解析飞书多维表格结构”，不另建 agent。

分工已经通过任务消息对齐：

| 本任务 | 五张跟进主表的逐列审计、共用组件其他消费方检查、字段规则与实施批次；仅编辑本文 | 接收历史任务的正式字段、来源和缺失值合同，再规划 UI 接入；不并行改其业务文件 |

## 2. 结论：问题分布在四层

当前组件把不同类型的字段都压成“一个选项列表、一个选中字符串、一个排序值”。历史导入又向这些字段提供了旧表达和缺失信息，因此统一弹层外观需要同时明确：

| 层次 | 本轮定位 | 改造结果 |
| --- | --- | --- |
| 字段含义 | 一个视觉列混合身份、时间、人员、状态、数值和备注 | 显示列与逻辑字段分离；每个字段声明类型、来源和允许操作 |
| 查询正确性 | 同列条件互相覆盖，部分先分页后筛选，部分显示值与排序值不是同一事实 | 独立字段条件、正确时间／数值排序、完整查询范围与一致的分页 |
| 展示与操作 | 长菜单、一次选择就关闭、枚举姓名／手机号／整段备注 | 类型化控件、横向字段分栏、可连续组合条件、紧凑反馈 |
| 历史数据适配 | 兼容旧值进入正式选项、原分缺少满分依据、部分业务记录未完整投影 | 使用现有标签白名单；原文进备注；缺失依据保持缺失，原始档案可追溯 |

### 3.1 两个最小复现

本轮在内存中编译现有 `useDashboardTableView.ts`，仅调用它导出的两个纯函数；夹具按现有测评字段定义构造，不涉及真实学生：

| 输入 | 现有输出 | 应有合同 |
| --- | --- | --- |
| 两条成绩分别为 `18/20`、`18/100`，现有键均为 `score:18` | 选项仅剩 `18/100`；选中后匹配两条 | 表达、筛选与排序都携带量尺；不以裸分数文本合并成绩 |
| 两条历史日期分别为 `2024-09-07`、`2025-09-07`，`scheduledAt` 均为空 | 选项仅剩后一日期；选中 `time:` 匹配两条 | 历史发生日直接生成稳定日期键，空计划时间不替代发生日 |

已存在且应保留的正确行为：共享 hook 空值双向末尾、同值稳定排序；学生状态和测评队列已有显式顺序；部分页面人员已使用 ID；分班已有同一候选班级关联判断。改造不把这些能力当作缺失重写。

## 4. 先按字段类型决定控件

分类依据是字段业务含义，不是“这页恰好有多少个不同值”。即使当前只有两个学生，姓名也不退回枚举；老师／课程可以检索选项，但仍按实体筛选。

| 字段类型 | 适用字段 | 筛选／检索方式 | 排序依据 |
| --- | --- | --- | --- |
| 身份短文本／编号 | 姓名、手机号、外部学号、批次 ID、来源行号 | 文本检索／准确查找；来源行号支持数字定位；不列全量值 | 姓名按本地化文本；电话／编号按字符串，保留前导零；行号按数值 |
| 有限业务枚举 | 当前状态、联系结果、类型、正式等级、缴费方式 | 现有白名单选项；同字段多选 OR | 复用该业务字段已确认的顺序；没有等级意义的类别按标签文本，明确不是能力排名 |
| 关联实体 | 老师、负责人、班级、课程、试卷版本、活动 | 按 ID 选择，可检索名称；同名提供必要的可见上下文 | 名称或字段明确约定的业务顺序，ID 只作稳定兜底 |
| 历史实体表达 | 未匹配到实体的老师／班型／地点原文 | 进入备注检索；保留来源追溯；不临时创建人员或标签 | 不把无法匹配的原文充作现有实体的排序值 |
| 日期／时刻 | 采集、安排、发生、最近联系、下次联系、缴费、真实更新时间 | 年／月／周／日日期桶及日期范围；完整规则见 §6 | 对应事实的日期／时间值，不使用格式化文案 |
| 周期课表 | 星期、上课起止时间 | 星期与时段分栏；若筛实际课次日期，使用实际 session 日期 | 星期序号、起止分钟；不比较整个课表摘要字符串 |
| 数值／金额 | 分数、金额、期数、联系次数、参与人数、来源次数 | 等于／至少／至多／区间；需要时加“有值／无值”条件 | 实际数值；金额明确币种；成绩遵守 §7 的量尺条件 |
| 长文本 | 备注、学习观察、家长顾虑、结论、建议、错误明细 | 关键词与有无内容；默认不提供整段文本枚举或无业务含义的字典排序 | 若确实需要排序，单独提供“更新时间”等真实字段 |
| 聚合／多值事实 | 多老师、多次联系、多季节、多个目标班级 | 明确筛单项、任一项还是同一关联记录；摘要只负责显示 | 必须选明“最近一次／最早一次／数量”等含义；不直接 `join()` 排序 |

补充约束：

- “有值／无值”“原文检索”是查询操作，不写入业务标签，也不新增“历史未知”测评等级。
- 状态、身份确认、重复线索、来源方式、意向、成绩等级各归独立字段；混合摘要不能反向成为权威状态。
- 备注检索遵守既有权限范围；候选项、日志、导出均不扩大人员可见性。脱敏手机号继续脱敏，不从排序或选项泄露底层值。
- 查询控制只更新视图；不触发跟进登记、身份确认、试卷选择、排课、分班或自动保存业务动作。

## 6. 日期合同

### 6.1 值、精度与显示分离

- 每个日期字段明确事实类型：计划日期、发生日期、最近联系、下次联系、缴费日期或真实更新时间。显示／筛选／排序指向同一事实。
- 日期键使用稳定 `YYYY-MM-DD` 或日期区间；显示文案由 locale 与机构时区生成。语言切换、跨年、修改显示格式都不改变已选范围。
- `date` 表示业务日，`datetime` 表示带时区解释的时刻；历史只有月／年或无法确定日期时保留原精度／缺失，原文进入备注，不补造月初或当天。
- 复用机构时区和 [schedule.ts](../../src/features/school/schedule.ts) 的日历边界函数；其 `startOfWeek` 已按周一开始。带时刻的范围采用开始包含、结束不包含；跨日计算用日历运算。日期字符串不通过截 UTC 时间戳代替机构日。

### 6.2 年／月／周／日聚合

1. 日期字段顶部切换年、月、周、日；聚合的是日期筛选选项，本批不对主表行新增分组汇总。
2. 年、月、周选项对应完整范围，日是最细过滤单位；主表在必要时仍可显示 `HH:mm`，不新增分钟级筛选选项。
3. 周按周一至周日，使用周起始日作稳定键，以日期范围显示。跨月／跨年的周保持完整，不硬塞进某个月再截断。
4. 手动起止日期与日期桶使用同一种范围合同；尚未填完或非法的范围不提交查询，清空范围与清空其他字段分开。
5. 切粒度保留当前已选的实际日期范围；只有用户选择新日期桶才变更范围，避免切换展示就扩大查询。
6. 已填／未填可作为缺失值查询条件；“无安排”和“历史日期未知”继续由业务上下文解释，不生成新的业务标签。

### 6.3 显示规则及本计划推荐默认值

| 场景 | 中文示例 | 英文示例 |
| --- | --- | --- |
| 当前年日期 | `9月7日` | `Sep 7` |
| 其他年日期 | `2025年9月7日` | `Sep 7, 2025` |
| 近期日期 | `9月7日 周一` | `Mon, Sep 7` |
| 需要时刻 | `9月7日 周一 14:30` | `Mon, Sep 7 14:30` |

“近期”推荐先取机构当天前后各 7 个日历日，星期作为同一紧凑日期字段的附加显示，不新增主表列。该窗口是待评审默认值；日期完整年份、时刻和时区保留在可访问说明／详情中。12／24 小时制本批统一为 24 小时；不影响日期键。

周期课表另行使用“星期＋时段”，不从“周六上午”等历史文字推造实际课次日期。需要查看实际发生时间时使用可追溯 session 日期。

## 7. 分数与历史标签合同

### 7.1 分数表达

推荐默认显示：有可靠满分依据时 `实得分 / 满分`，例如 `18 / 20`；缺少满分时显示 `18 分` 并标明满分未记录。这个默认值待产品评审，不擅自统一折算百分制。

- 统一成绩读取模型至少区分：实得分、满分、量尺／试卷版本、结果来源、是否正式结果、依据。由服务端判断依据，UI 不因有 `questionSummary` 就自行补满分。
- 逐题结果可使用其冻结试卷版本的真实满分；快速登记只有在明确记录评分口径时才可带满分。旧导入无数值依据就保持空值。
- 若原文明确为成绩 `18/20`，可在来源核对后保存两项；先排除它实际上是答题进度、日期或其他计数。不能从等级或备注语气反推分数。
- 当前写入合同为整数，本批沿用，不顺带扩大到小数。`0` 是有效分数；空值与零分分开；满分零／负数、得分超过满分保留核对提示，不静默修剪。
- 分数、等级、答题进度、正式状态分开；未正式完成的过程分数不混入正式成绩的排序／范围筛选。
- 原分比较先限定同一量尺／可比试卷。需要跨满分按得分率排序时显式选择“得分率”，仅对满分可靠的记录计算；得分率不宣称等同于跨卷能力排名。未知满分不按零处理。
- 表格、弹层、详情、学生 360 和新报告消费同一显示合同；既有冻结报告保留原始快照，其修订遵循既有更正机制。

### 7.2 现有等级白名单与旧表达

已与历史任务确认当前白名单是：**X+、G+、A、A+、S、C**，以 `ASSESSMENT_BANDS` 为权威，不从导入值生成新等级。

| 历史输入 | 业务字段处理 | 原文处理 |
| --- | --- | --- |
| A、A+、S、C、G+、X+，且来源字段确为测评等级 | 映射到对应现有编码 | 保留来源档案与映射依据 |
| 只涉及已确认的空白／大小写／全半角差异 | 使用明确的规范化规则后精确匹配白名单 | 保留原值，映射规则可审计 |
| 未达 A／below_a | 等级留空；不猜测为 X+、G+ 或 C | 以“历史测评原文：未达 A”保留在备注 |
| 多个等级混写、含否定／条件、自由描述、未知缩写 | 没有可唯一确认映射时等级留空 | 原文进入备注；不创建新的“其他”业务标签 |

历史适配不仅改下拉框：导入器、读取投影、主表筛选、行下编辑、历史修订表单、学生 360 与报告输出需要使用相同边界。旧字段在兼容读取期间可以解析，但不会重新作为当前业务选项流出；原始档案和冻结证据保留。

### 7.3 协作回传的覆盖问题

历史任务在 2026-09-07 回传并获用户允许共享的汇总：到访来源 848 行，708 行有姓名，343 行有思维测评等级；当时仅 77 行匹配 Student、61 行匹配 Lead，原业务投影只处理 Student；本机当时有 63 条导入测评。另有秋季来源 166 行，165 行有姓名，其中 155 行明确在读、10 行待报，但此前仅形成候选。

这些是另一任务正在核对的来源／身份／投影覆盖统计，分母并不等价，不能直接相减认定应补多少条业务记录。它们表明：即便筛选查询全部正确，未投影的业务事实也不会凭空出现。历史任务负责补齐确定映射与操作隔离；本任务将“投影覆盖”与“筛选漏项”分别验收。分数／满分来源依据仍等待该任务最终核对，不以这些计数推定。

## 8. 共享查询与弹层结构

### 8.1 显示列与逻辑字段

建立有类型的字段定义：`fieldId`、类型、值来源、允许的查询操作、排序值、缺失策略、实体关联范围。视觉列只负责指定要在弹层展示哪些字段。

以测评安排列为例，桌面弹层结构为：

| 日期 ↑ ↓ | 地点 ↑ ↓ | 老师 ↑ ↓ |
| --- | --- | --- |
| 年／月／周／日 | 检索已有地点 | 检索已有老师 |
| 日期桶／范围 | 地点选项 | 人员选项 |
| 清除此字段 | 清除此字段 | 清除此字段 |

有额外来源信息时，在对应字段内给出明确说明／条件，不增加占满屏幕的长串表单。复用现有 shadcn Popover、Button、Command 等组件；网格随可用宽度限制列宽及独立滚动。窄屏使用字段切换视图且保留条件，不把整个页面撑宽。

### 8.2 查询及排序状态

- 同一字段多个值 OR；不同字段 AND。姓名／电话关键词、枚举、日期范围、数值范围均使用自己的有类型条件，而不是编码到一个带前缀的字符串。
- 对数组关联记录显式声明语义：筛“某老师且某时段”时应命中同一个班级／课次；沟通的“某渠道且某结果”按同一事件判断。若业务明确要求任意历史事件，界面和谓词都明确说明。
- 各字段都有独立排序能力；默认采用一个主排序字段，点击另一字段替换主排序。重复点击当前方向清除排序；清除排序不清空该字段筛选。本批不隐式引入多重排序优先级。
- 筛选标记与排序方向分别可辨，SVG 有可访问名称／选中状态；多字段排序语义通过说明明确，不只用颜色表达。
- 选值与排序后弹层保持打开，支持连续组合；Escape／外部点击关闭。字段级清除、整列条件清除、全部条件清除明确各自范围。
- 选择枚举可即时更新查询；复合日期／数值范围完整校验后提交。服务器查询取消过期请求，旧响应不覆盖新条件；输入检索可防抖。
- 不恢复顶部数据数量摘要；需要提示当前条件时采用字段名和值，数量与页数保留在既有紧凑分页位置。

### 8.3 查询范围与分页

目标执行顺序：权限和业务范围 → 当前／历史、主工作队列及检索 → 字段条件 → 排序 → 分页。候选项在同一权限／业务范围和其他字段条件下生成，对当前字段自身条件作适当放宽以便改选；已选但当前无匹配的值保留并可清除。

- 服务端分页页面把字段条件与排序送到读取层，并在分页前执行；历史与当前合并视图明确统一行身份和分页范围。不能通过无限加载全量记录到浏览器来冒充完整查询。
- 数据库查询字段、操作符和排序白名单化；派生字段使用已有可验证读模型或受限投影；遵守 RLS，不通过候选项泄漏不可见记录。
- `count`、页数、当前页行数属于同一查询条件；筛选变化重置到有效页。稳定排序追加稳定行 ID，避免跨页重复／遗漏。
- 完整读取的本地列表可以复用同一纯谓词；存在读取上限的列表标明实际范围，并在需要完整查询时迁入服务端适配。核对相关加载器上限，不默认为“已全部加载”。
- 分阶段迁移时仍为当前页的页面继续明确标注“当前页”，不得提前标成全量筛选。分页页面的全量筛选验收必须包含第 2 页之外的匹配记录。

### 8.4 偏好与兼容迁移

为查询偏好增加版本，继续按账号／页面隔离。旧字段能唯一映射才迁移；依赖旧显示文案、已撤销枚举字段或不兼容历史标签的条件清除，并给一次简短解释。保留无关页面偏好，不清空用户其他设置。

共享组件先提供有类型的新接口与明确的旧接口适配范围；§5.2 全部消费方迁移后再移除旧实现。`LeadPoolTable` 的自维护过滤器单独纳入，避免形成第二套长期规则。
