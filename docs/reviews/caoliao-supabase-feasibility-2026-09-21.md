# 草料作为家长预约入口并接入 Supabase：可行性审查

> 日期：2026-09-21。状态：源码与公开文档评估，未选型、购买、配置或实施。
> 当前需求：家长查看线下课程／活动、预约报名、查询参加记录；无缴费，作业暂缓。继续保持已有 Supabase Auth 账号 UUID，不在外部报名到达时自动注册账号。
> 本轮读取了公开帮助、OpenAPI V2 文档及公共 OpenAPI JSON schema，未调用需密钥的业务接口，也未访问用户的草料账号或生产数据库。旧草料页面、版本权益、数据量和身份授权状态尚未核验。

## 1. 结论与方案选择

草料适合承担活动展示、报名收集及其原生记录查询，通过适配层将数据交给现有后台。它能减少小程序页面与表单开发；若要求同一界面实时显示 Supabase 全部课程记录、多子女授权、精确名额和原账号自动登录，仍需自建相应业务能力。

| 路线 | 前端与数据位置 | 开发及维护判断 | 适用范围 |
| --- | --- | --- | --- |
| 草料现有小程序／无标识小程序 + 原生表单 + Webhook | 表单及原始记录保留在草料，受控导入 Mathin | 相对较低；需接收、回查、映射、去重及异常处理 | 推荐作为报名入口的验证路线；原生历史仅代表草料内记录 |
| 草料企业专属小程序 + 同样的原生表单 | 使用自己的 AppID／名称，业务仍由草料托管 | 在上一条基础上增加认证、备案与发布协作；不增加任意改代码能力 | 需要自有品牌入口，但接受草料的组件及流程 |
| 草料企业专属小程序 + 自建 H5 家长页面 | 草料提供入口，H5 经现有服务访问 Supabase | 中至高；页面、身份、权限、预约均仍需我们实现，还需核验身份桥接 | 更接近“外层包裹”，能复用网页技术，但节省的主要是壳与发布操作 |
| 自建轻量家长小程序 | Supabase 作为业务主数据，自建家长客户端 | 前期工作更多；业务规则及后续迭代最可控 | 全量家庭历史、多监护人、多子女、实时预约为长期核心时 |

以上为工程判断，不是已联调结果。草料官方说明专属小程序不提供源码、不支持客户自行改代码，内容及表单仍在草料维护；系统集成另行开发。[专属小程序说明](https://cli.im/help/account-and-purchase/purchase-exclusive-mini-program)

## 2. 已核实的能力及限制

- **入库通道可行。** Webhook 支持新记录、编辑、审核和处理进度事件，以 JSON 推送到公网 HTTPS 接口。官方要求 5 秒内返回 HTTP 200，异常最多重试 5 次。设计应先持久接收再处理，并安排补偿回查。[Webhook 文档](https://cli.im/help/integration-and-connection/data-api/webhook-webhook-guide)
- **不能用“自有数据库”直接连接 Supabase。** 草料该功能只支持 MySQL 5.7，并自行建表及覆盖同步；本项目使用 PostgreSQL。应走应用层接口，不向草料开放生产数据库账号。[自有数据库说明](https://cli.im/help/integration-and-connection/data-api/private-database-guide)
- **不能断言草料完全不支持写入。** 老数据推送说明仍称不能外部写入，但当前 V2 文档及公共 `https://open.cli.im/openapi.json` 已有 `record/addRecord`、查询记录和凭证核销接口。V1 文档也列有模板子码创建／编辑。它们支持部分回写，不能等同任意双向同步或直接替换草料存储。[V2 接口索引](https://cli.im/open-api/openapi/v2/overview.html)、[添加记录](https://cli.im/open-api/openapi/v2/api/record/record-add-record.html)
- **记录写入不等于家长身份贯通。** 当前 `addRecord` 请求只接受 `code_id`、`tpl_id`、`fields`，公共 schema 未提供指定登录家长身份的字段；API 写入还不执行表单前端的必填／显隐规则。把旧课程数据写成记录后，能否正确归属家长“我填写的记录”，必须另行验证，不能以填入姓名或手机号代替。[添加记录说明](https://cli.im/open-api/openapi/v2/api/record/record-add-record.html)
- **H5 包裹有产品依据。** 草料专属小程序可绑定企业自有业务域名，微信 `web-view` 可承载网页。较旧教程只提行业专属版，而新的 2800 元增购说明也列出域名能力；购买前应确认该方案实际开放 H5、授权回跳域名和所需登录桥接，不能默认所有低价方案支持完整单点登录。[草料网页承载说明](https://cli.im/help/operation-tutorials/open-url-in-mini-program)、[微信 web-view](https://developers.weixin.qq.com/miniprogram/dev/component/web-view.html)

## 4. 建议的数据与身份边界

建议先验证“草料报名申请 → Mathin 接收与核验 → 待确认记录 → 员工确认后形成正式预约”。Supabase 中的正式课程、孩子、监护关系与既有账号继续作为业务依据。草料保留原始表单，应用保存必要外部编号和状态映射，按用途与权限同步资料。

### 4.1 身份

草料登录态、平台 `auth_id` 和其小程序微信身份不是 Supabase 会话。不同开放平台下的微信身份也不能直接互换；专属 AppID 属于我们，不证明草料已提供可验证的登录信息透传。[草料 API 鉴权](https://cli.im/open-api/openapi/v2/auth.html)、[微信 UnionID](https://developers.weixin.qq.com/miniprogram/dev/framework/open-ability/union-id.html)

普通报名可以先形成业务申请，无需新建 Auth 用户。手机号或姓名只能用于提出匹配候选；匹配旧账号、建立监护关系和开放历史记录之前，仍需可信的本人核验。H5 若不能获得受信的单次登录凭据，就应明确保留首次原账号核验，不能承诺从草料跳入后自动登录。账号设计继续遵守[微信身份审查](wechat-login-readiness-2026-09-18.md)。

### 4.2 名额与状态

草料能按微信用户限制填写次数及每个二维码的填写总数；这些限制不能自动覆盖同一课程在员工端、草料和其他入口的共同名额。[填写规则](https://cli.im/help/forms/form-design/fill-settings/fill-restrictions)

若 Supabase 掌握最终名额，草料提交成功只应表示申请已收到，由后端统一确认；两边分别显示“成功占位”会产生超额风险。若要求即时确认、改期、取消即释放名额，应由一个可信业务接口统一执行，倾向自建 H5 或轻小程序。

### 4.3 回显与迁移

草料内查询自己提交的报名较容易；Supabase 中原有课次、老师补录、另一位监护人操作和跨孩子历史，属于额外集成范围。需要证明记录归属与查看权限，不能做公开可猜链接或只按手机号查全家历史。活动基本信息可评估复用模板子码 API；完整原账号家庭中心不作为草料原生能力默认成立。

保留外部系统、表单、记录与内部业务 ID 的明确映射，避免依赖显示名称；接入应支持重复通知、乱序更新、限额、断线补偿及退出草料后的数据迁移。初期不将 Supabase 已有敏感历史全量复制进草料。

## 5. 仓库复用与尚缺部分

| 文件 | 现状与接入含义 |
| --- | --- |
| `src/app/api/integrations/webhooks/[provider]/route.ts` | 已有接收、HMAC 验证与回执框架；要求 Mathin 自定义签名头，返回 202。草料公开协议未列出相同签名，且要求 200；不能把 URL 填过去就认为兼容 |
| `supabase/migrations/20260728000300_r1_platform_runtime.sql` | 有 `webhook_receipts`、任务队列及重复回执约束，可复用可靠接收基础；适配成功后的重复回调应按草料协议确认，避免持续重试 |
| `scripts/r1-job-worker.mjs` | `webhook.receive` 当前返回 `PROVIDER_NOT_IMPLEMENTED`，还没有入站业务适配器 |
| `src/features/school/activity-actions.ts` | `bookActivityAction` 调用现有预约 RPC，但要求员工 `activity.register` 权限 |
| `supabase/migrations/20260902000400_school_ops_phase2_node_worktables.sql` | `book_activity` 校验当前用户权限与学生范围，并锁定活动检查容量；外部接收器不能借用员工身份或直接绕过这些业务约束 |
| `src/features/school/activities.ts`、`src/features/school/customer.ts` | 有活动、报名、监护及课次查询基础，需按家长可见字段和权限复用 |

本轮未发现草料专用连接器。建议新增小范围适配而非另造整套任务系统。草料入口若无可验证签名，可将通知作为待核验提示，再通过服务端 API Key 向草料回查真实记录及所属表单；先验证编号可回查、权限和限流，再决定接口。不能给第三方页面 Supabase service-role 密钥，不能将未核验回调直接变成账户授权或正式预约。

## 6. 选择前应完成的小范围验证

1. 在用户已有草料账号确认旧页面、当前版本、Webhook 与 OpenAPI 权益；选择一张不含真实儿童资料的演示表单，明确测试数据授权。
2. 验证提交、编辑、取消／状态变化能可靠同步，重复通知不会产生重复报名；核对 1000 条计量、超限行为和历史补拉。
3. 分别验证“原生表单中的本人记录”和“Supabase 历史课程记录”，确认后者采用原生镜像还是自建家长页。
4. 如考虑专属小程序 H5，先要求厂商确认域名、OAuth 回跳、微信身份可验证透传及代码扩展边界；用现有账号完成一次登录与记录查询，再评估购买。
5. 如实核对实际活动／课程和小程序类目。草料能减少开发及平台运营工作，不能作为实际培训业务资质或审核范围的替代；专属小程序仍需自己的认证、备案和审核。

以上是后续验证建议，本轮没有创建表单、购买服务、发出咨询或写入业务数据。文档完成引用检查与差异检查，不代表接入已经可用。
