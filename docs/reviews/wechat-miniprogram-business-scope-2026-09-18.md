# 微信小程序业务范围与校外培训风险审查

> 审查日期：2026-09-18。代码基线：`05cae0f9`；开始审查时工作树干净。
> 状态：仓库与公开规则审查完成，本文为产品范围建议，尚未实施或提交微信审核；不改变现有产品规划、生产功能和 Gate 状态。
> 证据范围：本地源码、产品规划、微信官方文档、教育部及其他主管部门公开文件。没有查询生产数据、实际收费合同、办学证照或小程序后台。
> 待补充事实：业务所在省市、服务年龄段、实际授课与收费主体。以下按仓库已经包含的中小学数学及家长／学生服务进行审慎评估，不据此认定现实业务违法。

## 1. 产品建议与适用边界

第一版建议定位为面向教师使用的数学工具，提供独立教具、个人场景保存和原账号绑定。导航可为“教具 / 我的场景 / 账号”。用户完成的是操作模型、准备演示和管理自己账号，不在小程序中完成报名、接受课程教学、提交作业或购买课时。

这一建议成立的前提是实际功能、人员服务、合同收费和宣传方式都与工具用途一致。如果公司实际上自行面向中小学生组织数学培训，缩小小程序范围只减少该入口承载的业务，不能解决培训业务本身的资质问题。网站、线下课堂、微信群及小程序需要按同一实际业务核对。

教育部的分类鉴别规则综合考察培训目的、内容、方式和评价。数学在学科范围内，工具展示数学知识本身不等于举办培训；按年级组织授课、练习与学习评价，则需要结合运营事实判断。不能仅通过“思维训练”“素质拓展”等名称推定为非学科类。[分类鉴别指南](https://www.moe.gov.cn/srcsite/A29/202111/t20211112_579358.html)

《校外培训行政处罚暂行办法》第十八、十九条分别涉及变相开展学科类培训及明知违法仍提供相关网络服务的情形。因此，将付费课堂转到群聊或网页、把课程费并入其他收费，都不是本报告建议的范围控制方式。[教育部令第 53 号](https://www.moe.gov.cn/jyb_xxgk/xxgk/zhengce/guizhang/202309/t20230912_1079802.html)

“双减”意见包含不再审批新的面向义务教育阶段学生的学科类校外培训机构等要求。当前没有审批文件，不能把“先开展数学培训、以后补证”作为默认产品路线；非学科类培训同样需要核对相应准入条件。[“双减”意见第四部分](https://www.moe.gov.cn/jyb_xxgk/moe_1777/moe_1778/202107/t20210724_546576.html)

## 3. 建议的第一版体验

| 页面 | 用户完成的事情 | 范围控制 |
| --- | --- | --- |
| 教具 | 自主操作分数、行程和几何模型；调整参数、恢复起点 | 不分配老师、不排课程、不发学习任务、不形成儿童学情报告；基础试用不以手机号授权为前提 |
| 我的场景 | 保存和重新打开本人准备的演示场景 | 登录后使用；首版仅个人保存，不附带班级、学生名单、作业发布或家长分享 |
| 账号 | 登录已有账号、绑定微信、按需授权手机号、查看绑定状态和隐私说明 | 微信身份与手机号用途分别说明；不因授权创建新 Auth 用户，不把账号号码自动写入招生线索 |
| 使用帮助 | 解释工具操作和真实可用范围 | 帮助不承接课程咨询、试听邀约或收费导流 |

可用的产品介绍草案：

> Mathin 教具为教师提供分数、行程与几何模型的交互操作、个人演示场景保存和账号管理功能。

这段文案只在功能确实按上述范围交付后使用。范围说明不能代替实际限制；现有工具若保留题序、学生提交、课堂同步等能力，需要逐项确定哪些组件进入小程序。

首版建议先覆盖已有授权工作人员的账号绑定，家长和学生身份进入后续单独评估批次。这是缩小首发范围的建议，尚未修改现有网站用户权限。对外提供免费数学阅读可以另行评估；免费、邀请码或用户很少都不是对培训性质的自动豁免。

游戏、公开笔记／评论、完整课程包与视频内容不属于本次登录和工具的必要范围，首版不一并搬入。是否后续提供这些服务，应分别核对内容、类目和运营条件。

## 4. 需要真正落实的产品与技术边界

1. **入口一致。** 小程序名称、介绍、首页、分享卡片、客服答复和手机号说明都描述真实工具用途。用户不会从“保存场景”继续进入“预约老师—购买课程—开课”的链路。招生宣传与课程导流不混入工具帮助。
2. **提供专用页面。** 复用数学内核和场景合同，单独组装小程序视图；不将通用 `/dashboard`、家长首页、学生首页或课堂页面整体装入 `web-view`。仅隐藏菜单不能落实范围。
3. **限制可调用服务。** 未来的小程序接口仅暴露被选入的工具、本人场景和本人账号操作。采用服务器可信的会话／权限校验，不能把可伪造的 User-Agent、Referer 或 `isMiniProgram` 参数当边界。
4. **共享身份不等于缩小授权。** 如果向小程序直接发放现有 Supabase 会话，原有 RLS 仍按该用户全部权限生效。实施时需明确是否采用服务端代理及受限客户端会话；若需要技术上限制客户端可用能力，应在可信服务端落实，而不是宣称“少几个按钮就完成权限隔离”。保持原 `auth.users.id`，不为实现边界复制账号体系。
5. **不通过外围流程恢复培训链路。** 外部网页、二维码、订阅消息和客服入口也纳入本次范围核查。账号绑定仅返回已核验的绑定结果或授权入口，不提供任意业务 URL 跳转器。审核与正式用户使用同一功能范围。
6. **保留既有正式事实。** 本次审查没有删除或改写课程、学生、班级、考勤等数据。若现实服务存在资质缺口，另行核对实际服务与整改方式；把功能移到员工后台本身不证明相关经营活动合规。

微信运营规范要求实际服务、简介与类目一致，核心功能在首页体现，也限制过于简单的功能。因此不建议做一个仅获取手机号的空壳小程序；教具与个人场景应当提供真实独立价值。具体提交内容须如实反映可用能力。[微信小程序运营规范 §3、§5](https://developers.weixin.qq.com/miniprogram/product/)

## 5. 认证、类目和备案分别核对

用户提供的“校外培训—审批文件—省级教育部门”条目与腾讯云 ICP 备案前置审批材料说明一致。这是特定业务的前置审批要求，不能直接推导所有数学内容都需要同一张许可，也不能据此认定某类软件一定豁免。[腾讯云前置审批材料](https://cloud.tencent.com/document/product/243/111391)

2026-09-18 读取微信**境内非个人主体**类目表，存在“教育服务—教育装备”“工具—办公”“工具—计算器”等范围。独立教具可将“教育装备”作为沟通候选，具体是否覆盖本项目的数字交互工具，需提交实际功能说明向微信确认；办公／计算器只适用于实际符合定义的服务。不能因为某行资质栏为“/”就把培训、教学视频或课程销售放进去。非学科类培训机构和在线视频课程另有资质要求；未采用旧转载表里的“教育信息服务”等名称替代当前后台选择。[微信服务类目表](https://developers.weixin.qq.com/miniprogram/product/material.html)

| 事项 | 本项目需要确认的内容 |
| --- | --- |
| 企业注册验证、微信认证、开放平台认证 | 证明主体或开通平台能力，不等于获得开展培训的许可；认证进度沿用前一份登录审查的待确认状态 |
| 小程序服务类目 | 根据最终真实功能选取，由微信审核；工具定位不保证某一类目必过 |
| 工信部门 APP／小程序备案 | 独立核对；涉及教育等互联网信息服务时，还可能需要相关主管部门同意文件，实际提交要求向属地通信管理部门及平台确认 |
| 教育移动应用备案 | 教师工具仍可能落入教育移动应用范围，不能仅因没有学生端就排除；按适用性与平台现行办理路径核对 |
| 校外培训准入 | 由实际授课对象、内容、形式和运营主体决定；与上述认证、备案分别判断 |

工信部 APP 备案通知明确覆盖小程序分发情形，并对从事教育等互联网信息服务的主办者提出相关文件要求。[工信部信管〔2023〕105 号](https://www.miit.gov.cn/jgsj/xgj/wjfb/art/2023/art_dd783a581c9644a4aee10afa582811db.html)

教育移动应用备案办法将面向教职工、学生、家长的教学管理和学习应用纳入其定义；第十条规定小程序、企业号等平台第三方应用统一向平台提交备案信息，再由平台共享给教育部。应确认当前微信入口如何落实该要求，不把它误述为所有小程序都必须重复单独走省级申请。[教育移动应用备案管理办法第二、九、十条](https://www.moe.gov.cn/srcsite/A16/s3342/201911/t20191122_409333.html)

如果未来实际转为向其他机构提供软件服务，需要核对实际授课方、合同、收费和责任分工；合作机构的许可应覆盖其服务内容及方式。合作不等于出借许可证，也不能让软件方实际授课后仅在说明中自称工具提供者。

## 6. 微信与手机号接入继续复用原方案

技术选型、社区实现、Supabase 无邮箱绑定缺陷与已有文件清单继续以[微信登录接入审查](wechat-login-readiness-2026-09-18.md)为依据，本报告不重复引入另一套认证系统。

- 微信身份绑定前证明原账号归属；保持一个 UUID、一个 profile；未知微信不默认创建账号。
- 手机号授权发生在用户明确选择绑定号码时，说明用于账号登录／绑定；不默认同步为家长联系方式或营销线索。
- 取消手机号授权时，保留不依赖号码的基础工具功能和已有可用登录方式。个人信息应符合必要性，不能为工具试用强制索取无关资料。[应用程序信息服务管理规定第十二条](https://www.cac.gov.cn/2022-06/14/c_1656821626455324.htm)
- 若以后开放儿童使用或儿童档案，手机号授权不能替代监护关系核验、监护人同意和儿童专门规则。不满十四周岁未成年人个人信息具有专门保护要求。[个人信息保护法第二十八、三十一条](https://www.npc.gov.cn/npc/c2/c30834/202108/t20210820_313088.html)

## 7. 可执行的后续顺序

1. 补齐省市、年龄段、自营培训／软件服务和收费关系事实。对数学培训分类或准入存在疑问时，向属地教育主管部门提交真实课程及业务说明，取得可留存的答复；涉及通信备案时同步核对相关材料。
2. 产品负责人确认第一版是否采用“教具 / 我的场景 / 账号”，以及账号绑定的首发用户范围。确认后再形成具体小程序路由、接口和内容清单。
3. 向微信提交这份真实功能说明及可用演示，确认数字教具类目、认证、备案与手机号权限；保留反馈。本文仅准备方案，没有代发咨询或申请。
4. 按现有组件拆出最小客户端，先落实账号绑定、专用页面和可信服务端边界，再做小程序运行时适配。范围核验包含直接链接、分享、客服、消息跳转及未授权接口，不只看首页。
5. 机器检查、开发端可用、产品人工验收、平台审核及业务资质核对分别记录；任何一项通过都不替代其他项。
