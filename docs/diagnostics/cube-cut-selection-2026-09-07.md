# 立方体结构切割选择诊断 · 2026-09-07

状态：原因核查完成，切割运行逻辑尚未修订。产品负责人反馈“选不中”“选线时直接选了面”“有的面无法选择”，并明确 **选线应由两条线确定一个截面**。本报告记录当前行为与合同差距，不记为交互验收通过。

左视图已作为独立增量交付（`95753664`）；本次诊断不改变生产、课堂同步、草稿版本或切割几何模型。

## 1. 首要原因：缺少两条线的选择过程

当前 `cubeCutFromEdge` 从鼠标所在方块的表面位置猜最近的 X/Y/Z 层界，当场返回完整 `CubeCutSelection`，包括 `axis`、`after`、`ids` 和唯一一段 `edge`。工作台第一次点击就执行 `setLockedCut(selection)`；没有保存第一条线、等待第二条线、检验两线关系的状态。

因此，当前实现不是两线定面失败，而是尚未实现两线定面。专题文档此前将两线方式记作可选后续项，与本次明确的产品要求不一致，已同步纠正。

入口：`src/features/tools/spatial-lab/cube-structures-cut-interaction.ts:4`、`:35`；`CubeStructuresWorkbench.tsx:131`、`:147`。

以当前业务函数和真实 Three `InstancedMesh`／`Raycaster` 做只读诊断；单位块大小复用实际 renderer 常量。没有使用浏览器自动化或 GPU 截图。

## 3. “选线却像选面”的视觉来源

`CubeStructuresScene.tsx:38` 对任何 `cut` 都立即绘制整个截面：半透明填充、矩形轮廓，并关闭深度测试。即使还在第一条线的悬浮阶段也一样。随后才额外绘制一段宽 6 px 的命中线。

线模式中的 `cut.edge` 存在，代码不会进入普通面高亮分支；看到的大色面实际是截面预览，不是程序自动切换了“选面”模式。由于两线选择步骤缺失，预览阶段也提前了。

预览面、轮廓和高亮线均设置 `raycast={() => null}`。因此，预览透明面抢走点击不是这条代码路径的解释；修复重点应放在候选与选择过程，而非调预览透明度。

## 4. 其他已确认的实现约束

- **范围隐藏变化**：`CubeStructuresWorkbench.tsx:83` 使用 `selectedIds.length ? selectedIds : scopeIds`；`:161` 的切换工具只清理悬浮／锁定，不清理选择；`:322` 的切割参数只展示 `scopeLabel`。这三处组合，使界面写“整体”但实际只计算一块成为可能。
- **选面不等于按所选面直接切**：`cubeCutFromFace` 只用面的法向决定轴，再选择靠内的最近层界。完整面高亮、选择法向、最终截面是三个不同概念，目前没有充分区分。
- **手势仍与观察竞争**：切割继续传入 `navigationMode="orbit"`，共享相机允许左键／单指旋转；点击处理会过滤移动超过 5 px 的操作。代码能确认这条竞争路径，本次没有模拟完整浏览器事件链，不能把它记成已复现的用户现场主因。
- **现有几何合同只表示 XYZ 层间截面**：切割操作保存 `axis + after`，保持单位块完整。两条不同共面线可能确定斜截面，现有模型不能表达这种情况。两线选择可先映射到现有合法层间截面；任意斜切／切碎单位块需要另外明确产品合同，不在此次诊断中扩展。

## 5. 修订顺序建议（尚未实施）

1. 先补正确的选择过程：空态 → 第一条线 → 第二条线候选 → 两线确定的截面 → 确认切割。第一条线只高亮线并提示选第二条；第二条无效时保留第一条。
2. 验证的是两条几何直线：不同的相交共面线或不同的平行线能确定唯一平面；同一条直线上的两段不算两条线，异面线也不能定面。还应单独验证该平面是否能在当前目标范围内形成有效切割。
3. 将“能选到线／面”和“能执行切割”分开反馈；明确显示实际目标范围和数量，单块残留选择、单层方向、无效第二条线都有具体提示与调整入口。
4. 线候选使用当前相机下的屏幕距离与可见性，并以稳定标识保持第一条线；悬浮与点击使用同一候选。完整面的命中不再靠大面积中心裁剪来防止误切轴。
5. 两条线成立后再展示完整截面；继续保留现有确认／取消、一次语义提交、碰撞拒绝、撤销／录制以及逻辑几何不变的边界。

后续最窄回归应覆盖：两线完成前不出现已锁定截面；重复／共线／异面选择；相交与平行两线；前后面／左右面组合；旧单选与当前组；薄片方向；面边缘命中；缩放与斜视；悬浮到点击的一致性。实际视觉、鼠标和触控手感仍由产品负责人在开发页验收。
