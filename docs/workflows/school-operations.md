# 学校日常工作

## 学生五个主标签

主标签从真实业务事实推导，互斥；正式课程关系优先于测评，再优先于首联。采用当前界面名称：

| 标签 | 精确定义 |
| --- | --- |
| 待首联 | 尚无有效首联，也无更后续的正式事实；包括尚未联系、未接通、待分配、号码无效 |
| 待测评 | 已有效首联，尚无完成的专业测评结果；预约、协调、已约待测、未到重约都留在本阶段 |
| 待报名 | 已完成专业测评，尚无正式报名关系；考虑、有意报名、待回复、缴费待核实均不代替报名 |
| 待续保 | 至少一项有效报名或在班关系仍在继续；包括等班、在读、续保考虑中、本轮不续但本期仍在读 |
| 已停课 | 曾有正式报名，当前全部有效课程关系均已结束；包括全部退课或课程全部结束 |

单科退课但其他课程仍有效，继续归待续保；不续保意向和退款备注不代替实际课程结束。已经确认的来源关系若缺结构化结束事实，保留服务状态，待补齐真实关系再分类。预约、未到、取消、空测评和报名意向不构成完成事实；未到后重约创建新尝试并保留原记录。

五个名单是工作分类。联系、测评、报名、资料完整度和分班继续分别记事实，不要求按界面顺序逐项完成。历史缺项保留来源、缺失含义及补充入口，修正同一对象后各入口沿用结果。

业务标签用于筛选，名单沿用来源大表的组织方式：获客按月份、小组及确认／跟进人员，到访与待报名按月份、学服老师，已停课沿授课老师、班序。线索、沟通和测评共用月份与分组栏，按原表位置接续；同一来源表中混合记录的业务不会因拆成标签而改换分组逻辑。明确的单一年级同时提供给列表、邀约匹配等入口；来源文字保持可追溯，年级范围或含糊说明继续待确认。

## 首联、沟通与行内登记

同一个人从首联、学生、测评或邀约打开，读取同一身份和业务记录；入口只决定初始展开及队列。点击行就地登记，点击姓名打开学生 360。首联沿用 [设计基线](../design.md#首联保护基线)：1–4 选结果，Ctrl/Cmd＋Enter 显式保存，切换保留草稿。

一次沟通填写情况、意向和下一次安排，保存为一次沟通及其关联事项。业务模块分别接收事实，未修改模块不阻挡速记；已有事项加载后更新，重复提交以请求 ID 保持幂等。有效首联保存同事务创建或关联最小学生档案，沿原权限且不创建家庭／账号。

首次确认和后续跟进使用同一种联系记录，按各次实际结果保留。只有未接通、挂断、号码无效等尝试时继续待首联；已经有效沟通且尚未测评时归待测评，后来的未接通不会抹掉早先的有效沟通。来源表的月份、经手人和“暂无结果”不代替有效联系；“未加V”不等于“加V”。列表展示最近一次内容、结果和记录数，原字段名称及完整原文放在展开记录中；来源备注合写多次联系时保留原文，记录条数不冒充精确通话次数。

学生阶段决定展开后的主要操作：待首联选择实际联系结果，所有待测评学生直接承接测评或活动邀约，首联四个结果选项只在待首联出现。意向标签帮助判断后续联系的方式；明确“不需要”“暂无需求”等课程需求回应可记为低意向，并保留判断依据。展开区沿用紧凑密度，姓名、学生全貌和同一操作入口集中在已有位置。

小标签按主阶段呈现：微信、意向是待首联、待测评、待报名共用的沟通信息，持续保留位置。待首联同时关注已有的诺访／到访，待测评关注诺访／到访及当前邀约进展，待报名关注测评结果和报名进展；续保与停课显示对应的课程状态。当前阶段关注项尚无明确记录时，保留灰色虚线图标提示待确认、待了解或资料待补齐；明确的未加微信、未诺访、低意向沿用各自状态。点击标签查看记录依据或需要确认的内容。协调时间、待老师／家长确认、等待活动、已约待测、未到重约、考虑中、缴费待核实等中间状态沿用已保存记录。

历史来源按同一原始行的最新版本提取当前标签，完整旧版本继续保留。实际日期优先于字段位置；同一来源未记日期时只使用明确的获客、首次确认、后续跟进顺序，跨来源无法排序的矛盾保留核对。人工保存的状态优先于来源提取。仅写“有意向”显示未分级，不自动判成 A；待缴费与提到已报名仍需正式依据。沟通进展、延后联系、费用、接送、时间与家庭决策等要点集中在可展开的标签入口，逐条保留原文和日期；纯确认月份、经手人不补造成功联系或预约。

正式报名由具备权限的人核实缴费与依据后办理；意向保存到课程机会，分班继续在分班入口。保存失败保留草稿与未提交字段；成功保持本轮名单位置并标识已处理，“保存并下一位”在主提交成功后前进。修订旧记录保留作者、发生时间与痕迹，新联系才新增次数。

跟进共用行、表头字段菜单与详情加载边界。搜索、筛选、排序、计数依据权限范围内完整集合执行，再返回一页；URL 保留查询。整批分配检查每行权限与负责人冲突，结果不明时保留整批上下文。

## 班级、教材与课表

日历集中查看课次、测评可约时段、内部日程、任务与备课邀请，支持日、周、月、年视图。点击空白时间格出现半小时预览块和旁边的快速填写卡片；主题、时间、人员、地点与说明可直接填写，“更多选项”携带同一份草稿进入完整设置。时间格不常驻加号，日程边缘不显示拖拽条，悬停上下边缘直接按半小时拖动。年度战略规划按每年 7 月至次年 6 月展开；点击日期纵线创建里程碑，保存的节点显示红旗。新建日程和可约时段可按日、周、月设置重复；周期日程显示关联标识，详情可跳转到前后安排，编辑只更新当前一次。可约排班与课表共用时间轴，教师和成员按实际身份筛选。

日历上方直接提供“日历设置”和“设置可排课时段”。每周可排课范围与学生在校上课时间可分别设置或同时使用：在允许范围中扣除在校时间，以及当前成员、校区和教室范围内已知的课次、日程与测评占用，标记完整半小时的可排课空档；隐藏日历分类不会释放占用。只配置在校时间时按每天 08:00–21:00 计算，两项都未配置时保持白底。已有全校／校区休假、停课和调休继续生效。此背景帮助排课，家长预约仍以明确发布的可约时段为准；已排课次和已确认预约继续从原记录处理。

家长可见范围来自老师或教务明确发布、尚未被占用的可约时段。内部会议和备课邀请只向创建者与参与人显示详情，参与人可接受或拒绝；任务按负责人分别记录完成。会议、备课、课程与测评预约在保存时核对教师占用，取消安排释放对应时间。正式课次继续从班级排课产生。

课程、班型、教材、难度分别表示业务含义。班型规则提供新建起点，逐班选择承接特殊情况，续班继承明确设置；批量变更先展示逐班结果。教材版本与正式资源保持来源，调整时保留相关教案、批注和冻结内容。

班级教材从班级设置进入，班型默认规则从课程维护。本节及后续课次顺延从当前课次选择范围，预览后保存；已完成、冻结及范围外课次按合同保留。日常维护由相关岗位在产品里完成，特殊脚本操作按 [数据操作](../ops/data-operations.md) 执行。

整班、学期课次和筛选批次分别作为工作整体，矩阵对照、展开处理、返回时保持排列与位置。大集合按筛选、分组和分页划定当前范围，不把全量数据塞进一屏。手机保持同一编辑器与草稿，纵向排列字段。

## 总览与列表读取方向

统计用于回答具体人员、对象、过程与下一步处理。采用固定链路：**写入时整理窄字段 → 数据库按当前权限关联、选版本、去重、聚合 → 应用接收展示结果 → 展开后读取一页明细**。

- 确定性的单行字段随原业务事务更新，保留原始事实与来源。首版使用现有 PostgreSQL／Supabase 表与 RPC；计数、趋势、人员汇总交给集合 SQL。总览与明细共用事实、权限及去重规则。
- 周期统计、当前学期容量、当前待办分别限定范围；先确定可见来源与对象，再选最新版本、补齐关联闭包，最后按业务日期聚合或分页。不能先裁日期再让旧版本重新入账。
- 字段缺失、显式 null、有效月份分别表示不同事实；实际时间、业务日期和仅月份分别保留，统一机构时区。无权限、读取失败、来源不完整、未知和真实零值分别返回。
- 正式身份由正式关系决定，来源署名仅用于显示和归组；同名不自动合并，显示人员选择不改变机构范围。容量区分学生去重人数与席位，未知容量为 null。
- 原文与来源证据在展开时读取；应用层不为算一个总数拉取全部历史 JSON。页面目标按完整页面首次可操作时间判断，局部 RPC 变快不代表整页已达标。
- 性能改写保持原指标口径。发现旧业务错误单独列为修正；执行计划证明需要后再增加物化视图或增量汇总，避免双写另一套事实表。

具体上线范围与余项见 [当前状态](../current.md)，字段映射和历次实现保存在归档。业务界面显示工作人员需要的对象、结果和动作，迁移编号、发布与内部审计留在操作资料。
