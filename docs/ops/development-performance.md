## 再次变慢时

先区分请求日志中的框架准备与业务处理；`next.js` 不是纯编译耗时。读取 `.next/dev/trace` 的当前进程事件，判断是 `compile-path` / `ensure-page` 等准备阶段，还是页面业务。临时证据放 `.tmp/`，输出只保留路径和耗时，避免记录 Cookie、凭据或业务数据。

样式准备慢时，可以在一次诊断进程中设置 `DEBUG=tailwindcss` 查看 PostCSS 各阶段用时，核对扫描来源是否包含非网页目录。不要通过反复删除整个 `.next` 处理一般变慢；这会丢失下一次启动可复用的结果。

需要对照缓存行为时，在该开发进程的环境中临时设置 `MATHIN_DEV_CACHE=0` 再启动。定位完成后移除此环境变量，恢复缓存；不需要改源码或依赖版本。

JavaScript 堆预算、Turbopack 预算和 React 开发调试保护仍保留。缓存用于复用编译工作，不是内存预算的替代品；持续内存增长按[内存诊断记录](../../archive/2026-10-04/docs/runbooks/local-development-memory.md)定位。该历史记录中“关闭文件系统缓存”的运行状态已由本次修复更新。
