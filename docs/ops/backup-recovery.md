# 需要时进行备份与恢复

备份和演练按实际需要安排：破坏性数据操作、不可逆迁移、破坏性重建，或确认已经长时间没有有效系统备份。普通代码、界面和可修订业务增量不把备份、回滚演练或整套冒烟作为前置步骤。

## 先确认已有恢复来源

读取最近备份的时间、对象、完整性摘要与存放位置；确认覆盖本次可能受影响的数据和文件。可用的现有备份可以复用。对于可逆的局部更正，明确反向修改或该批对象的原始记录即可判断是否还需要系统备份。

## 备份

仓库保留 `scripts/infra/p4e-backup.sh`。脚本读取 `BACKUP_ROOT`、`STORAGE_DIR`、`DB_CONTAINER`、`DB_NAME`、`DB_USER` 等环境变量；生成数据库 dump、Storage 包、数量清单和 SHA256 摘要。备份目录含业务私有数据，保持在受控位置。

使用前确认实际主机、存储挂载和容量。脚本含按 `RETENTION_DAYS` 清理旧备份的逻辑，因此运行前核对保留策略及对应授权；既有服务器定时任务按单独运维任务管理。

## 恢复与演练

恢复先选择隔离目标，识别数据库版本、Storage 路径和备份校验值，再按本次受影响对象验证读写与关联。只有恢复步骤不确定、设施变更或当前高风险操作确有需要时进行演练。成功恢复的历史结果注明版本与范围，可作为后续判断依据。

网站程序回切使用发布脚本的 previous release；数据库和文件恢复分别处理。恢复到生产与删除隔离副本都按实际目标、对象和授权范围执行。
