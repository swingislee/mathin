# 规划与文档治理规则

> 读取条件：任务修改规划、阶段、Gate、证据状态，或需要判断当前是否应施工。跨域规划任务全文读取 active 真相源；普通实现只读状态头与相关章节。

## 真相源与施工范围

- `../plan/04-roadmap.md` 顶部“当前施工阶段”是唯一施工入口。当前主线为 R1-Live 时，只把当前 Gate blocker 或产品负责人明确选入的开发预演作为施工项。
- `../plan/00-overview.md`、`../plan/04-roadmap.md`、`../plan/25-production-1.0-product-completeness.md` 是持续维护的 active 真相源。其他文档的 `complete` 表示历史阶段关闭；`partial` 只按状态头与 doc 25 重新收录的剩余项施工。
- 规范与意图冲突的优先级：工程硬约束 → doc 00 产品宪章 → doc 04 阶段顺序 → doc 25 发布门/缺口 → 相关专题文档 → 历史正文。实现状态最终以代码、迁移、自动验证和运行证据核对。
- 文档与代码冲突时先核对 00/04/25；规划确实过期时先更新 active 文档，再做实现，禁止按旧计划大范围返工。
- 路由存在只证明骨架；测试通过只证明覆盖的合同；开发数据不能证明生产状态。状态只使用当前规划允许的口径。

## 读取策略

- 普通实现：读取 doc 00 的状态头、§5 和相关产品章节；doc 04 的状态头及对应当前 work item；当前任务专题文档的状态头与相关章节。不要全文加载无关 active 文档。
- R1-Live/Production 1.0 的生产、Gate、成熟度或数据保护任务：再读取 doc 25 的相关业务合同、量化门、风险和证据章节。
- 阶段关闭、跨域架构重排或 active 真相源冲突审计：全文读取 00/04/25 与直接相关专题文档，并核对代码、迁移和自动化证据。

## 写作与收口

- 先写对象、动作、原因和结果；数量、时间、路由、表/RPC、角色、状态变化和验收命令优先于形容词。
- 同一结论只保留一处，其他文档链接到权威位置或补充新的证据、限制和案例。
- 结论注明证据范围；没有历史误解需要纠正时，不使用空泛对照句。
- 只有阶段真正关闭时才同步专题状态头、doc 04、doc 25 和证据索引，并运行 `pnpm plan:audit`。
- Agent 可以执行获授权的实现与验证，但不能代替产品 owner、审批人、真实教师、恢复复核人或生产高风险动作的人工确认。
