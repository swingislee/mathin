# 规划与状态

[产品方向](../product-direction.md) 用于构思和理解反馈，[当前状态](../current.md) 维护交付事实。本次用户任务决定施工范围。

规划写清正在解决的工作、可操作的第一版、所依赖的已有内容和还不明确的部分。探索中允许走弯路：方向不清楚时，并排提供对比明显的几个可操作版本；有价值的旧方案保留成可切换选项，方便用户比较后决定。先完成当前可用增量，再根据实际使用反馈选择下一步。

用户要求“改回上一版”时，先定位所指方案的提交，再按该提交精确恢复相关实现；其他任务与无关改动保留。任务卡记下版本与提交，帮助后续准确比较和恢复。

同一事实只在一个适合的位置维护。普通改动更新相关任务和使用说明；影响现有产品方向或主要交付事实时再更新对应入口。实现、部署、人工确认分别注明范围和日期。

历史编号阶段、验收 Gate 与旧证据集中在 [归档](../../archive/README.md)。它们支持追溯原决策，当前任务不依赖重新关闭全部历史门。整理文档不改变尚未成立的验收事实。

写作直接说明应做什么、为什么有用和怎样继续。经验以具体现场、判断和适用范围表达，避免把局部案例变成覆盖所有页面的固定模板。
