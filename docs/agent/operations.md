# 操作规则

## 开发与验证

普通增量：明确当前变更 → 实现 → 提交可操作版本 → 由产品负责人使用反馈继续调整。普通 UI、文案和业务逻辑不默认测试，也不附加全量审核、备份、恢复演练或冒烟。

以下情况按需要增加具体动作：

| 情况 | 适用动作 |
| --- | --- |
| 用户明确要求某项验证 | 只完成所要求的对象与范围 |
| 可能造成重大安全或生产问题 | 针对越权、身份串用、数据损失、密钥泄漏、生产中断等实际风险选择检查 |
| 需要可安装或可部署程序 | 运行生成该交付物所需的构建 |
| 破坏性数据操作、不可逆迁移、破坏性重建 | 明确对象与影响、确认可用恢复来源；必要时备份并验证恢复方法 |
| 长时间没有有效系统备份 | 先核对已有备份，再按 [备份恢复](../ops/backup-recovery.md) 补齐 |
| 需要确认服务启动或某条受影响链路 | 读取必要状态或做定向冒烟；范围由实际问题决定 |

生产正式数据的操作授权和目标识别用于保护真实对象；它们不把普通增量变成统一发布门。已有授权在本次任务已说明的范围内有效，已有可信检查结果可以复用。

既有测试全部保留原位及执行依赖，作为行为的可执行记录。`pnpm test -- tests/文件.test.ts` 明确选择所需文件；不带文件只显示用法，不运行整套回归。`pnpm test --help` 附安全用例索引，其他现有用例同样能指定运行。数据库重建与 SQL 手动调用。日常 CI 只做高置信凭据泄漏检查，其他流程按具体任务启动。

## 本地与交付

复用 3130 上的开发服务。需要启动时调用 `pnpm dev`，后台启动隐藏窗口。面向用户的开发链接为 `http://192.168.5.213:3130/…`。浏览器、截图和 Playwright 只在明确验证任务中使用，[共享技能](../../.agents/skills/verify/SKILL.md) 提供方法。

Git 提交只包含当前任务文件。提交前核对实际暂存范围并调用 `node scripts/check-staged-secrets.mjs`，避免把私有资料带入共享仓库；脚本只输出位置和规则名。普通提交不要求全量回归。

已有的测试、发布、人工确认分别按日期和版本记录。交付说明写实际做过的检查，不以测试数量推定视觉、业务或教学效果。

## 脚本与私有资料

连接信息从环境变量或已忽略的本地配置读取。脚本可以共享参数名与执行方法；真实密码、Token、Cookie、账号清单和个人数据不得写入共享脚本、命令示例、URL、日志或 Git。

临时材料放 `.tmp/`，输出只保留任务需要的摘要。数据库连接串传递时避免命令回显；错误报告保留可定位信息并脱敏。扫描实际暂存内容，工作区已改正不能替代暂存区核对。
