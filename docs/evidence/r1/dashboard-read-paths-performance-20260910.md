# 首页大屏第二轮提速 · 2026-09-10

状态：**开发端已交付，待人工交互验收；生产尚未发布**。本轮在[第一轮应用优化](dashboard-loading-performance-20260910.md)之后，继续减少数据库权限计算和无用读取。当前阶段与 Gate 保持原状态。

## 改动与范围

- 首页统计已不使用 `course_enrollment_assignments`，移除该表读取以及未使用的聚合入参。原来的报名发生日期、来源去重和统计口径继续沿用；入班关联读取失败也不再影响首页统计。
- 迁移 `20260910003000_dashboard_read_paths` 增加 `leads(student_id,id)` 部分索引，把 SELECT 策略中只与当前账号有关的判断提升为单次查询求值。
- 线索池的直接可见分支先求值，其余情况回到原策略；报名读取展开已知的学生范围表达式，按学生判断的归属、授课、学服、参与和分组辅助函数继续沿用。空学生的结果单独按原函数计算。来源确认策略沿用原来源条件。
- 迁移核对已知函数和策略定义，遇到不认识的版本即停止。后续修改学生查看范围时，应同步维护报名 SELECT 策略中的对应表达式。

本轮修改四条 SELECT 策略，不修改权限辅助函数、函数 owner/ACL、写策略或业务记录；不缓存身份或业务统计，不增加数据过期窗口。

## 同数据计时

目标已核对为本机 Windows 开发服务及隔离 Supabase。复用固定开发管理员和教师账号，统计截止时间固定为 `2026-09-10T12:00:00Z`，选择 2026 年 9 月。优化前基线已包含第一轮提速代码。

| 场景 | 第一轮之后，本轮之前 | 第二轮之后 | 数据库请求数 |
| --- | --- | --- | --- |
| 管理员完整统计读取 | 2,563 ms | 966 ms | 45 → 40 |
| 教师完整统计读取 | 3,129 ms | 1,084 ms | 32 → 31 |
| 管理员完整首页 HTTP，预热后 | 第一轮记录 2,877 ms | 1,408 ms | — |
| 教师完整首页 HTTP，预热后 | 第一轮记录 3,208 ms | 1,556 ms | — |

两个身份的完整统计返回值逐字段深度比较一致，包括总量、趋势、人员归属、容量和不可用来源标记；教师原有受限来源状态继续保留。HTTP 均返回 200 且包含大屏正文。计时是本机服务端处理与完整响应接收，不代表浏览器绘制或生产环境保证。

数据库独立测量中，教师报名读取由约 1,997 ms 降到 305 ms，管理员沟通读取由约 739 ms 降到 32 ms。数据量及可见行数保持一致，改善来自减少重复计算。

开发模式仍有额外编译开销：本轮教师第一次 HTTP 请求为 16,997 ms，开发日志将其中约 15.4 秒记在 Next.js 层，业务代码约 1.5 秒；随后请求为 1,556 ms。该次编译等待单独保留，没有计入预热指标。生产需在实际发布后测量。

## 权限与回滚检查

`scripts/dashboard-read-paths.mjs` 通过共享本机目标核对后，执行了以下检查：

- 七个固定开发身份及匿名身份：比较六类读取的完整可见行集合，同时比较所有现有学生与空学生上的报名策略结果。
- 管理员、教师在停用和强制改密状态下：新旧线索与报名策略结果一致，验证状态变化后重新求值。
- 复用学校协作断言，覆盖参与人、同组只读、无关主体、移出分组、直接写入限制及停用身份。
- 当前协作策略与协作前策略分别在事务中演练。业务数据摘要、函数定义/owner/ACL、写策略、其他策略及关系权限保持一致；回滚后完整策略、函数和索引目录恢复，未留下业务事实或测试身份。
- 两轮检查通过后，在同一已核对开发目标应用本条迁移并登记规范化 checksum；应用前复核检查版本、迁移 head、业务数据和目录没有漂移，应用后业务数据摘要一致。
