# Dashboard 其他页面加载逻辑复查（2026-09-20）

状态：**开发数据库已应用，应用读取已调整；生产未部署，页面体验待验收**。本轮承接大屏受限账号读取修复，继续检查其他页面；不关闭 R1-Live Gate。

## 覆盖与判断方法

- 重跑 `scripts/dashboard-query-audit.mjs`：75 个 Dashboard 入口及 11 个 API 补集，保守可达 990 个调用点，其中表读取 381、RPC 540。包含共享布局、按需详情及写命令，**调用点数不是首屏请求数**。逐入口路径沿用 [9 月 19 日覆盖清单](dashboard-query-routes-20260919.md)，本轮当前清单保存在私有审计文件中。
- 对照 128 个实际表／视图的策略，使用固定开发管理员及受限员工抽查首千条读取计划；单条 2 秒上限用于定位，不把无条件探针当作页面真实参数。课件引用／轨道表的全表探针超时，不代表按页面 ID 查询的课件首屏超时。
- 复读总览、线索、学生名录／详情、沟通、测评、活动、分班、班级／课次、续班、课程／课件、财务以及共享鉴权的数据依赖。重点区分独立查询、必须等待的关联键、按需详情和授权检查。

## 本轮改动

| 范围 | 发现 | 调整 |
| --- | --- | --- |
| 学生表及引用学生的页面 | 每行经 `can_view_school_student` 重复执行身份及岗位判断，零可见行也需扫描整表 | 在学生 SELECT 中按单次查询求值；学生归属、授课、学服、参与及分组函数保持原实现 |
| 课程意向／续班及历史视图 | 不具备任何必要权限的账号逐条执行范围判断 | 按原函数的管理员、报名管理与跟进分支前置判断；部分范围继续执行原函数 |
| 班级、课次、活动、报名与测评结果 | SELECT 中的账号级 `is_staff`、`is_admin`、`staff_has_perm` 逐行调用 | 只把无行参数的判断放入标量子查询；原对象范围和策略组合保持 |
| 分班与续班页面 | 名单、补充信息结束后才开始读独立历史资料和时区 | 独立读取同时开始；课次继续等待名单中的班级 ID，补充信息继续等待对应工作区 |
| 分班数据 | 教师、续班事实、健康信息、转课记录互相串行等待 | 取得工作区后并行读取；教师无管理权限的分支沿用原来的较小数据范围 |
| 续班补充数据 | 策略、健康、登记、学生、班级成员按阶段串行；大数组 `.in` 无结果分页 | 独立读取并行；关联 ID 每批 80 个、每组最多四批并发、结果每页 1000 行；专业信号合并后恢复全局时间倒序 |
| 测评来源资料 | 来源资料逐批等待，且等待学生负责人查询结束才开始 | 两者并行；来源 RPC 共用每批 80 个、四批并发的助手，来源负责人选择规则和失败行为保持 |

数据库候选 `20260920150000_dashboard_related_read_paths` **只改 11 条 SELECT 表达式**。权限函数、写策略、角色、ACL 和 RLS 开关未变。迁移先核对三个相关函数体及全部目标策略，遇到未知规则即停止。本轮曾试验修改协作查询函数，最终采用保留函数原实现的较小方案；下表仅列最终候选的结果。

`node scripts/dashboard-related-read-paths.mjs --check` 完成：

- 11 个固定身份加匿名，覆盖 14 个直接及关联表／视图，共 168 组可见行数量与有序摘要一致。
- 对同一个既有员工依次撤销岗位权限、撤销协作关系、停用、锁定和要求改密，再对照 70 组读取。全部使用保存点，业务状态完整回滚。
- 身份与状态切换复用 `force_generic_plan` 预备语句，验证查询内预计算随当前身份和状态重新求值。
- 恢复原策略后再对照 168 组读取；事务结束后，业务事实、函数、策略、ACL、RLS 与迁移账本摘要一致。
- 仅在上述检查通过且写前状态完全匹配后，`--apply` 写入本机隔离开发库。复读确认只变动目标 11 条表达式及迁移账本，业务事实保持。

应用定向验证：续班批读、分班入口、续班事实、共享分页、测评负责人、测评完整投影及测评批读共 7 组、38 项通过。覆盖独立读取启动时序、关联键依赖、权限分支、跨 1000 行的完整信号、跨 ID 批次的时间顺序以及后续页失败传播。受影响文件 ESLint 通过。首次全库类型检查遇到并行教具变更的错误；对方代码更新及本轮测评读取修改后，最终完整 TypeScript 检查通过。

另外复用 `assessment-workbench-read-database.test.ts` 完成真实 Supabase 集成检查：固定管理员与教师分别在原延迟、每请求附加 40 毫秒延迟下，对比当前批读助手与旧版分页助手，完整返回值及顺序一致。这个对照同时包含此前共享分页优化，不能把其全部差值归因于本轮来源读取修改；本轮将它用于实际 DTO 与读取范围验证。

## 仍需调整或继续实测的位置

| 页面族 | 结论 |
| --- | --- |
| 线索入库 | `lead-intake-table-data.ts` 先读取范围内全部 ID，再按批补齐所有行的来源、沟通、邀约等详情，最后计算列候选、排序并分页。仍是优先级最高的结构性重构点：将筛选与排序摘要在数据库聚合，当前页再补详情，同时保持全量列候选与批量分配范围。本轮记录该问题，未通过简单提前截断名单改变业务结果。 |
| 学生名录、沟通阶段名单 | 当前已有服务端筛选、分页及批量协作投影；与直接读取 `students` 的 RLS 路径分开评估。本次学生表数字不能替代这些 RPC 的整页成绩。 |
| 班级、课次、续班的部分权限账号 | 多层对象关联授权仍有约数百毫秒开销，后续应按真实页面过滤条件测量；本轮只提升重复账号判断，未声称全部消除。 |
| 测评与公开课 | 测评来源串行已处理；完整工作表仍汇合跨活动事实。公开课目录也有按批读取报名关联资料的逻辑，需结合可见记录量评估分页或摘要读取，保持现有列筛选语义。 |
| 课程、课件、资源、审核 | 现有按讲次／页面／资源 ID 的详情边界继续保留；列表聚合沿用已发布补丁。大表无条件探针不能证明这些页面慢，需采实际过滤参数。 |
| 财务、组织、账号、通知、导入、家庭 | 继续沿用权限门、服务端分页、单对象详情和按需读取；本轮未发现足以支持批量重写的同类证据。 |
