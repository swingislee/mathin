# 数据总览汇总接入与共享候选优化

状态：**开发库与页面已接入，机器检查通过，待人工验收；本轮未发布生产。** 阶段保持 R1-Live-2。

## 发现与变更

用户反馈上一轮生产修复后体感改善，并要求进一步优化。新附件 `mathin.club922实测加载2.har` 只有 155 字节，`entries`、`pages` 均为空，无法用于测量修复后的生产首屏。

本机重新测量发现，页面仍有 33 次内部 REST 调用、8,616,933 字节。已有获客/沟通汇总接口虽然只返回约 8 KB，但原 SQL 约 667–679 ms：多个统计视图各自重复分类身份、检查来源并遍历相同关联。直接接入原接口会延长部分角色的等待。

迁移 `20260922002000_overview_summary_shared_candidates` 在调用者 RLS 下形成窄候选，统一调用一次身份分类及来源权威判断，复用活动、报名、测评与邀约的关联资格。沿用既有批量分类函数、最新版本先于日期筛选、别名关联、月份三态、归属及去重规则。保留函数签名、owner、ACL 和 SECURITY INVOKER；迁移前校验原函数与 business view 条件，最终迁移只更新两个读取函数。

`getStaffOverviewData` 默认使用数据库获客/沟通汇总，与其他必要读取并行，共用已取得的客户端、时区和期间；传入 detail 时继续使用所选指标的明细读取。首页省去获客来源、来源提交、沟通明细三个入口，汇总缺失或无效时显示不可用。逐条算法保留为明确命名的 `getStaffOverviewLegacyData`，用于独立对照，避免页面及性能门槛落在不同默认路径。

汇总还返回去重的历史署名 ID 和当前比较期间可见的获客人员 ID。这样可保留历史人员选择，以及受限角色“获客不可用、其他指标为零”的人员行，同时不返回不可用指标的计数。完整对照曾发现此类行缺失，已补齐并加入定向测试。

## 本机结果

以下为固定开发管理员、同一数据库和固定期间的对照。字节是 **Supabase → 应用服务器的解码数据量**，不是浏览器下载量；SQL、数据读取和 HTML 响应是不同测量层级。

| 测量 | 原路径 | 本轮 |
| --- | ---: | ---: |
| 获客/沟通汇总 SQL，三次 | 667–679 ms | 325–328 ms |
| 总览内部 REST 调用 | 33 | 27 |
| 总览内部 JSON | 8.62 MB | 3.20–3.21 MB，减少约 63% |
| 完整总览读取，四个周/月期间 | 532–603 ms | 421–469 ms |
| 开发完整 HTML，预热中文/英文 | 上一轮 1.09–1.32 s，非本轮同场对照 | 1.079 / 1.016 s |

修改后的首次开发 HTML 请求为 **2.849 s**，响应头约 980 ms；未隔离开发编译等成本。该请求和预热结果均为 HTTP 完整响应，不包含浏览器下载、执行和可操作时间，不能宣称首次 1 秒目标已经达成。没有本轮生产首屏新测量。

四角色、当前/历史周月共 16 组完整 DTO 对照一致，覆盖全部六项指标、趋势、归属、缺日期数量、目录、教师、容量、待办和不可用状态。人员目录按 ID 排序后比较内容，界面本来就会按姓名重排选项。研究角色原有的课堂范围拒绝响应与原路径一致。其返回数据本来较少，本轮耗时基本持平，约 0.27–0.29 s；不把管理员收益外推到所有身份。

- 本机 preflight 核对 Windows `WhiteHouse`、实际 Supabase origin `http://127.0.0.1:35421`、Docker loopback 网络、数据库指纹、3130 Node 与 35421 Docker 监听，未使用 SSH。
- `scripts/overview-summary-shared-candidates.mjs --check`：六角色、周/月完整事实及四期间汇总共 36 组一致，其中非员工八组汇总保持拒绝；prepared statement 管理员→教师→管理员三次一致。
- 事务回滚后函数、视图、策略、迁移账本及八张业务表摘要一致。本机候选修订仅在同一事务中恢复迁移前定义并核对原候选校验和；脚本固定本机 attestation，不能用于生产修订账本。
- 定向 Vitest 四文件共 33 项通过，含真实 PostgREST 16 组完整数据对照、缺失汇总、人员归属与明细合同；TypeScript、定向 ESLint 和迁移类型摘要通过。两条函数签名与本机实际生成类型一致。
- `tests/staff-overview-summary-http.test.ts` 在 `MATHIN_OVERVIEW_SUMMARY_HTTP_TEST=1` 下验证真实默认读取入口；管理员读取须小于 1 s、解码数据小于 3.5 MB，且不请求已移除的三个明细入口。这个门槛是读取层预算，不代替浏览器验收。
- 本轮开发库已应用；生产发布需要数据库函数与应用一并切换，先函数后应用。生产原有应用仍可使用新函数定义；应用回退应先恢复旧应用，再按备份恢复两条函数。实际生产备份、目标 preflight 与发布属于后续已授权发布批次。
