# 数据库优化后本地逐路由 HAR 分析

状态：**用户反馈本地体验改善；23 个路由的 HAR 与同轮开发日志核对完成，作为后续优化基线。** 本次只读分析，没有修改应用、数据库或生产服务。完整页面 1 秒可操作尚未验收，R1-Live-2 与 Gate 状态保持。

## 样本范围与结论

用户提供 `mathin.club921 数据库优化后.har`。实际来源是本仓库局域网开发应用（3130）与本机 Supabase（35421），不是文件名所指的生产站点。采集时间为北京时间 2026-09-21 21:23:19.270 至 21:24:36.688，约 77.42 秒。

- 233 个请求均为 HTTP 200；包含 23 个路由 RSC GET、12 个读取型 Server Action POST、2 个浏览器鉴权 GET、187 个脚本、6 张图片、1 个样式和 2 个预检。23 个路由各有一次响应观察。
- HAR 的 `pages` 为空，没有 document 请求、硬刷新导航计时或交互就绪标记。可以分析本轮站内切换和后续请求，不能据此验收硬刷新或“1 秒可操作”。
- 全部 23 个路由响应都标记 `development`。8 个路由主响应低于 1 秒，其中线索 503 ms、沟通 487 ms、测评 271 ms；这些请求结束后仍可能加载业务数据，见下文。
- 同轮开发服务日志最后一组路由顺序与 HAR 一致，毫秒级请求相差约 1–5 ms；日志以秒显示的请求存在舍入。没有请求关联 ID，因此此处按路径、顺序、耗时交叉核对，不声称已经获得逐条 SQL 追踪。
- 前一份生产 HAR 中线索、沟通、测评分别约 1.43、0.92、0.64 秒。本次本地结果与用户体感改善一致，但环境、构建、网络和缓存不同，不能计算为本轮补丁的严格 A/B 提升比例。

## 需要继续处理的实际路径

### 1. 总览：继续完成完整汇总接入

本次总览主响应 1573 ms，等待响应头仅 106 ms，主要时间在流式响应阶段。RSC 开发调试记录中 `DashboardPage` / `StaffFactOverviewHome` 所在组件链跨度约 795 ms；整个应用处理为 1476 ms，说明统计读取之外仍有后续渲染、调试序列化与发送开销。组件链的包含时间不能作为独立 SQL 时间相加。

[当前页面](../../../src/features/school/home/StaffFactOverviewHome.tsx)仍调用 `getStaffOverviewData`。前轮[沟通/获客聚合内核](overview-aggregate-core-20260921.md)尚未接入页面，本次改善不能归功于“整个新汇总已经生效”。继续按[读取升级设计](../../plan/dashboard-statistics-read-model-upgrade.md)的 C+D 批次完成其余指标、完整 DTO 与按需明细，并移除页面旧全量事实读取。

### 2. 课件：任务队列是明确的服务端热点

课件应用处理约 3.7 秒；RSC 调试记录中 `CoursewareTaskQueue` 跨度 **2809 ms**，从服务器渲染时间轴约 452 ms 持续到 3261 ms。其读取器 [loadCoursewareTaskQueue](../../../src/features/courseware-studio/data.ts)只调用一次 `list_courseware_tasks`，这给出明确的查询追踪入口，但仍需 HTTP/SQL 分段确认具体耗时。

[页面](../../../src/app/[locale]/dashboard/courseware/page.tsx)先等待模板进度及可选预览，之后才渲染异步任务队列；本样本父内容组件先花约 403 ms。后续应让不互相依赖的统计和队列并行，同时检查队列 SQL 的范围与执行计划。[现有 SQL](../../../supabase/migrations/20260720000700_p4h_courseware_task_queue_return_type_fix.sql)在末尾筛选/限制前构造页面数量、草稿和最新修订集合；筛选、权限、排序必须保持完整语义，先减少无关候选，再补齐本页展示字段。

此次没有打开预览的 `lecture` 参数，但浏览器已下载 Three.js core、空间数学和教具代码，三类显式命名脚本解码合计约 **2.71 MB**。[预览组件](../../../src/features/school/curriculum/LectureCoursewarePreview.tsx)静态引用课件工作区和 StagePreview。这是需要核对的打包边界：生产构建确认后，将预览/编辑依赖留到实际打开时加载。HAR 无脚本执行剖析，不能将这些下载大小直接换算成卡顿时间。

### 3. 素材库：区分列表 SQL、关系读取和签名等待

素材库主响应 5768 ms；应用处理约 5.3 秒，`CoursewareAssetLibraryPage` 组件跨度 **5076 ms**。浏览器中五次 Storage 图片读取只有 **76.77–161.93 ms**，在本次导航约 **5754 ms** 后才开始；本包没有重现浏览器对象下载的 2.8 秒等待。

服务端 [loadCoursewareSharedAssets](../../../src/features/courseware-studio/data.ts)目前按顺序执行：

1. `list_cw_shared_assets` 获取 11 条候选，只展示 10 条。
2. 当前页图片的 revision → object 两次关系读取。
3. 批量 `createSignedUrls`，完成后才返回列表。

[先前素材聚合与分页 SQL](../../../supabase/migrations/20260919100000_dashboard_asset_query.sql)仍保留；不能因为页面慢就判断优化被重新写回。HAR 看不到上述服务端内部请求，**既不能把 5 秒全部归为 SQL，也不能排除签名服务的首次等待**。下一次追踪需分别计时这四段；列表文字和操作与缩略图签名解耦时，仍须维持私有资源权限、签名有效期和明确错误状态。

### 4. 学生：已分页，但分页前的集合准备仍需测量

学生主响应 1543 ms，应用处理 1238 ms；`StudentsPage` / `StudentDirectoryPage` 所在组件链跨度 **1192 ms**。默认入口走 [loadStudentDirectory](../../../src/features/school/student-directory-data.ts) → `list_student_directory`，不是回收站 `listStudents` 分支。

[名录 SQL](../../../supabase/migrations/20260919001000_student_directory.sql)在分页前收集报名事实、生成 subjects JSON、计算协作投影和分组，分页后才补完整行。应保留权限、阶段、分组和稳定分页，测量这些前置集合成本，判断哪些宽字段与 JSON 转换可以推迟到本页；不能只看到数据库里有 `LIMIT` 就视为已完成优化。

## 开发框架与资源的边界

- 课程页 9.04 秒主要在进入应用处理前，应用实际约 432 ms；课件审核及组织/校区/员工等设置页也有约 1.4–2.0 秒框架等待。先用相同代码与数据库的生产构建复测，再决定是否优化业务读取，避免围绕开发首访误改权限或数据语义。
- 整个 HAR 的实际传输约 **8.65 MB**、解码响应约 **70.89 MB**；187 次脚本请求占解码 **64.39 MB**，共有 110 个不同脚本 URL。原始 HAR 文件约 86.26 MB，包含响应文本与记录结构。这些均不等于此前服务端内部 8.85 MB 的事实读取。
- 单个脚本请求最长 206.44 ms。开发 RSC 含大量调试元数据，总览响应解码约 1.19 MB、系统健康约 1.47 MB，不能与生产业务 JSON 直接比较。脚本执行、绘制和交互仍需独立浏览器测量。
- 本包没有带预取标记的请求；开发环境与前次生产 HAR 不同，不能据此把此前 155 次预取记为本轮已消除的请求量。
