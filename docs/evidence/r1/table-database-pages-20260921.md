## 改动与边界

测评由 `loadAssessmentWorkbenchPage` 调用一次 `list_assessment_workbench_page`。数据库沿用调用者 RLS，先限定当前／历史范围，计算搜索、列条件、排序、完整筛选候选和页码，再返回当前页。原全量读取器从路由移出，仅用于展开详情和等价性基线。逐题备注、操作人历史与来源完成情况按展开的学生／线索读取，权限从数据库关联重新确认。

历史范围的执行计划曾错误估计权限视图的基数，造成重复嵌套连接；迁移先解析范围键，并在排序中仅传递键和字段值，减少宽 JSON 的重复物化。筛选使用与 JavaScript 相同的 Unicode 空白语义。详情请求绑定记录版本，刷新或离开记录后丢弃旧响应。

沟通首联无额外列条件时，先按实际阶段和可见范围确定页码，再为当前页生成姓名、归属、背景及协作字段。阶段总数仍计算完整授权集合。有搜索或其他列条件时继续执行原有完整候选查询。新增私有函数从经过定义摘要校验的事实函数生成，沿用原授权逻辑；自动对照检查防止后续事实规则只更新其中一条路径。

`leads.ts` 只对已选页面的线索读取关联数据，来源、兴趣、沟通、邀约及提醒按 REST 实际 1000 行上限继续翻页，避免 `.limit(5000)` 静默丢行。这是关联读取完整性修复；当前页的长历史仍需进一步改为数据库聚合摘要。

迁移：

- `20260921001000_assessment_database_pages.sql`：新增测评列表 RPC 与纯字段函数，业务读取使用 `SECURITY INVOKER`。
- `20260921002000_communication_page_before_enrichment.sql`：首联补齐前分页，通用筛选分支保持原逻辑，新增 helper 不对客户端授权。
