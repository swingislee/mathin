# 测评导入学服姓名与学生 360 修复

状态：开发端已交付，待产品负责人验收。2026-09-07，仅本机隔离开发环境。

## 修复内容

- 测评主行显示学服姓名。当前学生或线索负责人优先；账号尚未匹配的来源姓名继续显示并参与筛选。旧活动备注未携带人员信息时，通过既有授权来源读取补齐。
- 学校业务入口和相关 DTO 使用 PostgreSQL UUID 字符串合同，兼容已入库的导入主键，并继续拒绝非十六进制、缺段和注入式畸形输入。鉴权、业务归属与 RLS 继续承担授权判断。
- 后续业务导入生成确定性的 UUIDv8；读取既有快照后复用原主键，保持来源图和关联关系。完整历史投影继续按已有来源跳过重复导入。
- 逐题测评接受原表未提供精确时间的记录，页面显示空值占位。已有时间仍按原格式呈现。

## 验证

- 实际测评读取为 951 行，其中导入 930 行。修复前 88 行有学服显示值，修复后 869 行；新增恢复 781 行，包括 1 行仅在原始来源保留人员字段的旧投影。
- 用户截图对应主体的真实学生 360 Action 从 `VALIDATION` 恢复为成功，返回 3 条时间轴事件；对应测评主行显示来源学服，逐题页面可打开。
- 另抽取 7 个不同主体，覆盖 3 个已建档学生和 4 个线索主体，真实 360 Action 全部成功；匿名请求继续被拒绝。
- 360 入口、学服读取/筛选/中英文呈现、缺失时间的逐题呈现、关联 DTO、导入主键与旧关系复用的定向回归通过。已同步旧布局测试中与日期提示和现行等级口径不符的断言。
- 本次修改及新增测试的定向 TypeScript、ESLint、Git 文本检查通过。全应用类型检查曾遇到并行空间工作台 `CubeDraftPanel` 的两处 `size="icon"` 类型错误；本次验证范围单独限定到受影响模块与其依赖。
