## 已固化的逐生检查边界

正式课件只保存稳定 `page_doc_id + track` 上的“需逐生检查”布尔标记，发布时固化到 release。备课课次默认继承当前 release，允许本课删除默认页或临时加入其他课件页；额外项目通过新增空白课件页实现，不另建脱离页面的自定义项。每次点击自动写入 `session_learning_checks`，`class_sessions.learning_checks_configured_at` 使明确保存的空清单刷新后仍保持为空；所有课次调整不反向修改正式课件。

- 正式课堂全屏学情面板把原三层抬头压缩为 2 层：首行合并当前检查项、完成进度和批量入口，次行保留横向检查项；正文固定为 20 个座位槽，横屏及大屏为 5×4、竖屏为 4×5，行列等分剩余视口。卡片采用座位状态键盘，六个状态保留 44px 触控高度；大屏由完整座位图铺满，人数减少不触发学生卡放大。
- 人数不足 20 人时渲染带座位号的轻量空座；空座是可拖放目标，教师可按真实教室位置保存稀疏座位图。姓名旁手柄支持触摸拖拽以及按实际列数移动的方向键/Home/End；`20260731001200_r1_learning_check_seat_layout.sql` 以显式 position 保存完整在读名单，保留空座并跨课次复用，名单变化时拒绝整笔保存。
- 开发库已应用迁移；回滚事务探针把完整名单写入从 position 1 开始的稀疏布局，确认 0 号空座保留并返回 `SPARSE_SEAT_LAYOUT_RPC_OK`；学生身份调用返回 `SPARSE_SEAT_LAYOUT_UNAUTHORIZED_REJECTED`，旧连续排序 RPC 对 authenticated 已撤权，探针未保留数据。固定教师课堂在 Chrome 90% 缩放下实测：CSS 1024×768 为 5×4，网格 1003×633px；768×1024 为 4×5，网格 747×879px；1600×900 大屏保持 5×4，网格 1579×765px 并铺满正文。当前 1 人班三档均显示 1 个学生座位与 19 个同尺寸空座，状态按钮最低 53×44px，页面 `scrollWidth=clientWidth`、`scrollHeight=clientHeight`，浏览器应用 error 日志为 0。

## 本轮媒体问题结论

学生从中间页加入时，页面文档会先于绑定资源 URL 到达；旧实现又按整套课件顺序串行预载，导致教师端已缓存可播放、学生端长时间显示“资源不可用”。当前页对象现在排在队首并采用 4 路有界并发，其余对象后台预载；绑定未到时显示明确加载态，完成后视频无原生控制条且不接受学生触摸。

## 家庭门户发布与跨子女隔离增量

- `get_my_schedule` 与 `get_my_attendance` 返回稳定 `student_id`；`/dashboard/children` 和家长首页按 ID 过滤，不再以可重复的姓名拼接多子女数据。
- 家庭课评投影只联接 `published_at is not null` 的家庭摘要，删除了对内部 `class_sessions.knowledge_summary` 草稿的回退。
- 保存家庭摘要会清空发布时间；逐生课评 insert/update/delete 由触发器自动撤回当前家庭摘要。教师显式重新发布后家庭端才再次可见。
- `get_my_session_review_states` 只投影家庭可见的课次元数据和 `pending/published/withdrawn`；孩子详情与家长首页显示待审核或已撤回，不再把两者伪装成“暂无课评”，发布正文仍由独立 RPC 控制。
- `get_family_session_brief` 对家长要求 `grades` scope；关系或 scope 撤回后 RPC fail-closed。
- `revoke_my_guardian_relationship` 只删除调用者自己的关系；同一学生上的操作串行化，当前同意记录追加 `withdrawn`，主监护人离开时按绑定时间顺延下一位。
- 家庭页先区分学生本人档案与监护绑定；只有监护绑定显示解除入口，并用 `AlertDialog` 明确即时失权后果。
- `list_my_session_leave_requests` 按家庭关系共享申请，并返回补课待安排、已安排、已完成或已取消状态；家庭页展示目标课次、时间和班级。
- 最新补课安排会加入 `get_my_schedule`，即使目标课次属于另一个班级；安排成功同时完成 `makeup_followup`，并向学生与当前有效监护人写入通知。
- 旧请假通知触发器的 `classroom_id` 歧义会让提交事务失败；新触发器使用限定变量名，并保持提交→员工、决定→全家庭的角色定向。
- `r1_family_portal_assertions.sql` 在开发库事务内创建最小外部课室 fixture，验证草稿→发布→修订正文隔离及三态投影，外部作业正文/提交/家庭摘要/监护同意、列表、权限与邀请全部拒绝，跨家庭请假/关系撤回拒绝，关系撤回即时失权与主监护人唯一性，请假→审批→补课→任务关闭→家庭课表/通知可见，以及所有带 `student_id` 的家庭投影只包含当前家长可访问学生；事务最终 `ROLLBACK`。
- Codex in-app Browser 以固定测试教师的家庭环境验证中文/英文孩子页：财务关闭分别显示“财务未启用”与“Finance is not enabled”；临时成果在 `pending` 时显示“待审核”与“Pending review”，发布后撤回则显示“已撤回”与“Withdrawn”，两种不可见状态均未渲染带唯一标记的点评正文，应用控制台无错误。验收后临时摘要/课评删除计数为 0/0，账号使用环境恢复为“工作台”。
- 开发专用账号夹具显式要求 `R1_DEV_TEST_FIXTURES=1`，并验证 Supabase 域名解析后的全部地址属于私网/回环网段；重复执行返回 `created=false`，没有重复账号或关系。Codex in-app Browser 以 `test-parent` 验证 zh/en 孩子页同时列出两个稳定学生 ID，并切换到第二学生查看独立课表、星数、监护关系与空状态；以 `test-parent-unbound` 验证 zh/en 家长首页和孩子页只显示绑定引导且侧栏不出现孩子入口。两个账号验收后均退出，最终浏览器 error 日志为 0。
