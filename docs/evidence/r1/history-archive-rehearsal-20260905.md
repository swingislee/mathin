# 历史资料导入演练首版

日期：2026-09-05。状态：开发端已交付，待产品负责人进行原文、归属和视觉验收。本轮为独立 SQLite 演练，不修改 Supabase 业务数据，不部署生产，不关闭阶段或 Gate。

## 已实现

- 开发路由 `/zh/dashboard/history-import` 与 `/en/dashboard/history-import`，仅固定开发管理员在 staff 环境使用。
- 姓名、电话和原文关键词搜索，来源表与归属筛选，25/50/100 行分页；完整原文、原值、来源日期、记录 ID 与文件摘要可追溯。
- 明确匹配、待复核、未匹配分开呈现；未匹配记录仍可检索。只汇集明确匹配到同一对象的资料，不自动把候选、共享号码或共用活动解释成同一家庭。
- 原始资料和重复导出文件完整保留，系统创建/修改时间不充当沟通发生时间，横向名单和无缓存公式保留位置及原值。

## 验证

- 飞书解析 7 项、身份匹配 13 项、SQLite 检索 9 项、服务端权限/查询/双语边界 35 项合成 Vitest 检查通过；Excel 原始单元格提取 6 项 Python 检查通过。
- 本次文件及依赖的定向 TypeScript 检查与定向 ESLint 通过。未运行无关全库回归。
- 管理员中英文 HTTP 页面返回 200，并返回预期原文字段；匿名访问跳转登录，普通 staff 访问跳转工作区且未返回受检原文。只读连接使用 `query_only`，合成检索验证文件摘要与修改时间不变。
- 修复了 Node SQLite 的 CommonJS 外部引用与开发打包器不兼容的问题，最终使用 ESM 导入；中文页面热更新期间出现一次上下文错误，复查已恢复 200，未重启开发服务。
- 最终程序重放同一输入，两次均为 8,592 条记录与 2,520 个来源对象；记录、原文、归属和来源对象逐项摘要完全一致，9 个原始文件摘要保持不变。SQLite 完整性与引用检查通过。
