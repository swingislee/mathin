# Base 无损拆分与映射规则 · 2026-09-22

状态：**分析方案，待业务审阅**。本轮分析 9 月 7 日、14 日、20 日三个原始 Base 文件；未连接生产，未修改导入程序、开发或生产业务数据，未执行部署。规则中的业务对象名称表示建议的信息组织方式，不表示已经新增数据库表、状态枚举或产品页面。

## 1. 先修正“有确认月份和确认人员”的解释

按产品负责人本轮说明，**同时填写确认月份和确认人员，应承认已经开展过确认联系**，保留该联系记录及人员归属。结果栏空白不能把它降为“从未联系”。此前把这一条件概括为“统计推断、不能证明沟通”，表达过于笼统。

这里需要分别保存四件事：是否开展联系、原表具体结果、联系带来的微信／诺访等变化、下一步要做什么。它们不能全部挤入一个“未联系／已联系”字段。

| 原表情况 | 建议解释与映射 |
| --- | --- |
| 有确认月份＋确认人员，结果未填 | 有确认联系记录；具体结果标为未填。保留日期、备注和归属，不重新当作新线索首联。 |
| 结果为“未通” | 有联系尝试，接通结果为未通；若仍需办理，下一步为再次联系。 |
| 结果为“暂无结果” | 原样保留这项业务结果。有月份和人员时仍承认已开展确认；它没有说明具体转化结果，也不自动解释为未拨打、未接通或已成功接通。 |
| 结果为“加V／已进群／诺访” | 分别保存建立微信联系、入群、承诺到访；多选同时成立时保留全部信息。不能把这些变化压成一个没有细节的“已沟通”。 |
| 结果为“下期次再联系” | 保留暂缓和再次联系的要求；不是永久流失。 |
| 只有确认人员，没有月份及其他联系依据 | 确认人员仍可作为学服负责人来源；是否开展联系再查看结果、日期和备注，不单凭分配了负责人判断。 |
| 有明确结果但月份或人员缺失 | 保留联系及明确结果，对缺少的归属或时间标记待补；不因资料不齐丢掉业务。 |

9 月 20 日获客表中，2,629 行同时有确认月份和确认人员：

| 确认结果 | 来源行数 |
| --- | ---: |
| 未填 | 1,208 |
| 暂无结果 | 665 |
| 未通 | 322 |
| 其他明确结果 | 427 |
| 含“暂无结果”的其他多选组合 | 6 |
| 含“未通”的混合组合 | 1 |

1,208 行未填结果中，1,132 行有确认日期，1,111 行有确认备注。不能根据结构化结果空白否定其运营信息。其中确认月份为 9 月的 142 行均未填结构化结果。另有 870 行只填人员未填月份、63 行只填月份未填人员；412 行虽缺少这两个字段中的至少一个，但已经填了结果。这些是不同资料完整度，需要分别处理。

此前提到的 1,703 行，是旧实现对具体结果的推导范围，**不是已经证实的 1,703 条虚假沟通，也不是应该回退到未联系的清单**。本轮不据此执行状态反转。

## 3. 一行怎样拆开

建议保留三个层次：**原始来源版本 → 按业务含义拆出的资料 → 供页面和统计使用的当前结果**。页面结果可以重新计算，原始来源和人工核对记录应能一直追溯。

| 拆出的资料 | 获客总表对应字段 | 保存方式 |
| --- | --- | --- |
| 学生及家庭资料 | 学员姓名、性别、年级/25级、就读学校、家长电话 | 原始称呼与规范身份分开；家长联系方式与孩子分开；年级附适用学年。 |
| 获客资料 | 获客区位、获取渠道、获取人员、获取日期、获取月份、获取周次、获客组别、触达内容、获客加V情况 | 保存来源上下文。一个人可有多条获客记录，不能用最后一次覆盖所有旧来源。 |
| 确认联系摘要 | 确认人员、确认组别、确认日期、确认月份、确认周次、确认结果、确认信息备注、意向分类 | 作为有版本的确认资料保存；拆出联系结果、意向、微信、入群及诺访信息。确认人员同时提供学服归属依据。 |
| 后续跟进摘要 | 跟进人、跟进组别、跟进日期、跟进月份、跟进周次、跟进结果、跟进信息 | 与确认摘要分别保存；互不借用日期、人员、结果。可识别独立事件时再关联事件。 |
| 业务进展声明 | 诺访与否、到访与否、报名与否 | 分别保存承诺、出席和报名；带来源项目与时间上下文，连接到访表、报名和班级资料。 |
| 袋鼠项目资料 | 真题拼团沟通、开团与否、团成员手机号、真题领取、当下状态、沟通情况、沟通人员 | 保存项目范围内的沟通、团成员和参与信息；开团不等于开班，专项沟通不冒充首次确认。 |
| 当前微信快照 | 用户当下加V与否 | 与获取时加V、确认时加V分别保留；当前快照不改写过去某次联系的状态。 |
| 来源登记资料 | 登记日期（此列不用填，自动生成） | 用于追溯填表时间，不能当获取日期或联系发生时间。 |

这里覆盖获客表全部 41 列。“获客区位”虽然在原表“学员基础信息”分组中，业务上属于获客上下文；分组是语义依据之一，仍需结合字段本身解释。

**到访表也需要再拆一次。** 它有 46 列，包含学员背景、组织归属、产品、诺访确认、到访、测评与体验、体系课报名、奖学券。尤其注意：

- 到访表的“确认日期／确认月份”位于“诺访确认数据与信息”分组，记录的是诺访确认，不是再做一次招生首联。
- “学员情况／家长情况”是学服确认阶段资料；“学员情况2／家长情况2”是老师到访阶段资料。后者不能因为名称相近覆盖前者。
- “学服老师”为该来源的学服依据；“学科老师”为该次测评或体验服务老师。“其他老师”保留协作署名，不能统一覆盖负责人。
- “参与内容”的测评、体验课、一对多说明会、一对一沟通可以同时成立，拆成多个参与维度并关联同一到访，不重复计算到访人数。
- 思维测评、学习力测评、备考成绩是不同评价；保留原量表、等级和分数，不相互换算或填充。
- 到访表的报名字段明确属于“体系课报名信息”。145 行为已报名，其中 41 行没有班型、14 行没有报名日期。这类资料应保留报名事实及缺项，不能因缺班型退回待测评，也不能凭空补一个班级。

## 4. 身份、角色和班级怎样衔接

| 对象 | 基本规则 |
| --- | --- |
| 来源行 | 用同一 Base 来源身份＋表 ID＋行 ID 标识；文件名只表示版本。改名字、换导出日期不产生一个新人。 |
| 学生身份 | 已人工确认的关联和别称优先保留。同名同号、学校、对应年份的年级可形成关联候选；同名无号、同号不同孩子和相互冲突的资料分开标记。匹配多个候选时不强行选第一个。 |
| 家庭号码 | 电话作为联系渠道和身份辅助证据，不作为学生唯一身份。兄弟姐妹可共用家长电话；团成员手机号另存成员联系。 |
| 同人多行 | 多条来源可关联同一学生，但每行获客、确认、跟进、项目资料都保留；身份合并不等于事件合并。 |
| 当前学服 | 确认人员是获客表的学服负责人来源；到访表使用学服老师。已有明确人工转交按已确认关系处理；后续来源不因导出更晚就覆盖它。 |
| 阶段老师 | 测评使用该次学科老师，授课使用该学期班级老师，续报保留该阶段老师。学服兼任时两个职责引用同一员工。 |
| 历史经办人与组别 | 获取人、确认人、跟进人、项目沟通人及各自组别分别保留，不把他们都作为当前负责人。当前学服分组沿用用户已指定的成员关系。 |
| 班级 | 根据学年学期、校区、对应阶段的年级班型、授课老师、周次时段关联班级。单师班序仅为表内统计辅助标识，不是跨老师、跨学期的班级唯一键。 |
| 在读 | 以明确的学期在读信息、已经确认的班级关系及后续正式变更形成当前值。待报、空行和未确认安排分别保留，不直接等同已在读。 |
| 测试身份与别称 | 继承前几轮已确认的测试身份、主名／别称和班级例外决定；导入不得重置这些决定。按稳定身份匹配，不能依赖界面“第一行”等会变化的位置。正式统计沿用既定测试排除口径。 |

同一人可以在一个项目里已经参加活动，同时在另一个项目里尚未报名。人物身份只建一份，业务状态按产品和周期区分。班级、到访和沟通表不会各自产生一套互不相认的学生身份。

## 5. 摘要、事件、当前值与统计分别处理

**摘要先完整保存。** 确认和跟进栏都保留原文、原始结构、来源版本及其署名。摘要描述一次明确联系时，可以关联一条事件；有清晰分段、日期或其他可区分证据时，可以关联多条事件。只有字段修改、没有独立发生依据时，记录资料修订，不自动增加沟通次数。

同一次实际联系可能同时被获客表备注和到访表确认描述。关联为同一事件需要人员、业务日期、内容与产品共同支持；仅凭同人同日不能把不同联系强行去重。无法判定的保留摘要和待核关联，原资料仍可查询和用于办理。

**每个字段保存自己的时间含义。** 完整日期、月日、月份、业务周期、第几周、相对“第几天”、填表时间和导出时间分别保存。比如“9月”没有具体发生日，“第1周”不是 ISO 周；“缴费第3天”没有活动起点时不能转换日期。年级名称中的“25级”和表名中的学期作为背景依据，不自动给所有无年份日期补上 2026 年。

当前值按字段维度选择，有明确业务时间或人工裁定时采用相应依据；只有导出时间时，只能说“最新维护的来源值”，不能断言它是最近发生的事件。没有时间、存在冲突时保留多个带来源候选，不按随机 ID 或新文件顺序挑选。

**同一份资料产生两类读取结果：**

- 线索页展示当前运营对象及其获客资料；已有沟通、到访或报名的对象仍可查看获客来源，但不能因此再次成为新人。
- 待沟通展示需要继续办理的事项。已开展联系但结果未填显示相应说明，未通显示再次联系，暂缓保留后续联系要求。历史资料缺项不等于今天产生一个待首联任务。产品现有主阶段、表内结果和下一步事项分别计算；本方案不增加一个未经确认的主阶段体系。

统计需明确单位：来源行数、关联后人数、可区分事件数、指定学期的在读人数、正式班级数。Base 兼容报表可以保留原筛选口径，业务统计按已确认的语义另算并解释差异，不能靠复制事件把数字凑齐。

仪表盘名称也不代替筛选条件。例如导出中的“获客私域仪表盘-4月”仍包含按 3 月筛选的图表；“3月确认分析”按获取月份筛来源，再分析确认结果。应保存图表配置和筛选含义，不能把图表标题直接当作行级事实。此次只检查关联指标配置，未声称重算通过全部 30 个仪表盘的所有图表。

## 6. “无损”的具体保证

1. **原始层完整**：三个文件及以后每版导出完整保留，记录内容哈希；保存表和字段定义、分组、选项 ID、原始值、显示文本、空值、元数据、引用及图表配置。原始内容与解释规则版本分开。
2. **每格可追溯**：每个业务值指回来源表、行、字段、版本；一个格子拆出几个含义也保留同一个来源引用。未理解或未采用的值可原样查看。
3. **空值不含糊**：未填写、明确未发生、字段已清空、字段不在本次 schema、来源行未出现分别处理。清空来源产生一个修订版本，是否撤销已确认业务需另判；不采用一律“空值覆盖”或一律“空值忽略”。
4. **多值不丢失**：加V、进群、诺访分别保留；同格冲突选项保留两边并标记，而不是只取第一个。原始昵称、别称、班型和时间文字保留在规范值旁。
5. **反复导入稳定**：同文件重复处理不增加人、获客条目或沟通次数；同来源行的新版本只更新相应资料。更改映射规则可以重算读取结果，不重写原始证据或已确认身份。
6. **人工决定持续生效**：保存决定的对象、范围、依据和时间；重新导入后仍应用已确认别称、测试分类、姓名纠正及班级关系。新证据冲突时形成待核项。
7. **核对以内容为准**：建立字段守恒清单及按版本回读检查，确认原始格子的值和类型都能还原。字段“已映射”只能证明规则有去向，不能证明所有业务解释已正确。

“无损”能保证已经取得的原始信息不再丢失，不能恢复导出前已经被覆盖、且三个文件都没留下的历史。最新文件还有一条学习资料链接指向未包含的外部表；保留引用并标记缺失目标，不能补造目标内容。当前 9 个附件字段没有非空附件值，这也不证明外部文档或曾有的文件已经备份。

| 情况 | 现有标记的使用建议 |
| --- | --- |
| 已开展联系但具体结果未填 | 对结果资料使用 `review: missing`，在已有业务备注说明已开展联系的依据。不要给“暂无结果”强行加一个空值标记。 |
| 无法确定摘要是否代表独立事件 | `ambiguous`；保留摘要版本和现有备注中的待核原因。 |
| 原始多选包含矛盾选项 | `conflicting_options`，完整保留选项。不同来源互相矛盾时使用 `ambiguous` 和原有备注说明来源差异。 |
| 多孩或共享号码 | 明确包含多个孩子时使用 `child_identity`，多孩子年级用 `multiple_grades`，多人安排用 `record_scope`；单纯同名但身份不明用 `ambiguous`。身份关联沿用现有确认或推定状态。 |
| 原值填错字段，或所属项目不明确 | 填错字段使用 `field_mismatch`；项目不明确使用 `ambiguous` 和原有备注。已明确的专项资料直接归入专项，并非错误；`record_scope` 维持“多名学员安排”的现有含义。 |
| 班型或引用无法确定 | `class_label`／`reference`；只保留来源关系，不创建猜测的班级或外部对象。 |
| 日期表达不完整或不明 | 原值和精度先保留；现有状态和备注说明缺项，`time_period` 只用于它现有定义适用的时段歧义，不泛化为所有缺年份。 |

这些是字段级建议，不要求把一整个人标成有问题。JSON 规则中的 `review` 列列出该类资料可能使用的现有标记，不代表应给每个字段批量套用全部标记。
