## 核查范围与方法

- 以最新已提交的工作入口重组基线 `894927a0` 核查：70 个 Dashboard 页面、3 个读取路由、1 个布局；另纳入 11 个 API 入口作为保守补集。
- 从入口追踪普通导入、动态导入、布局、共享认证、Server Action 和查询包装器。共得到 986 个静态可达调用点：378 个表读取、539 个 RPC、32 个表写入、30 个 Storage 调用和 7 个动态构造器。
- RPC 对照生产实际函数定义、权限和执行统计，区分稳定读取、volatile 读取及写命令；动态包装器继续追踪其调用参数。生产没有的开发功能按源码迁移核查。
- 静态可达性是模块级保守集合，包含点击后才调用的操作；**调用点数量不是首屏请求数，也不是每个页面的执行计划测量数**。`head:true` 的计数查询、外层统一分页及按单个学生／课次过滤的查询，不按“没有直接 limit”认定为重查询。
- 可重跑：`node scripts/dashboard-query-audit.mjs .tmp/dashboard-query-audit.json`。入口明细见[覆盖清单](dashboard-query-routes-20260919.md)。私有原始清单保留每个调用点的文件、行号、资源、方法、分页标记和所属路由。
- 生产诊断基线：应用 `2ded3c75` / `20260915-080520`，迁移账本 392。应用进程、活动 release、实际 Supabase origin 已核对；SQL 使用只读事务和限时查询。`pg_stat_statements` 的历史均值仅用于找热点，改进数字取本轮独立读取计划。
