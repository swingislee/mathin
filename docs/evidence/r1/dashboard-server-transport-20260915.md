## 查明的开销与改动

1. 生产 Next 服务端通过公开 Supabase 域名访问同一台主机的网关。生产 Node 复用连接后，健康读取为 **42–54 ms**，同机网关为 **5–14 ms**；同一份 261,573 字节公开 REST 接口说明，经公开域名为 **230–263 ms**，同机入口为 **92–140 ms**。这些是生产只读传输测量，不是业务页面时延。
2. `server-transport.ts` 为 Proxy 与 SSR 数据客户端提供可选同机传输，范围限于原 Supabase origin 的 Auth/REST 请求。已核对 Kong 的 loopback 绑定、REST 与数据库的共同网络、数据库目标及 REST 1000 行上限。SDK 继续使用公开 URL 生成 Cookie、回调和资源链接；请求方法、正文、凭据、取消信号与错误保持原样。
3. 测评页面基线一次完整请求记录了 131 个请求。关联读取原先每 80 个键逐批等待，每页 200 行；本轮保留 80 键 URL 边界，将行页调整为 1000，并以每组最多四批并行读取。输入去重、完整分页、结果顺序和失败处理保留。

本轮保持首联视觉、字段、快捷键、草稿、显式保存及身份入口。未修改 `requireUser`、MFA 或数据库 RLS，也未缓存跨请求的账号或业务结果。
