## 范围与完整性

- 全引用审计发现 2 个包含该值的历史 blob，均属于 `apps/parent-wechat/project.config.json`；提交说明及附注标签中没有该值。
- 使用 git-filter-repo 2.47.0 在独立镜像重写 1,542 个提交中的 26 个；逐提交比较确认作者、时间、提交说明、父提交结构及其他文件内容保持一致。保留空提交和原消息中的版本引用。
- 本机更新 3 条分支、1 个标签、1 条远端跟踪引用与 4 个树检查点。主工作树和总览发布候选的最新文件树保持一致；另一候选仅将 AppID 替换为占位值。既有未跟踪文件及私有配置完整保留。
- GitHub 只有 `codex/deploy-overview-summary-20260922` 受影响；用精确旧 SHA 的 `--force-with-lease` 更新此分支。其他 12 条公开分支及 1 个标签保持原 SHA；仓库没有 fork 或 PR。
- 从 GitHub 读取全部引用，复用本机已验证对象后通过 `--dissociate` 建立独立镜像。镜像无 alternates 依赖，`git fsck --full --no-reflogs` 通过；28,447 个可达对象的精确值扫描为 0 命中。

## 防止再次公开

- 当前文件、暂存文件和历史内容统一检查微信 AppID 字面值，检查范围包含脚本和文档，结果只显示位置及规则。
- 历史扫描扩展到提交说明、附注标签；pre-push 同时读取 Git 提供的实际推送对象，直接推送没有分支指向的旧 SHA 也会拦截。
- 17 项定向合同与受影响 ESLint 通过。覆盖“HEAD 已清理但旧提交仍含值”“只在提交/标签说明中出现”“直接推送旧 SHA”、暂存区残留、私有文件与脱敏输出。提交和推送 hooks 保持启用。
- 其他机器上的旧克隆需迁移自己的改动到清理后的历史，并启用 `.githooks`；合并旧历史会重新引入该值。受控回退 bundle 留在本机已忽略目录，目录权限限定为当前用户及 SYSTEM，不对外发布。
