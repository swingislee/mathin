# 按产品工作选择用例

用例为当前工作提供可执行依据：教学材料的准确操作与保存恢复、整班与连续记录、草稿和显式提交、冻结版本、权限隔离与数据保护。先说明本次要保护的行为，再决定是否需要检查及所选文件。视觉、教学手感和业务效果由产品负责人实际使用确认。

整理时一起检查用例、夹具和运行脚本的用途。只约束旧阶段清单、固定投产数量、历史文档文字或已被替代布局的检查归档；一次性演示造数没有当前用途时连同入口归档。混合文件保留有效行为，移出过期断言。数学边界样例、真实交互输入和权限拒绝场景按所服务的工作保留。

普通增量不默认运行。用户明确要求，或变更涉及重大安全、生产风险时，按范围选择：

- `pnpm test -- tests/followup-nested-navigation.test.ts`：指定行为检查。
- `pnpm e2e -- e2e/具体文件.spec.ts`：按验证任务调用浏览器，并遵守目标识别与固定账号规则。
- `pnpm db:test -- supabase/tests/r1_account_security_assertions.sql`：先识别隔离环境，再运行所选 SQL；具体设置见 [数据操作](../docs/ops/data-operations.md)。

以上入口不带文件只显示用法。[safety-cases.json](safety-cases.json) 是安全检查的索引，不是默认回归套件，也不限制其他有效文件的调用。日常 CI 只检查凭据泄漏；GitHub 的 Requested checks 用于明确选定的文件或隔离重建。
